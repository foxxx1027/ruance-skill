# 07 数据库与数据存储

这一层测的是「数据存下来之后」：表结构与字段分类、数据权限与行级隔离、加密与密钥、备份与还原、脱敏与留存。典型被测物是库表设计与敏感字段清单、备份文件与恢复演练、导出报表、以及落在磁盘或对象存储上的密文与密钥。关注点是「数据有没有被过度收集、明文落盘、越权读取，或者真出事时还原不了」。

## 这一层最常见的四类问题

- 手机号、身份证、密钥明文落库，日志、导出报表和接口响应里也照抄一份。
- 密钥硬编码在配置或代码里，或者和密文放在同一台机器，密文等于没加密。
- 备份从没做过还原演练，真出事才发现备份是空的、少了一份、或者恢复不了。
- 数据库账户权限过大，库文件或备份直接放在 Web 根目录可被下载。

## 这一层的 skill

| skill | 作用 | 什么时候会用到 |
| --- | --- | --- |
| sensitive-data-lifecycle | 判定字段是否敏感，定加密存储、密钥管理、脱敏、数据最小化与留存期限。 | 「这个字段要不要加密」「密钥放哪」 |
| data-protection-and-secrets | 核查数据在传输、存储、展示、留存中的保护，排查密钥硬编码与日志/报错泄露。 | 「日志里能不能带手机号」「前端源码里有密钥」 |
| data-backup-recovery-discipline | 设计或检查备份方案与还原演练，在误删、格式化、分区丢失后决定先做什么。 | 「这个备份真能还原吗」「误删之后先做哪一步」 |

## 跨层可复用

- input-validation-output-encoding（06_接口与协议）— SQL 注入的根因在拼查询，防护规则由它给；本层只看存储侧的加密与权限。
- authorization-and-least-privilege（05_后端业务逻辑与权限）— 数据库账户、行级权限与租户隔离属于最小权限模型的一部分。
- logging-security（13_日志与审计数据）— 日志字段脱敏与审计事件留存，避免日志成为第二份数据库。
- web-minimal-exposure（08_中间件与Web容器）— 库文件/备份能否被直接下载、目录权限是否过宽。
- supply-chain-and-dependency-security（12_构建产物与依赖）— 数据库驱动与组件版本的已知漏洞。
- cloud-and-container-baseline（11_云与容器）— 对象存储桶是否公开、云数据库是否对公网开放。

## 和相邻层的分界

- 与 05 后端业务：07 关心「数据存得对不对、能不能被还原」，05 关心「谁有资格读这条数据、业务规则是否被绕过」。数据权限的策略设计在 05，落库后的加密、备份与脱敏在 07。
- 与 13 日志与审计：13 管的是「过程记录」，07 管的是「业务数据的存储与留存」；日志脱敏这件事两边都要看，规则在 07，落地形态在 13。
- 与 08 中间件：库文件被下载，是「文件放错位置」的容器/站点配置问题，归 08；库里的数据本身怎么加密归 07。
