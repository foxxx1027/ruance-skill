# 备份的故障域隔离与恢复写入纪律

## R — 原文 (Reading)

> “为了分区表备份文件的安全，请将其保存到当前硬盘以外的硬盘或其它介质中。”
>
> “为提高数据恢复成功率，请不要将本软件安装到需要恢复文件的磁盘中。”
>
> “千万不要往要恢复的分区上写入新文件，避免破坏数据！”
>
> — 第11章《磁盘数据的备份与恢复技巧》

---

## I — 方法论骨架 (Interpretation)

1. 备份的本质不是“多一份文件”，而是让副本与原件不会同时失效。
2. 先按“丢失后能否重建”给对象分层：分区表、引导区等元数据决定系统能否找到数据；用户文件决定工作成果；两类都要覆盖。
3. 用故障域检查备份位置，而不是用文件类型检查：同一块硬盘、同一个分区、同一台易失设备、同一个同步账号，都算同一个故障域。
4. 备份任务显示“完成”不等于“能恢复”；只有做过一次异机或异盘还原，才能把“有备份”改写成“可恢复”。
5. 真发生丢失时，第一动作是冻结原盘：不装软件、不新建文件、不下载、不解压、不保存日志，恢复工具与输出都放到别的故障域。
6. 然后按丢失类型选择扫描深度：误删用标准扫描，格式化或目录损坏用深度扫描，分区丢失先做分区扫描，最后才考虑原始数据扫描。
7. 恢复结果必须落到第三块盘或另一分区；原盘在整个过程中保持只读。
8. 若磁盘出现异响、坏道或识别不稳，先做整盘镜像，后续只在镜像上操作。
9. 顺序的核心是“先止损，再找工具”；每多写一次，都会缩小可恢复的数据块范围。

## A1 — 书中的应用 (Past Application)

### 案例 1: DiskGenius 备份分区表，备份默认落在本盘
- **问题**: 分区表损坏会导致系统启动失败、数据“入口”丢失，需要在改动磁盘前先备份这类底层元数据。
- **方法论的使用**: 作者把分区表当作不可重建的元数据单独备份，并检查备份落点。软件把 `.ptf` 文件写到 `C:\Users\Administrator\Documents`，而这与待保护磁盘同属一个故障域，只是一份临时副本。
- **结论**: 备份文件必须转存到当前硬盘以外的硬盘、U 盘、移动硬盘或光盘；否则磁盘故障时原件与备份一起消失。
- **结果**: 分区表备份成功生成，但书中明确提示转存；只有完成转存，才满足故障域隔离。

### 案例 2: FinalData 恢复误删文件，软件与结果都离开原盘
- **问题**: F 盘误删了“美图.rar”，需要在不覆盖原数据的前提下找回。
- **方法论的使用**: 作者把 FinalData 安装到 D 盘而不是待恢复的 F 盘，选择“误删除文件”扫描 F 盘，并把恢复目标指定为 H 盘，让 F 盘保持只读；这同时满足“软件异盘”和“结果异盘”两条纪律。
- **结论**: 恢复软件与导出目录都不能落在待恢复盘上，连新建文件夹、保存日志都算写入。
- **结果**: 恢复摘要显示处理 1 个、成功 1 个、失败 0 个，恢复后的文件在 H 盘可见。

### 案例 3: EasyRecovery 的“目的地警告”强制异盘保存
- **问题**: F 盘的“图片.rar”被彻底删除，需要用删除恢复找回。
- **方法论的使用**: 作者用 EasyRecovery 的“删除恢复”扫描 F 盘，选中文件后软件弹出目的地警告，要求复制到“比恢复处安全的地方”；作者选择 E 盘作为保存路径。
- **结论**: “恢复到异盘”不是可选项，而是恢复工具主动设置的安全边界；回写原盘会覆盖待恢复数据。
- **结果**: 恢复报告显示源分区为 F:\、恢复 1 个文件共 4.81MB 到 E:\、跳过 0 个文件。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 准备重装系统、换硬盘或迁移服务器，问“哪些东西要备份、备份放哪里才算安全”。
2. 刚误删文件、格式化分区或丢失分区表，问“先做什么、用哪个恢复软件、能不能装回原盘”。
3. 已经有一份“备份”（同盘副本、同步盘、RAID、快照），想确认它能不能扛住硬盘损坏、误删或勒索软件。
4. 需要向别人解释“为什么备份任务成功不等于数据可恢复”，并要求做一次恢复演练。
5. 磁盘出现异响或坏道，用户仍想直接跑恢复软件，需要先判断是否应停止通电并做镜像。

### 语言信号 (用户的话里出现这些就应激活)

- “备份到哪个盘”“备份放 C 盘行不行”“重装系统前要备份什么”
- “误删了还能恢复吗”“格式化后怎么找回”“分区表丢了怎么办”
- “恢复软件能装在原来的盘吗”“恢复到原分区可以吗”
- “我有 RAID / 云同步 / 快照，还需要备份吗”
- “backup plan”“restore drill”“recover deleted files”“fault domain”“data loss”“partition table”

### 与相邻 skill 的区分

- 与 `recon-funnel-and-scoping` 的区别: 后者是在未知目标上做侦察与漏洞面收敛；本 skill 处理“数据丢失前后的连续性”，不做目标发现或攻击面枚举。
- 与 `malware-triage-order` 的区别: 后者是已感染主机的处置顺序；本 skill 只负责数据保全与恢复。若勒索或病毒仍在运行，应先按前者断入口、隔离，再冻结原盘做恢复。
- 与 `usb-autorun-hardening` 的区别: 后者封堵可移动介质的自动播放入口；本 skill 关心备份介质选择与恢复写入纪律。二者可在“U 盘既可能传播病毒又承载备份”时组合使用。
- 与 `wireless-security-grading` 的区别: 后者评估无线认证路径的强度；本 skill 不涉及无线接入，只在“路由器配置备份”这一交叉点上相关。

## E — 可执行步骤 (Execution)

1. **列出对象并判定可重建性**
   - 完成标准: 清单至少覆盖分区表/引导区、驱动与系统配置、用户文件、账号与密钥；每项标注“可重建/不可重建”以及重建代价。
   - 判停条件: 若对象是正在写入的数据库或虚拟机磁盘，先停写或做一致性快照，再进入备份，避免拿到损坏副本。

2. **为每类对象选择不同故障域的介质**
   - 完成标准: 每个“不可重建”对象至少有一份副本位于不同物理设备、不同分区或不同失效域；能在介质清单上指出源与副本为何不同域。
   - 判停条件: 若副本仍在同一块盘、同一个同步账号或同一台易失设备上，视为未完成，不得进入验证步骤。

3. **验证备份可实际还原**
   - 完成标准: 至少抽取一个对象，在异机或异盘实际还原并校验（文件可打开、校验和一致、系统可启动），记录演练时间与结果。
   - 判停条件: 若还原失败，回到步骤 2 更换介质或备份方式；不要把“备份任务成功”当作通过。

4. **事故后冻结原盘**
   - 完成标准: 停止对原盘的一切写入（不装软件、不新建/下载/解压、不保存日志），恢复工具安装到其他盘，恢复输出指向第三块盘或另一分区。
   - 判停条件: 若磁盘有异响、坏道或识别不稳，先断电并做整盘镜像，后续只在镜像上操作；无镜像条件时停止自行恢复。

5. **按丢失类型恢复并校验结果**
   - 完成标准: 按“误删→标准扫描、格式化/目录损坏→深度扫描、分区丢失→分区扫描、最后原始数据扫描”的顺序选择方式；结果落到异盘，并逐项核对数量、大小与可打开性，记录失败项。
   - 判停条件: 若首次扫描结果不完整，原盘仍保持只读，可换工具再扫；一旦确认无需再扫，再解除只读。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 磁盘已物理损坏、持续异响、掉盘或无法识别：不要继续通电反复扫描，应停机上专业镜像或开盘；本 skill 只能告诉你“先停”，不能替代硬件级操作。
- 需要司法取证链保全：不要用普通恢复工具写盘，应先做只读镜像与哈希记录；普通恢复追求“取回文件”，取证追求“证据不被改变”。
- 只是磁盘空间不足、清理垃圾或扩容：这不是数据丢失场景，按本 skill 执行只会增加误操作风险。

### 作者在书中警告的失败模式 (warning_signs)

- **备份留在 C 盘或待保护盘**: 备份路径在系统盘、与原盘同一物理设备、只有一份副本、从未做过异机恢复演练——都说明备份与原数据共享同一故障域。
- **恢复软件装在待恢复盘、结果写回原盘**: 安装路径与待恢复分区相同、导出目录选在原盘、恢复前还在该盘新建/下载/解压文件；常见结果是“扫描能看到文件，恢复出来却打不开或内容错乱”。
- **把“新建文件夹”当成无害操作**: 在原盘建目录、保存日志、截屏到原盘，都会分配并写入新数据，可能覆盖待恢复的数据块。
- **把备份完成当成可恢复**: 只看到任务成功日志，却从未验证还原；一旦真出事才发现备份不完整或无法挂载。
- **把 RAID、云同步或快照当成备份**: RAID 主要防单盘故障，误删、勒索加密和同步错误会照样传播；快照与同步需要单独验证能否回滚到可用状态，不能默认等于“异域副本”。

### 作者的盲点 / 时代局限

- 书中案例以 2019 年前后的机械硬盘和 Windows 桌面工具为主；现代 SSD 的 TRIM 会在删除后较快擦除数据块，恢复窗口更短，“停止写入”必须更早执行。
- 只讲单机桌面恢复，未覆盖服务器、虚拟化快照、数据库一致性备份、备份加密与密钥托管；企业环境还需资产台账、备份任务监控与恢复演练制度。
- 重操作、轻验证：书中给出工具步骤，却很少给出“如何确认恢复成功”的校验方法；本 skill 因此把“演练与校验”补成独立步骤。
- 具体软件菜单会随版本失效；本 skill 只保留判据与决策顺序，不把菜单路径当作方法本身。

### 容易混淆的邻近方法论

- **备份 vs 归档 vs 同步 vs 快照 vs RAID**: 它们解决不同的故障域与时间尺度，不能互相替代；“有一份副本”不等于“能恢复到某个时间点”。
- **数据恢复 vs 取证镜像**: 两者都要求停止写入，但前者追求取回可用文件，后者追求证据完整与可复现。
- **`malware-triage-order`**: 勒索软件仍在活跃加密时，先断入口、隔离主机，再做数据恢复；不要在加密过程中反复扫描原盘。
