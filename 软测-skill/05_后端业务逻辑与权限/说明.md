# 05 后端业务逻辑与权限

这一层测的是「服务端的规则有没有被绕过」：谁能做什么、一笔钱能不能被重复花、文件落到哪、账号怎么登录。典型被测物是订单/支付/退款状态机、角色与数据权限矩阵、登录注册与找回流程、上传与下载接口。对象是业务规则本身，而不是协议格式，也不是代码写法——规则对不对，要靠行为验证。

## 这一层最常见的四类问题

- 改一个 ID 就能看到别人的数据，或者前端藏起来的按钮对应接口照样能调。
- 一分钱支付、重复退款、并发超额、优惠券反复用，服务端没有原子校验。
- 上传的文件落到可执行目录，或者下载接口能 `../` 穿越到配置文件。
- 登录能被爆破、错误提示能枚举账号、验证码可以复用，找回流程可被绕过。

## 这一层的 skill

| skill | 作用 | 什么时候会用到 |
| --- | --- | --- |
| business-logic-and-race-security | 画业务流程状态机，列金额/库存/次数/资格/时序不变量，逐条试跳过、重放、并发与边界值。 | 「能不能一分钱支付」「重复退款成不成立」 |
| access-control-and-idor | 建主体—对象—动作—上下文授权矩阵，分水平、垂直、上下文三类做只读验证。 | 「改个 ID 能看到别人数据吗」 |
| authentication-and-passwords | 评审登录、注册、找回、短信验证码与 MFA 的强度，以及口令存储与锁定策略。 | 「登录接口被刷怎么办」「提示会不会泄露账号存在」 |
| authorization-and-least-privilege | 设计或评审权限模型、多租户隔离与数据库/服务账户的最小权限。 | 「这个接口要不要单独加权限」 |
| file-and-upload-safety | 处理路径拼接、下载导出、上传落盘、临时文件、目录遍历与符号链接竞争。 | 「下载接口能不能 ../ 穿越」「上传存哪里才安全」 |
| upload-parser-bypass-audit | 比较存储名与解析名，验证分号、多后缀、AddHandler、fix_pathinfo 等解析绕过。 | 「传个 .php.jpg 会不会被当脚本执行」 |

## 跨层可复用

- api-and-interface-security（06_接口与协议）— 业务规则最终都从接口进来，接口层先查认证、对象级校验与批量赋值。
- input-validation-output-encoding（06_接口与协议）— 参数怎么过滤与转义是它的规则；05 只判断「这里的值该不该被当成数据」。
- object-design-immutability（04_源码与代码实现）— 金额/权限字段如果在类层面就能被改，业务层怎么校验都白搭。
- concurrency-safety（04_源码与代码实现）— 并发超额在代码层是锁，在业务层是不变量，两边要相互印证。
- middleware-misconfig-audit（08_中间件与Web容器）— 上传目录能否执行，很多时候是容器解析配置决定的。
- data-protection-and-secrets（07_数据库与数据存储）— 批量导出接口是否越权、导出内容是否脱敏。
- authentication-and-passwords 之外的会话问题见 auth-session-and-federation-security（06_接口与协议）。

## 和相邻层的分界

- 与 06 接口与协议：06 看协议、认证、对象级校验与输入解析，05 看业务状态机与金额/库存/次数不变量。「接口没鉴权」归 06，「鉴权了但换个状态就能白拿」归 05。
- 与 04 源码：05 不读实现细节，只按行为验证规则是否原子、是否默认拒绝。
- 与 08 中间件：同一个目录穿越，来自 alias/解析配置归 08，来自代码拼路径归 05。
