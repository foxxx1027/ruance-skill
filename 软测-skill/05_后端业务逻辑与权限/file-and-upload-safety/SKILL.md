# 文件与上传安全

## R — 原文

> b） 对来自文件系统的所有信息（包括但不限于文件路径、文件名的内容和长度）进行标准化，然后进行验证。c） 确保文件上传安全：验证文件类型，仅允许上传满足业务需要的相关文件类型。除验证文件类型扩展名外，还需至少检查文件报头中的类型信息……关闭在文件上传目录的运行权限。
>
> — GB/T 38674—2020，7.4 b) c)；另见 7.4 d) e) f) g) h) i) j) k)

## I — 方法论骨架

文件安全的错，大多不是"没过滤特殊字符"，而是把三层不同语义的东西混为一谈：用户给的名字、文件系统解释的路径、进程打开的那个对象。

第一层是路径语义。外部给的路径必须先变成唯一规范形态（解析相对段、绝对路径、符号链接、编码），再判断结果是否仍落在允许的根之下。顺序不能反：先校验后规范化，等于用一个会被下一层重新解释的字符串做安全判断。

第二层是命名与暴露面。不要向用户返回目录或绝对路径，改用预置路径列表的索引值；应用自身文件与资源对用户只读；关闭自动目录列表。路径不仅是访问手段，也是内部结构的测绘入口。

第三层是对象身份。同一个文件可以被多次按名打开，名字不变不代表对象不变。多次操作要持有句柄，让校验与使用针对同一个对象；句柄要及时释放、不得使用过期句柄；调子进程前关闭敏感句柄。

上传是写入与后续访问的复合风险，四道闸缺一不可：上传前鉴别身份；扩展名与文件报头双检，只认扩展名等于没检；被访问前做恶意代码扫描与完整性校验；上传目录去掉运行权限。落盘时重命名并隔离存储，不让原文件名决定最终路径。

临时文件是权限与时间的双重约束：启动时以严格权限建独立临时目录，只对本应用开放；存活时间最小化、用完即删，不能靠退出钩子兜底。

## A1 — 书中的应用

### 案例 1: 路径前缀检查被 `../` 绕过（附录 A.4.4.5，对应 7.4 d)）

- **问题**: 用户提交 path，代码只判断字符串是否以安全目录前缀开头，通过就执行删除。
- **方法论的使用**: 在字符串层它只是一个前缀匹配，进入文件系统层后 `../`、绝对路径、符号链接会被重新解释；校验对象与使用对象不是同一个语义层，闸门等于装在了河的另一边。
- **结论**: 先取规范路径，再与安全根目录比较；更稳妥的是维护合法资源名白名单，用户只能从列表中选择，路径不由输入直接决定。
- **结果（防住什么）**: 不修时提交 `/safe_dir/../important.dat` 可通过前缀检查并删掉受保护文件；规范化后越界路径被拒绝，读写被限制在安全根内。

### 案例 2: 文件流句柄未及时释放（附录 A.4.1.2，对应 7.1 d)、7.4 h)）

- **问题**: 打开文件输入流与缓冲读取器后只在成功路径上读取，异常或提前返回时不关闭，指望虚拟机回收。
- **方法论的使用**: 文件句柄是有限资源，且属于按对象身份操作的一类资源；生命周期模型要求每条退出路径都归还，不能把回收时机交给 GC。
- **结论**: 资源变量先置空，在 finally 中判空逐个关闭，关闭动作自身再单独捕获；或使用自动关闭语法。
- **结果（防住什么）**: 不修则在反复请求下耗尽文件句柄，正常用户无法打开文件，形成拒绝服务；修正后句柄数稳定。

## A2 — 触发场景

### 用户会在什么情境下需要这个 skill?

1. 下载、预览、导出接口接收 filename 或 path 参数，需要判断能不能直接拼进文件 API。
2. 头像、附件、导入包等上传功能，需要决定类型怎么校验、落在哪、能不能被直接访问。
3. 报表或转换任务要生成临时文件，担心权限过宽、残留时间过长或文件名可预测。
4. 上传压缩包后批量解压、按目录批处理，担心条目路径逃出目标目录。
5. 对象存储直传场景，服务端只拿到对象键，需要重新安排校验点与下载路径。

### 语言信号

- "这个文件名能不能直接用 / 要不要过滤 ../"（can I use this filename directly / should I strip dot-dot-slash）
- "上传只允许 jpg/png 怎么校验"（how to validate upload file type）
- "下载接口能不能传路径"（can the download API take a path）
- "临时文件放哪 / 什么时候删"（where to put temp files / when to delete）
- "上传目录能不能执行脚本"（can the upload directory execute scripts）
- path traversal, directory traversal, file upload bypass, webshell, temp file, symlink

### 与相邻 skill 的区分

- 与 `memory-and-resource-safety` 的区别：后者管句柄、流与临时文件何时归还、容量多大；本 skill 管路径与文件类型能不能信、文件该落在哪。
- 与 `trust-boundary-mapping` 的区别：后者回答路径参数在哪一层变成可信、边界画在哪；本 skill 给出这一层具体用什么标准化与校验动作。
- 与 `authorization-and-least-privilege` 的区别：本 skill 判断某条路径是否在允许根内，授权判断某个主体是否有权访问该对象；文件越权往往两者都要过。

## E — 可执行步骤

1. **枚举文件输入面**
   - 动作：列出所有接受路径、文件名、上传内容的入口，标注是否匿名可访问、参数来自请求还是配置。
   - 完成标准：每个入口有是否已鉴别、参数来源、最终落到哪个文件 API 三项信息。
   - 判停条件：若入口只接受枚举 ID 且内部映射到固定文件，标注为低风险并跳到步骤 4。

2. **标准化后再判定**
   - 动作：对每个路径做规范化（相对段、绝对路径、符号链接、编码），再与允许根目录比较；校验与打开必须使用同一个已校验对象。
   - 完成标准：每个入口有标准化函数、根目录比较、是否改用预置索引三项结论；不存在先前缀校验后拼接的写法。
   - 判停条件：若已改为预置索引或固定枚举，直接跳到步骤 4。

3. **上传四闸**
   - 动作：核对上传前身份鉴别、扩展名与文件报头双检、访问前扫描与完整性校验、上传目录禁执行；落盘重命名并隔离存储。
   - 完成标准：四项各有实现位置，或有不适用理由；类型判断不是只看扩展名或客户端 Content-Type。

4. **句柄、临时文件与只读**
   - 动作：多次操作同一文件改持句柄；及时释放、不用过期句柄；启动时以严格权限建独立临时目录、短存快删；应用文件与资源对用户只读；调子进程前关闭敏感句柄。
   - 完成标准：每项有结论；临时目录的权限与清理触发点可指出。

5. **输出面收口**
   - 动作：检查响应、错误页、下载链接是否暴露绝对路径或目录结构；关闭自动目录列表。
   - 完成标准：抽查响应与错误信息中无真实路径；目录列表关闭，或开启时已逐一核查无敏感文件。

## B — 边界

### 不要在以下情况使用此 skill

- 问题主要是对象存储桶策略、IAM 或 CDN 缓存规则：本 skill 只给键不可由用户控制、下载走鉴权代理这两条设计约束，具体策略要按云平台配置方法处理。
- 路径问题的根因是权限模型（谁能访问哪个租户目录）：这属于授权与最小权限，路径校验只能兜底。
- 纯静态资源的前端下载链接，没有服务端文件 API：没有可校验的入口，收益接近零。
- 需要做恶意文件内容检测与沙箱分析：本 skill 只要求扫描与完整性校验，不教检测引擎与规则。
- 目标是文件格式解析器本身的内存破坏（图片、文档、压缩格式漏洞）：转到内存安全与模糊测试类方法论。

### 作者在书中警告的失败模式

- **ce07 上传只校验扩展名**：扩展名与 Content-Type 都由客户端控制，改后缀即可通过；只有读文件魔数与允许类型比对，再配合目录禁执行、访问前扫描，才能阻断上传即执行的利用链。
- **ce19 不标准化就做黑名单**：`....//`、URL 编码、绝对路径、符号链接、短名与 UNC 路径都可等价表达同一个目标；替换一次 `../` 后仍能拼出新的穿越，正确顺序是先规范化再判断前缀，并用同一个对象打开。
- **ce20 忽略文件操作返回值**：delete、mkdirs、设置权限的返回值被丢弃，删除失败仍认为敏感文件已清除，权限设置失败仍认为文件已受保护。

### 作者的盲点 / 时代局限

- 未覆盖对象存储预签名直传、S3 键注入、CDN 缓存投毒与容器挂载卷：服务端拿不到文件流时，落盘后扫描无处落地，必须把校验前移到签发与回调两处。
- 上传目录禁执行在 Serverless 与对象存储中没有对应物，需要换成禁止公开读、固定内容类型与下载走服务端代理。
- 符号链接、硬链接与跨租户共享目录的竞态只提了句柄一句，没有给出链接解析与目录归属的判定方法。

### 容易混淆的邻近方法论

- 输入验证与输出编码：路径也是输入，但编码或过滤字符解决不了语义等价，必须先规范化再比较。
- 授权与最小权限：路径边界回答文件在哪，授权回答谁能碰它，两者不能互相替代。
