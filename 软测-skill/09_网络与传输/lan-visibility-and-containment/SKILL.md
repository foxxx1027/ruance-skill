# 内网可见性与可达性收敛

## R — 原文 (Reading)

> “‘关键主机组’是由管理员指定的IP地址，可以是网关、其他计算机或服务器等。管理员将指定的IP存入‘关键主机组’后，即可令非法用户仅断开与‘关键主机组’的连接而不断开与其他计算机的连接。”（PAGE 180，第9章 9.4 局域网安全的防护）
>
> — 网络安全技术联盟 主编, 第9章 9.4

---

## I — 方法论骨架 (Interpretation)

内网治理不是先拔网线，而是先回答三个问题：谁在网上、谁能到谁、谁被允许接入。
先把可见性做成六层台账：IP、主机名、工作组、MAC、共享、开放端口；单层异常不足以定性，至少两层同时异常才值得追。
台账要和一份“正常基线”比对，新增、消失、变更才有意义；没有基线，扫描结果只是一张名单。
准入层按资产归属分类：白名单/黑名单回答“它是不是内部设备”，IP-MAC 绑定回答“这个地址有没有被冒用”，关键主机组回答“断哪一段能把附带损伤压到最小”。
控制点优先放在咽喉处——网关、AP、核心交换；对违规主机只断它与关键主机组的连接，保留必要的其他通信。
所有变更前先核对既有设施（尤其上游是否已有绑定），变更后留下可执行的回滚路径。
一句话：先看见、再比对、定归属、控咽喉、小半径隔离、可恢复。

## A1 — 书中的应用 (Past Application)

### 案例 1: LanSee 一次扫描得到六层台账

- **问题**: 需要知道局域网里有哪些主机、共享资源和开放端口，才能判断是否存在异常设备。
- **方法论的使用**: 设置自动获取 IP 段、扫描间隔与资源间隔后开始扫描，结果按 IP 地址、计算机名、工作组、MAC 地址、共享资源、共享文件分列展示，并统计在线主机数。
- **结论**: 台账的价值不在“扫到几台”，而在先有一份正常基线；之后新增、消失、变更的条目才有比较对象。
- **结果**: 扫描出指定网段的主机清单并显示在线主机数，共享资源与共享文件可单独查看（PAGE 161–162）。

### 案例 2: 网络剪刀手切断与恢复目标主机

- **问题**: 某台主机需要被限制访问网关，但不能让整个网段陪它一起断网。
- **方法论的使用**: 选中目标 IP 执行切断，观察其“开/关”状态变化；需要恢复时再点“恢复”，让状态回到“开”。
- **结论**: 内网可达性本身就是一个可被单点操控的开关，所以防御要有分段与关键主机保护，而不是假设“大家都能互通”。
- **结果**: 被切断主机不能访问网关、也不能打开网页；点“恢复”后可以重新访问因特网（PAGE 165–166）。

### 案例 3: 大势至用白/黑名单先分类再隔离

- **问题**: 扫描到一批设备后，无法直接判断哪些该断开、哪些应保留通信。
- **方法论的使用**: 先按资产归属把设备分入白名单（内部电脑）与黑名单（外部电脑），再对黑名单启用“自动隔离外来计算机/手机/平板”和“自动隔离局域网无线路由器”；确认某台是内部电脑后，将其移回白名单。
- **结论**: 准入控制不是“发现陌生就全断”，而是先分类，再按类别决定连通范围。
- **结果**: 外来设备被自动隔离，内部设备在白名单中保持正常通信（PAGE 182–183）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 办公室有人说网速突然变慢，怀疑有人私接无线路由器或蹭网。
2. 接手一个没有文档的小型内网，需要先盘点有哪些设备、共享资源和开放端口。
3. 发现陌生 IP/MAC、IP 冲突或 ARP 异常，需要隔离但不想让整个网段断网。
4. 要建立准入规则：区分内部与外部设备，做 IP-MAC 绑定，并定义关键主机组。
5. 准备变更网管策略或绑定表，需要先核对上游已有配置，并确保能够回滚。

- “IP 冲突” / “ARP 攻击” / “只断这一台，别影响别人” / “关键主机组怎么设”

### 与相邻 skill 的区分

- 与 `recon-funnel-and-scoping` 的区别: 后者面向外部目标的侦察与范围界定；本 skill 只在已授权的自有内网做资产台账与可达性收敛。
- 与 `identity-deception-detection` 的区别: 后者判断 ARP、DNS、URL 是否在欺骗；本 skill 用台账、绑定和隔离降低可达性，不承担欺骗取证。
- 与 `wireless-security-grading` 的区别: 后者配置无线加密与认证；本 skill 不配置无线加密，只把 AP 当作准入与咽喉点。
- 与 `host-default-surface-convergence` 的区别: 后者管单机默认攻击面；本 skill 管网段级的“谁看得见谁、谁能到谁”。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行:

1. **建立六层台账**
   - 完成标准: 每台在线设备都有 IP、主机名、工作组、MAC、共享资源、开放端口六层字段；未知或缺失字段被标注，台账可导出并与基线比对。
   - 判停条件: 若网络使用动态地址且拿不到 DHCP 租约，先固定观测窗口或从网关/DHCP 取租约，否则台账不可比。

2. **与基线比对并归类异常**
   - 完成标准: 形成异常清单，按地址冲突、冒名主机、跨组访问、伪造 MAC、非授权共享、多余服务六类归档；每类都有至少一条证据。
   - 判停条件: 若只有单层变化（例如 DHCP 换 IP），不要直接定性，需第二层证据（MAC 同时变化、共享/端口异常等）再继续。

3. **确定准入基线**
   - 完成标准: 每台设备有明确归属（白名单/黑名单），关键主机组与敏感主机单列并经业务确认；绑定策略明确由哪一层统一维护。
   - 判停条件: 若上游路由器、防火墙或交换机已有 IP-MAC 绑定，先盘点既有绑定并决定维护层，禁止再叠一套绑定。

4. **在咽喉点做最小半径隔离**
   - 完成标准: 违规主机无法到达关键主机组，其他业务通信保持正常；隔离动作发生在网关、AP 或交换层，未对路由器、交换机、服务器执行锁定或“管理”动作。
   - 判停条件: 若隔离会波及业务，先降级为告警或限速，并安排维护窗口后再执行断连。

5. **留好变更记录与恢复路径**
   - 完成标准: 变更前已导出既有绑定、策略与拓扑，变更后有可执行的回滚清单；隔离已实际验证可解除，关键设备仍可通过带外或本地通道管理。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 未授权的网络或他人网络：不做扫描、绑定、隔离或任何可达性操作；本 skill 以“自有或书面授权”为前提。
- 需要配置无线加密、认证、访客网络：转 `wireless-security-grading`；本 skill 只把 AP 当作准入与咽喉点，不做无线加密配置。
- 已确认主机失陷、需要取证或清除恶意代码：转 `malware-triage-order` 与 `log-integrity-and-evidence`；本 skill 不负责样本处置与证据链。
- 只是单台主机的默认配置加固：转 `host-default-surface-convergence`；本 skill 处理网段级可见性与可达性。

### 作者在书中警告的失败模式

- **把“监听整个网络”当常规排查手段**（ce04）：交换网中要看他人流量通常要先做 ARP 欺骗或端口镜像，全网监听会持续污染多台主机的 ARP 缓存，造成丢包、IP 冲突、网关表项震荡，甚至中断业务；还会接触同事的明文凭据，带来授权与合规问题（PAGE 168）。
- **锁定路由器、交换机、服务器等关键设备**（ce05）：这类“锁定/管理”多通过 ARP 欺骗或断开 TCP/IP 连接实现，不区分普通终端与关键资产；锁定网关会让整个网段无法上网，锁定服务器会让业务中断，且可能需要现场或带外管理才能恢复（PAGE 181–182）。
- **在已有 IP-MAC 绑定的网络里再叠一层绑定**（ce06）：两套绑定表不一致时，合法主机会被判定为“非法 IP/MAC”而断网或隔离；排障往往只查一层，容易误判为网卡、DHCP 或病毒（PAGE 176）。
- **把 ping 超时当成“无法 ARP 欺骗/主机安全”**（ce07）：防火墙可以只丢弃 ICMP 而继续转发其他协议，ARP 工作在链路层，不需要目标响应 ping；ping 通也不代表目标易受攻击（PAGE 172）。

### 作者的盲点 / 时代局限

- 工具绑定严重：LanSee、网络剪刀手、WinArpAttacker、大势至、聚生网管、长角牛等多已停更或难以获取，书中步骤随版本失效；应只保留“台账—准入—咽喉点—分组隔离—回滚”的框架。
- 现代网络已有 802.1X/NAC、交换机 DAI 与端口安全、DHCP Snooping、微分段与 SDN 策略，书中未覆盖；这些应作为 IP-MAC 绑定与手工隔离的替代或上位方案。
- 书中大量演示断网、ARP 欺骗与监听操作，却缺少授权边界说明；本 skill 只允许在自有或书面授权网络内使用，且优先选择可审计、可回滚的控制点。
- 作者假设管理员能随时到现场恢复；未讨论远程操作把网关锁死后的带外通道问题。

### 容易混淆的邻近方法论

- “发现”不等于“准入”：LanSee 类扫描只回答“有哪些设备”，白/黑名单与绑定才回答“谁被允许接入”。
- “关键主机组”不等于“重要资产清单”：它是隔离时控制附带损伤的边界；把过多主机放进去，隔离就会变成全面断网。
- “白名单/黑名单”不是信任等级：在大势至语境下它只表示资产归属，内部电脑也可能中毒。
- “全网监听”不等于“流量分析”：需要流量证据时应使用端口镜像、NetFlow/sFlow 等可审计手段，而不是 ARP 欺骗式监听。
