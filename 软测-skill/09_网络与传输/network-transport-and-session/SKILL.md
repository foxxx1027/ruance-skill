# 网络传输与会话安全

## R — 原文

> c） 避免将没有成功的 TLS 连接后退为一个不安全的连接……确保 TLS 证书是有效的，有正确且未过期的域名，并且在需要时，和中间证书一起安装。f） 会话标识符应总是在一个可信系统上创建……如果一个会话在登录以前就建立，在成功登录以后，宜关闭该会话并创建一个新的会话。
>
> — GB/T 38674—2020，7.5 c) f)；另见 7.5 a) b) d) e)、5.3.1 g) k) l)、5.3.2 j)

---

## I — 方法论骨架

传输层先问三件事，顺序不能换：对面是谁，通道会不会被降级，消息是不是新鲜的。

加密只解决通道被窃听，证书校验才解决对面是谁。关掉校验之后，同网段的攻击者可以终止 TLS、出示自签证书，把加密流量变成可读可改的明文。因此要同时验证书链、有效期、域名匹配，必要时装中间证书；主机名校验不能关。

通道要单一标准：使用配置合理的 TLS，敏感文件与非 HTTP 连接也要覆盖；握手失败就断开，绝不回退到 HTTP 或更弱协议；TLS 上传输的 cookie 打 Secure 属性。

消息层要有新鲜性与完整性：重要消息做摘要或签名；重放检测用时间戳加随机数联合判断，单用时间戳可被截取重放，单用随机数要额外维护存储与过期。

会话是另一条时间线。标识必须由服务端或可信框架生成、足够随机、只认有效的；登录前就存在的会话在登录成功后关闭并新建；任何重新鉴别都换新标识；HTTP 转 HTTPS 时换标识，并尽量全程 HTTPS；登出彻底终止；超时取业务可接受的最小值；同一用户 ID 的并发登录按业务决定。

口令不进明文信道，传统协议要套安全传输；修改口令、改绑定、转账、删除这类不可逆操作，执行前重新鉴别一次。核心区分是：鉴别是某个时刻的事件，会话是一段时间的凭据，两者必须分别设计。

## A1 — 书中的应用

### 案例 1: 会话永不过期且 SSLSocket 不验主机名（附录 A.4.5.2、A.4.5.3，对应 7.5 f)、7.5 c)）

- **问题**: 会话超时配置为永不过期；建立 SSLSocket 时使用了不校验主机名的重载，甚至直接关闭全部 SSL 检查。
- **方法论的使用**: 前者把一次性鉴别变成永久通行证，标识一旦被窃取可无限期复用；后者只有加密没有身份认证，攻击者在链路上冒充服务端即可解密。
- **结论**: 超时设成具体分钟数并在登录后重建会话；改用带主机名与端口的建连方式，保留证书与主机名校验。
- **结果（防住什么）**: 不修时会话可被长期盗用、TLS 可被中间人劫持；修正后会话定时失效，握手校验服务端身份。

### 案例 2: SSL 连接不校验服务器证书（附录 A.2.3.1.3，对应 5.3.1 g)）

- **问题**: 邮件客户端只开启 SSL 连接，未开启服务器身份校验，所用库默认不验证证书。
- **方法论的使用**: 传输层的第一问是对面是谁；不验证书等于信任所有证书，加密仍在但认证缺失，中间人持任意域名证书即可冒充。
- **结论**: 显式开启服务器身份校验，并按所用库完成证书链与主机名验证。
- **结果（防住什么）**: 不修时任何证书都被接受，用户名口令与邮件内容可被截获篡改；修正后证书或域名不匹配即握手失败。

### 案例 3: 直接用网络传来的明文口令连数据库（附录 A.2.3.2.4，对应 5.3.2 g)）

- **问题**: 从请求参数取出明文口令，直接交给驱动建立数据库连接；相邻示例还有 null 口令与空口令。
- **方法论的使用**: 口令属于要求身份鉴别的数据，不能在不安全信道中传输，也不能以明文进入配置与日志；凭据应来自受保护的配置并保持密文。
- **结论**: 口令经加密信道传输、加密后存放，建连时解密使用；null 与空口令直接拒绝。
- **结果（防住什么）**: 不修时口令可被抓包或从代码中读取，数据库凭据泄露；修正后传输与存储均为密文，无凭据无法建连。

## A2 — 触发场景

### 用户会在什么情境下需要这个 skill?

1. 上线 HTTPS、配置反向代理或网关终止 TLS，需要确认认证与降级行为。
2. 移动端或内部客户端报证书错误，产品要求先关掉校验把功能跑通。
3. 排查会话固定、登出后令牌仍可用、会话超时过长、多设备并发登录策略。
4. 开放 API、支付回调、设备上报需要防止报文篡改与重放。
5. 内网已经上了 mTLS 或服务网格，团队问应用层还要不要签名与防重放。

### 语言信号

- "证书报错先关掉校验"（just disable certificate validation）
- "已经 HTTPS 了还需要防重放吗"（is anti-replay still needed over HTTPS）
- "会话多久过期 / 登出后 token 还能用"（session timeout / token still valid after logout）
- "登录后要不要换 session id"（should the session id be rotated after login）
- "内网 mTLS 够不够"（is mTLS inside the network enough）
- TLS, certificate validation, hostname verification, session fixation, replay attack, MITM

### 与相邻 skill 的区分

- 与 `authentication-and-passwords` 的区别：后者管鉴别强度、穷举与账号枚举；本 skill 管鉴别之后那条会话通道怎么建、怎么续、怎么终止。
- 与 `authorization-and-least-privilege` 的区别：本 skill 判断通道对端与会话是否可信，授权判断这个主体能否操作该对象；会话有效不等于有权。
- 与 `sensitive-data-lifecycle` 的区别：后者管数据在存储与展示中的加密与密钥，本 skill 只管数据在传输通道上的保护。

## E — 可执行步骤

1. **画通道清单**
   - 动作：列出所有跨信任域的连接，标注协议、TLS 版本、证书来源、TLS 终止点、是否跨主机。
   - 完成标准：每条通道有加密方式、认证方式、终止位置三项；明文通道单独标红。
   - 判停条件：若通道仅为本机 Unix socket 且无跨主机，标注不适用并跳过步骤 2、3。

2. **验证认证而不是只验证加密**
   - 动作：检查客户端是否校验证书链、有效期、域名，服务端是否配置完整证书链；搜索空信任管理器、恒真主机名校验、关闭校验的开关。
   - 完成标准：每个客户端有证书校验与主机名校验开启的证据；服务端证书链完整；不存在关闭校验的代码或配置。

3. **检查降级与失败分支**
   - 动作：走一遍握手失败、协议协商失败、超时、证书错误的处理路径，确认不会回退到 HTTP 或弱协议；确认 cookie 带 Secure。
   - 完成标准：所有失败分支的结论是断开或重试安全连接，没有降级分支；TLS 承载的会话 cookie 已加 Secure。

4. **确认消息新鲜性与完整性**
   - 动作：对写操作、回调、支付、设备上报等接口确认有摘要或签名，以及时间戳加随机数的联合判重，随机数有存储与过期。
   - 完成标准：每个敏感接口有三项结论（完整性、时间窗、随机数唯一性）。
   - 判停条件：若接口只在未终止 TLS 的内网 mTLS 中传输，可标为可接受残余风险并写明理由。

5. **核对会话生命周期**
   - 动作：逐项检查标识生成源与随机性、登录后重建、重新鉴别换标识、HTTP 转 HTTPS 换标识、登出终止、超时值、并发登录策略、关键操作重鉴别。
   - 完成标准：八项各有具体值或书面业务权衡；超时是分钟数而不是永久；关键操作有重鉴别入口。

## B — 边界

### 不要在以下情况使用此 skill

- 问题是算法、模式、密钥长度、IV 或口令散列选型：属于敏感数据与加密方法论，本 skill 不判断密码学强度。
- 需要设计或运维 PKI、证书签发流程、CA 信任链治理：超出编码指南范围。
- 问题在应用层谁能访问哪个对象：那是授权，通道可信不代表有权。
- 目标是 TLS 握手性能与连接复用优化：那是性能工程，不是安全编码。
- 遗留设备只支持已被淘汰的协议且无法替换：本 skill 只能标记风险与补偿控制，不能给出合规结论。

### 作者在书中警告的失败模式

- **ce18 为兼容关掉 TLS 校验或降级到明文**：空信任管理器、恒真主机名校验、握手失败后重试 HTTP，等于把加密降级为可读可改；用反向 DNS 或来源 IP 作为身份依据，则把授权交给了可被欺骗的网络层。
- **ce09 只在登录那一刻鉴别**：会话不过期、不重建、不随权限变更失效，一次窃取即可长期复用；只保护已知入口，其他 API、消息、下载通道裸奔。
- **ce05 用非密码学随机数生成会话标识**：线性同余生成器的输出由种子决定，观察少量输出即可预测下一个令牌，直接导致会话劫持或重置接管。

### 作者的盲点 / 时代局限

- 未覆盖 mTLS、服务网格与零信任：在 sidecar 管理证书的架构里，应用看不到证书链，标准里客户端校验的条目要重新映射到平台配置与策略。
- 未覆盖 OAuth2、OIDC 与 JWT 的失效、刷新、撤销，也未讨论 SameSite、CSP 等现代会话手段；禁并发登录在移动端多设备场景是业务权衡而非硬规则。
- 只写配置合理的单一标准 TLS，没给版本与套件基线，也没讨论证书固定、后量子迁移与 HSTS 预加载。

### 容易混淆的邻近方法论

- 身份鉴别与口令安全：鉴别回答这一次凭据对不对，本 skill 回答这条会话能活多久、在哪些节点必须换新。
- 敏感数据生命周期：数据在磁盘上要不要加密归它管，在链路上要不要加密归本 skill 管。
