# 身份替换类欺骗的识别与处置

## R — 原文 (Reading)

> “DNS 欺骗并不是要黑掉对方的网站，而是冒名顶替，从而实现其欺骗目的。”
>
> “ARP欺骗木马的中毒现象表现为：使网络中的计算机突然掉线，过一段时间后又会恢复正常。”
>
> — 网络安全技术联盟，第6章 绝招9、绝招10

---

## I — 方法论骨架 (Interpretation)

ARP、DNS、URL 钓鱼看起来是三件事，底层却是同一个结构：受害者需要一个“身份到地址”的映射，而攻击者抢先把错误答案递了过来。目标网站、网关、真实域名都不需要被攻破；被替换的是“谁是谁”的答案。

所以排查的第一步不是找病毒，而是问：这次故障里，哪一层映射被替换了？IP 与 MAC 的映射对应二层，域名与 IP 的映射对应解析层，页面显示与实际跳转、证书的映射对应应用层。层次定了，证据类型和修复手段才定得下来。

现象的时间形态很有用：间歇性、成片出现、过一会儿自行恢复，通常更像同网段的二层欺骗；只有某个域名出错、其他网站正常，更像解析层；地址栏、证书、跳转链对不上，则落在应用层。

确认要靠对照，而不是靠单一提示：网关 MAC 与路由器标签或管理页对照，nslookup 与可信 DNS 对照，显示文本与实际 href、证书 SAN 对照。悬停状态栏、页面外观都不足以作为判据。

最后是处置顺序：先做验证性修复（确认 MAC 后再静态绑定、改用可信解析），再按“第一次提交即泄露”处理凭据，最后复查映射与故障是否复发。修复动作本身也可能造成断网，所以要先核对再落地。

## A1 — 书中的应用 (Past Application)

### 案例 1：用 IP 冲突提示确认局域网阻断生效
- **问题**：作者要验证局域网内把某台主机加入阻断列表后是否真的生效。
- **方法论的使用**：先用 ipconfig 确认本机网段、ping 同网段主机确认连通，再把 192.168.0.108 加入阻断列表，并以目标是否出现 IP 冲突提示作为判据；若 ping 超时，先考虑防火墙等干扰，而不是直接判失败。
- **结论**：目标弹出 IP 冲突提示，说明其网络身份被干扰，阻断生效。
- **结果**：目标无法正常使用 TCP/IP；作者同时提醒，ping 不通不能直接当作攻击失败。

### 案例 2：显示为银行域名、实际跳转到伪装站
- **问题**：需要判断一个“显示为银行域名”的链接是否可信。
- **方法论的使用**：检查显示文本与实际 href 的分离，而不是只相信页面文字或悬停状态栏。
- **结论**：显示文本是 95599，实际 href 指向百度；点击后打开的是伪装网站。
- **结果**：用户看到的地址与最终落点不一致，说明应用层的身份映射可以被替换。

### 案例 3：网关 MAC 静态绑定，填错就断网
- **问题**：部署 ARP 防御，需要让主机只信任正确的网关映射。
- **方法论的使用**：手工把网关 IP 与 MAC 静态绑定，书中特别提示必须核对 MAC 是否正确。
- **结论**：静态绑定是有效防御，但配置本身有可用性风险。
- **结果**：作者特别提示必须把网关 MAC 设置正确，否则将无法上网。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **局域网时好时坏**：一个办公室或机房多台机器同时断网，过一会自行恢复，重启网卡也查不出硬件故障。
2. **访问到假站**：地址栏、证书或页面与常用网站不符，或登录后立即提示密码错误。
3. **链接核验**：收到显示为银行、OA 或邮箱域名的链接，需要判断点击后到底去哪里。
4. **故障定层**：已经怀疑 ARP 或 DNS，但不确定是二层、解析层还是应用层，需要设计对照验证。
5. **处置后复查**：做了静态绑定或更换 DNS 后，需要确认没有造成新的断网、欺骗是否停止。

### 语言信号 (用户的话里出现这些就应激活)

- “网络一会儿断一会儿好”
- “整个办公室都断了，过会又自己好了”
- “打开的是假网站 / 钓鱼网站”
- “密码明明是对的，一直提示错误”
- “网关 MAC 对不对”
- “nslookup 结果不一样”
- "ARP spoofing"、"DNS spoofing"、"MITM"、"rogue gateway"、"phishing URL"、"wrong certificate"

### 与相邻 skill 的区分

- 与 `wireless-security-grading` 的区别：那个 skill 解决 Wi-Fi 加密与口令（WEP/WPA/WPS），是“能不能接入”；本 skill 解决接入之后“身份映射是否被替换”。
- 与 `recon-funnel-and-scoping` 的区别：那个 skill 是主动扫描目标、收敛漏洞面；本 skill 是对照当前连接，判断“谁在冒名回答”。
- 与 `malware-triage-order` 的区别：那个 skill 处理主机上的恶意进程与持久化；本 skill 处理网络路径上的身份替换。若抓到本机 ARP 欺骗木马，可组合使用：先断网络入口，再清主机。
- 与 `hidden-account-hunt` 的区别：那个 skill 处理主机内账号被隐藏；本 skill 处理网络身份被替换。两者都可能表现为“登录异常”，但一个看账号视图，一个看映射与证书。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行：

1. **判定疑似层次**
   - 记录故障的时间形态（间歇、持续、自恢复）、影响范围（单机、同网段、全员）、受影响对象（所有流量、某个域名、某个链接）。
   - 完成标准：形成一行“层次假设 + 支持现象 + 反证”，能说清为什么先怀疑二层、解析层或应用层。
   - 判停条件：若只是单个网站打不开、其他正常，优先按解析层或应用层查；若同网段成片断网，优先二层。

2. **做对照验证**
   - 二层：对照网关 IP 的 MAC 与路由器标签或管理页，观察 MAC 是否频繁变化或重复；比较“ping 同网段主机”和“ping 网关”；在确认正确 MAC 后做静态绑定 A/B 测试，或抓包看是否有大量伪造 ARP 应答。
   - 解析层：用 nslookup 或 dig 分别查询本地 DNS 与可信 DNS，核对结果；检查 hosts、路由器 DNS 设置、DNS 缓存；看证书域名与签发者是否匹配。
   - 应用层：核对地址栏实际域名、链接真实 href、跳转链与证书；不要只依赖显示文本或悬停状态栏。
   - 完成标准：至少两条独立证据指向同一层，并能排除服务器宕机、普通链路故障与正常跳转。
   - 判停条件：若证据互相矛盾，保持“未定性”，先抓包或隔离受影响主机，不要急着改配置。

3. **做验证性修复**
   - 二层：先核对网关 MAC，再静态绑定或启用 ARP 防护，绑定后立即测试上网。解析层：改用可信 DNS 或加密解析，清理缓存，检查路由器 DNS 是否被改。应用层：用书签或手动输入到达官网，核对证书，阻断假站。
   - 完成标准：故障消失或欺骗路径被阻断，同时没有引入新的断网（能 ping 通网关、能解析并打开正常网站）。
   - 判停条件：若绑定后立刻断网，先回滚绑定，回到步骤 2 重新核对 MAC；不要把它当成“攻击没清干净”。

4. **处置凭据**
   - 按“第一次提交即泄露”处理：只要在可疑页面提交过账号密码，就视为已泄露；从干净设备改密，撤销会话与令牌，检查异常登录，启用多因素认证；同一密码在其他系统复用的，一并更换。
   - 完成标准：密码已更换、旧会话已失效、异常登录已排查、复用密码已全部处理。
   - 判停条件：若无法确认是否提交过，按已泄露处理，不要用“没登录成功”作为安全证据。

5. **复查与记录**
   - 重新核对关键映射（网关 MAC、域名解析、证书），观察一个工作周期内是否复发；记录时间线、受影响主机、证据与处置动作。
   - 完成标准：复查期内无复发，正常业务访问恢复，处置记录可供复盘。
   - 判停条件：若同一现象反复出现，回到步骤 1，考虑路由器或 DNS 服务器被控、内网存在其他欺骗源、终端已被植入。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 单个网站打不开、服务器宕机、带宽不足等普通可用性故障：先按服务可用性与链路排查，不要一上来就归因于欺骗。
- 无线口令被破解、WEP/WPA/WPS 加固：用 `wireless-security-grading`；本 skill 不解决“能不能接入”。
- 主机上的恶意进程、挖矿、病毒查杀：用 `malware-triage-order`；本 skill 只处理网络路径上的身份替换。
- 主机内隐藏账号与凭据持久化：用 `hidden-account-hunt`。
- 没有证据就断言“网站被黑”：DNS 欺骗不等于目标服务器被攻破，两者排查方向不同。

### 作者在书中警告的失败模式

- **网关 MAC 静态绑定填错**：绑定后立刻无法上网，还被误判为 ARP 攻击没清除（ce05）。warning_signs：绑定后马上断网、解除即恢复；能 ping 通同网段主机但 ping 不通网关；ARP 表中的网关 MAC 与路由器标签或管理页不一致。
- **只看显示文字或悬停状态栏**：显示文本与 href 可以分离，状态栏也可能与实际落点不一致（ce06）。warning_signs：显示域名与地址栏不一致；悬停地址与点击后落点不一致；域名只差一个字符；链接经过短链、跳转或编码。
- **反复重输密码**：可疑页面第一次提示“密码错误”时，凭据可能已经被记录；继续重输只会补充更多样本（ce07）。warning_signs：登录立即报错但域名或证书与官方不符；反复要求重输；提交后跳到与业务无关的页面。
- **把 DNS 欺骗当成网站被黑**：目标站点可能完全正常，被替换的是解析结果（g10）。warning_signs：只有本机或本网段解析异常，换可信 DNS 后恢复；证书域名不匹配。

### 作者的盲点 / 时代局限

- 书中的 ARP/DNS 演示默认攻击者与目标处于同一局域网，未覆盖跨网段、运营商 DNS、公共 Wi-Fi 与云环境。
- 书以旧版 Windows 和旧工具为主，菜单路径与工具行为会随版本失效；不要把“局域网终结者”“绿盾”的操作步骤当成方法本体。
- 书没有讨论 HTTPS 证书校验、DNSSEC、DoH/DoT、企业网的动态 ARP 检测、端口隔离与 802.1X，这些在现代环境中应优先于手工静态绑定。
- 书重演示、轻验证：很少说明修复后如何确认生效；本 skill 用“绑定后能上网、解析对照一致、证书匹配”补上验证环节。

### 容易混淆的邻近方法论

- “网络故障排查”不是“身份欺骗识别”：前者先查链路、设备与服务可用性；后者查“谁在回答身份映射”。
- “无线加密加固”不是“ARP 防御”：一个保护空口接入，一个保护局域网内的 IP 与 MAC 映射。
- “主机杀毒”不是“路径欺骗处置”：清除本机木马不等于清除了网关、DNS 或上游的冒名回答。
