# 网络欺骗、MITM 与设备攻击链

## R — 原文 (Reading)

> "欺骗让我们能够假扮成其他系统。在计算机系统和网络中，这是很有好处的，因为欺骗攻击允许我们利用系统之间的信任来提升在网络中的权限。"
>
> "在ARP欺骗中，我们将假扮成网关。这使我们能够拦截任何要离开我们的本地网络的流量。"
>
> — Daniel Regalado 等，《灰帽黑客 第4版》第8章 8.1、8.2

---

## I — 方法论骨架 (Interpretation)

1. **先判断信任关系，而不是先选工具**：目标信任谁、通过哪个协议信任——网关（ARP）、递归解析器（DNS）、本地广播/多播名称解析（NBT-NS/LLMNR）、更新服务器（HTTP 自动更新）、设备配置通道（SNMP/TFTP、ACL 与路由）。
2. **再判断自己站在哪一层**：二层可达才能 ARP 投毒；能影响解析器才能做缓存投毒；只在本地子网就伪造响应；已能改设备配置则改路由或建隧道。
3. **选择欺骗层**：ARP 伪装网关，看到并改写同网段出网流量；DNS/LLMNR/NBT-NS 把名称指到攻击者；应用更新劫持把合法更新换成恶意载荷。
4. **每次欺骗先定最小影响范围**：单主机、单网段、单协议；能只观察就不改写，能只中转必要流量就不全量转发。
5. **先判编码与加密**：明文 HTTP 才谈编码降级与响应注入；HTTPS 未降级时不承诺明文改写或凭据捕获；GRE 本身不提供机密性。
6. **凭据分两段处理**：捕获阶段只收集并保留主机映射；破解离线进行，不在线爆破以免锁定和告警。
7. **设备路径按顺序推进**：默认凭据→默认团体→只读/读写验证→配置外带→密码类型判定→流量中转；不把"能登录"当成结果。
8. **配置修改要双份核对**：区分 running-config 与 startup-config，用 show run / show startup 复核；回显 OK 不等于命令生效。
9. **影响控制与取证并行**：记录时间、主机、PCAP/哈希、执行命令与回滚步骤；结束后恢复 ARP、路由、隧道与临时账户。
10. **结论回答影响而非工具**：暴露了哪些凭据、流量与配置，涉及多少主机，应如何分段、关闭弱协议与加固。

## A1 — 书中的应用 (Past Application)

### 案例 1: Ettercap ARP 欺骗查看流量并抓取表单凭据（实验 8-1）

- **问题**: 授权测试需要证明同网段主机的明文 HTTP 凭据可被截获，但在正常交换网络中看不到受害机发往网关的流量。
- **方法论的使用**: 确认与网关 192.168.192.2、Windows 7 主机 192.168.192.20 处于同一广播域；用 `ettercap -T -q -M arp:remote` 把两端同时作为目标，利用无故 ARP 更新让双方都把攻击机 MAC 当作对方；按空格退出静默模式观察请求，由解析器提取表单字段；同时用 `-w` 保存 PCAP、`-m` 保存消息，便于后续用 Cain 二次解析。
- **结论**: ARP 投毒是把攻击机主动插入路径，不是被动嗅探；成立前提是二层可达并能持续维持缓存。Ettercap 的输出不带原始 IP，多目标时容易混淆，必须靠 PCAP 与日志做主机匹配。
- **结果**: 看到受害机发往外部 Web 服务器的 HTTP 请求，解析器输出 vulnuser/vulnpass 一组表单凭据。

### 案例 2: Responder 捕获 NTLMv2 并用 John 离线破解（实验 8-3）

- **问题**: 不知道内网存在哪些可认证主机，希望拿到可离线破解的凭据，同时避免在线爆破带来的锁定与噪声。
- **方法论的使用**: 把 Windows 7 的网络位置设为 Work/Home，确保认证走 SMB；在资源管理器输入不存在的主机名 ghh，Windows 先查 DNS 失败，随后发出 LLMNR 查询；Responder 抢先应答并记录用户 sussurro 的 SMB-NTLMv2 质询哈希。捕获完成后停止监听，用 John 配合 rockyou 字典和 `--rules` 规则模式离线破解。
- **结论**: 名称解析回退就是系统间信任缺口：任何本地主机都能应答 LLMNR/NBT-NS。正确节奏是"先积累哈希、再离线破解"，而不是边抓边爆破。
- **结果**: John 在两秒内解出明文 Abc123!，证明默认质询加弱口令在离线模式下几乎不构成阻力。

### 案例 3: Cisco SNMP→TFTP 外带配置，再用 GRE 中转抓 Basic Auth（实验 9-1～9-9）

- **问题**: 目标 Cisco 设备管理密码猜不中，但设备仍开放 SNMP；需要拿到配置中的凭据，并观察经过路由器的内网明文认证流量。
- **方法论的使用**: Nmap -A 枚举 SSH/HTTP 管理接口；Ncrack 与 Metasploit 的默认密码字典均未命中，按判据转向 SNMP——onesixtyone 加默认团体字典找到 public 与 secret，再用 snmp_login 确认 secret 为读写、public 为只读。随后用 `cisco_config_tftp` 设置读写团体、RHOSTS、LHOST 与 OUTPUTDIR，让设备主动连接攻击者 TFTP 并回传 running-config；解析出 enable/admin 的 Type5 哈希与 test 用户的 Type7 密码，Type7 直接还原、Type5 交给 John。最后建立 GRE：Kali 上 tun0（local 192.168.1.90、remote 192.168.1.250，10.10.1.2/24），路由器上用 ACL 100/101 分别匹配出站与入站的 HTTP/Telnet/SMTP，route-map 把 next-hop 指向隧道地址并应用到内外接口，Kali 开启 ip_forward 并补回目标内网路由，在 tun0 上 tcpdump。
- **结论**: 设备访问权本身价值有限，价值在配置外带与选择性流量中转。GRE 不加密、延迟越高越容易被察觉，因此只引必要协议，并分别匹配出站与入站。
- **结果**: 取得 1340 字节 running-config 与 test/Passw0rd! 的非特权 SSH 访问，enable 的 Type5 破解为 Abc123!；GRE 隧道中抓到 `Authorization: Basic YWRtaW46QWJjMTIzIQ==`，解码为 admin:Abc123!。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 已获授权的内网渗透或红队评估，需要证明同网段凭据与流量暴露面，例如明文 HTTP 表单、SMB 认证哈希、Basic Auth。
2. 发现 Windows 主机访问不存在主机名，或 DNS 解析失败后回退到 LLMNR/NBT-NS，想评估 Responder 类捕获风险。
3. 观察到某软件自动更新走明文 HTTP、缺少签名校验，需要评估更新通道被整体替换的风险。
4. 发现 Cisco 或同类网络设备管理接口可达，默认凭据、SNMP 团体字符串或配置外带路径可疑。
5. 蓝队、审计或报告阶段，需要解释 ARP/DNS/LLMNR/GRE 欺骗的检测信号，并给出分段、关闭弱协议与加固建议。

### 语言信号 (用户的话里出现这些就应激活)

- "同网段能不能抓到别人的明文密码"
- "访问了一个不存在的主机名，怎么就发出 NTLM 哈希了"
- "Responder 抓到的哈希怎么破"
- "软件自动更新能不能被替换成后门"
- "Cisco 设备默认密码进不去，还能从哪进"
- "SNMP 团体字符串能读到什么，能不能下载配置"
- "GRE 隧道把流量引过来抓包怎么做"
- "ARP 欺骗 / DNS 欺骗 / 中间人 / MITM / LLMNR / NBT-NS"

### 与相邻 skill 的区分


- 与 `web-encoding-filter-bypass` 的区别: 后者在 Web 编码与规范化层，问"同一字节串在过滤器与执行者眼里是否不同"；本 skill 在链路、名称解析与设备配置层，不构造 SQLi/XSS payload。只有流量已被劫持、需要改写明文 HTTP 响应时，才借用"编码降级后再匹配"这一小步。
- 与 `beef-client-side-attack` 的区别: 后者从脚本已在浏览器执行之后接手，负责挂钩、指纹、模块与 JavaPayload；本 skill 负责把流量引到攻击者、把目标引到恶意更新、捕获凭据，属于投递与凭据层，不负责浏览器后渗透。
- 与 `pentest-engagement-and-disclosure` 的区别: 后者定义授权、范围与披露；本 skill 的所有主动投毒、配置修改与隧道搭建都以该授权与停止条件为前提，不能反过来用技术可行性替代授权。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **确认授权与影响边界**
   - 完成标准: 写明授权网段/设备、允许的欺骗方式、时间窗、禁止动作、数据处置与停止条件。
   - 判停条件: 无书面授权，或目标属于生产网且无维护窗口 → 停止主动投毒，改为只做被动观察与配置审查。

2. **画出信任关系与流量路径**
   - 完成标准: 列出网关、DNS、WINS/LLMNR 行为、自动更新源、设备管理协议，以及自己与目标的二层可达性和是否加密。
   - 判停条件: 目标网段不可控（不同广播域、无法影响解析或路由）→ 只做被动观察，不进入投毒步骤。

3. **选择欺骗层与最小影响方案**
   - 完成标准: 在 ARP、DNS、LLMNR/NBT-NS、更新劫持、设备配置路径中选定一条，并写清单主机/单网段/单协议的范围与回滚方法。
   - 判停条件: 目标已强制 HTTPS/HSTS 且无降级点 → 放弃明文改写与凭据捕获，只评估元数据暴露。

4. **部署工具并做基线验证**
   - 完成标准: 转发已开启、抓包与日志路径确定；在单台非关键主机上确认流量可见或名称可被应答。
   - 判停条件: 基线阶段即出现断网、网关异常或地址冲突 → 立即停止并恢复，不扩大范围。

5. **执行欺骗并验证可见性**
   - 完成标准: PCAP/日志中出现目标流量或伪造应答，且能对应到具体主机与时间。
   - 判停条件: 网络启用了动态 ARP 检测/端口安全/802.1X 导致投毒失败 → 停止投毒，转设备配置或被动分析。

6. **捕获凭据并离线处理**
   - 完成标准: 哈希或 PCAP 已保存，标注来源主机、协议、用户名；破解在独立环境用字典与规则离线进行。
   - 判停条件: 只能在线爆破才能继续 → 停止，避免锁定与告警；改为检查其他信任路径。

7. **设备路径：默认凭据与 SNMP 团体**
   - 完成标准: 管理接口清单完整，默认用户名/密码与默认团体已快速尝试并记录结果；找到团体后用 snmp_login 确认只读/读写。
   - 判停条件: 默认凭据失败 → 转 SNMP 团体猜测；团体只读 → 只做信息收集，不尝试 SNMP set。

8. **配置外带与密码类型判定**
   - 完成标准: 通过 SNMP+TFTP 取得 running-config/startup-config，解析出用户名、团体、Type5/Type7 密码与接口路由信息。
   - 判停条件: 只有脚本回显 OK、show run 中没有目标配置 → 判定未生效，停止后续依赖该配置的步骤。

9. **流量中转（GRE）只引必要流量**
   - 完成标准: 出站与入站 ACL 分别匹配协议/源目/端口，route-map 已应用，攻击机转发与回程路由正确，tun0 上抓到预期流量。
   - 判停条件: 链路利用率或延迟明显上升、用户可感知变慢 → 缩小 ACL 或停止中转。

10. **控制影响范围并恢复**
    - 完成标准: 停止投毒并恢复 ARP 缓存，撤销 route-map/ACL/隧道与临时账户，核对网络恢复基线。
    - 判停条件: 无法恢复设备配置或网络状态 → 停止测试并立即上报，保留现场。

11. **取证与报告**
    - 完成标准: 证据链包含时间、主机映射、PCAP/哈希、执行命令与配置差异；结论写明暴露的凭据/流量/配置、影响主机数与加固建议。
    - 判停条件: 证据无法对应到具体主机或时间 → 补做基线记录，不得用推测填充结论。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **非授权网段或生产网络**: ARP/DNS 投毒、GRE 改路由都可能造成断网与业务中断；没有 SOW 与维护窗口时等同于入侵。
- **加密流量且无法降级**: 强制 HTTPS/HSTS、证书固定、更新走 HTTPS 并带签名校验时，MITM 只能看到连接元数据；不要承诺捕获明文凭据或改写页面。
- **设备型号与固件差异过大**: 书中的 Cisco IOS 12.4 命令、OID、ACL/route-map 语法不能直接套用到 IOS-XE、ASA、FTD 或其他厂商设备；未确认型号与版本前不得照抄。
- **网络已部署动态 ARP 检测、端口安全或 802.1X**: 投毒可能失败或直接触发阻断；应先确认防护状态，再决定是否改为被动观察。
- **只需证明单个应用漏洞**: 一个可复现的应用层证据即可交付，引入链路层欺骗只会扩大影响面与风险。

### 作者在书中警告的失败模式

- **ce54**: 向已接近满载的 HTTP 响应包追加数据，只做替换不腾空间，包尾被截断、页面结构损坏。
- **ce55**: 把证书告警当作 DNS 欺骗的充分防御，忽略用户会点击"继续"并访问伪造主机。
- **ce56**: 网络仍允许 NTLMv1，攻击者固定质询后哈希可预计算，离线破解速度被大幅放大。
- **ce57**: 默认密码没中就越过其他服务直接放弃，漏掉 SNMP 团体、HTTP realm 等入口。
- **ce58**: 看到 Cisco::CopyConfig 的 merge 返回 OK 就认为配置生效，未用 show run 核对。
- **ce59**: 只改 running-config 未写入 startup-config，设备重启后后门账户或路由规则消失。
- **ce60**: 把全部进出流量引入 GRE，隧道与上游链路拥塞，用户明显感知异常。
- **ce61**: 把 Cisco 公告都当成可远程拿 shell 的漏洞，忽略其中大量是 DoS 且依赖具体型号/版本。
- **ce62**: 重复用同名文件上传配置，Metasploit TFTP 缓存旧内容，设备拿到的不是新文件。
- **ce129**: 对整段网络做 ARP 投毒，大量主机断网、网关异常，测试暴露并造成事故。

### 作者的盲点 / 时代局限

- **Cisco IOS 旧版本语境**: 书中实验基于 IOS 12.4 与当时的 SNMP/TFTP 行为；现代设备的默认服务、OID 支持与管理面已变化，命令和路径必须逐目标重验。
- **弱协议已收窄**: NTLMv1 与 Type7 在合规环境中已少见，域环境默认 NTLMv2，新配置多用更强哈希；书中"两秒破解"不能外推为普遍结果。
- **自动更新普遍加密与签名**: Evilgrade 依赖明文 HTTP 与缺失签名校验，今天多数软件已改用 HTTPS 加代码签名，适用面显著缩小。
- **工具与版本过时**: Ettercap、Responder、Evilgrade、Metasploit 模块的选项与输出会随版本变化，不能照抄命令。
- **默认实验条件**: 同广播域、Host-Only 网络、可关闭防护、本地管理员，都是书中成功的前提；生产环境还有分段、EDR、代理与日志。
- **检测与合规讨论不足**: 书中以完成攻击链为主，较少讨论检测工程、影响最小化与测试后恢复，执行时必须自行补足。

### 容易混淆的邻近方法论

- **欺骗 vs 扫描/爆破**: 前者利用系统间既有信任（网关、名称解析、更新、配置协议），后者是正面尝试口令或服务；路径选择与暴露面完全不同。
- **MITM vs 被动嗅探/端口镜像**: MITM 主动插入路径，能转发、修改与注入；镜像与被动嗅探只读，不改变流量。
- **DNS 缓存投毒 vs 同子网伪造响应**: 前者污染递归解析器、影响所有查询它的主机；后者要求与受害主机同子网，结果更一致但范围更小。
- **GRE vs 加密 VPN**: GRE 只做封装与路由牵引，通常不提供机密性；把它当隐蔽或加密通道会误判泄露风险。
- **Cisco Type5 vs Type7**: Type5 是加盐 MD5 单向哈希，只能字典/暴力；Type7 是可逆弱加密，可直接还原。先看配置关键字与数字再选工具。
