# 01 前端与浏览器端

这一层测的是「代码跑在用户浏览器里」的那部分：页面 DOM、前端打包产物、浏览器与插件本身。典型被测物是 H5/SPA 页面、CSP/CORS 响应头、postMessage 与端侧存储的使用点、老式 ActiveX/COM 控件。对象不是服务器，而是攻击者与用户之间的这层客户端。

## 这一层最常见的四类问题

- 输入被拼进 `innerHTML`、`document.write` 或 `location.hash`，没有任何上下文转义。
- `postMessage` 不校验 origin、CORS 反射任意来源、CSP 里带 `unsafe-inline`，跨窗口与跨域的口子开着。
- 令牌与敏感数据放在 localStorage / sessionStorage，登出后仍可读，XSS 一次就全拿走。
- 浏览器或插件自身的内存破坏（UAF、堆喷射）能被做成可控执行，或浏览器被控后的影响面没人评估过。

## 这一层的 skill

| skill | 作用 | 什么时候会用到 |
| --- | --- | --- |
| client-side-and-frontend-security | 审 DOM XSS、CSRF、点击劫持、postMessage、CORS/CSP、原型污染与端侧存储，按信任边界逐个执行点核对。 | 「页面把 location.hash 拼进 innerHTML 了」「postMessage 没验 origin 算不算问题」 |
| browser-heap-spray-and-uaf | 分析浏览器 UAF/堆溢出并做成可控执行，选堆喷射载体、处理 LFH 重占、伪造 vtable。 | 「这个 UAF 能不能打」「堆喷射占多大比例才稳」 |
| beef-client-side-attack | 用 BeEF 评估浏览器被控后的影响面，规划挂钩投递、指纹侦察与模块编排。 | 「浏览器被控之后攻击者能干什么」「演练怎么写钩子」 |
| activex-vulnerability-analysis | 评估 ActiveX/COM 控件能否被网页调用，枚举方法属性并测试内存与权限类问题。 | 「这个 CLSID 能不能被网页实例化」「控件是不是 safe for scripting」 |

## 跨层可复用

- input-validation-output-encoding（06_接口与协议）— 前端回显、模板渲染与属性上下文同样要按位置转义，规则是同一套。
- api-and-interface-security（06_接口与协议）— 前端把按钮藏起来不等于安全，接口的对象级校验要在这一层对着看。
- logic-and-isolation-bugs（99_跨层通用方法）— 浏览器沙盒逃逸与类型混淆不是内存破坏，要用它的判定模型。
- exploit-chain-construction（03_桌面与二进制程序）— 浏览器漏洞从原语到完整利用链的缺环体检。
- vuln-debugging-and-breakpoints（03_桌面与二进制程序）— 定位控件/插件崩溃时要下条件断点与记录断点。
- network-transport-and-session（09_网络与传输）— 前端拿到的 Cookie 是否 HttpOnly/Secure、会话是否可重放。

## 和相邻层的分界

- 与 06 接口：01 看「攻击者能不能在你的页面上下文里执行脚本」（DOM 执行点、跨窗口消息、端侧存储），06 看「请求本身的协议、认证与对象级校验」。同样是 XSS，落在服务端模板渲染归 06，落在浏览器 DOM 归 01。
- 与 03 桌面与二进制：浏览器内存破坏的调试与利用手法同 03，但被测对象是浏览器进程而不是一个 exe，所以放 01。
- 与 09 网络：01 不关心包怎么到、证书对不对，只看到了浏览器之后发生了什么。
