## 按被测对象怎么选

- 我在测一个 H5 页面 / 前端应用 → **01 + 06 + 13**（DOM 与端侧存储 → 它调的接口 → 是否留下可审计记录）
- 我在测一个 App，怀疑关键逻辑在 native 层 → **02 + 03 + 99**（分层调试与签名 → 逆向手法 → 机理判定与方法选型）
- 我拿到一个崩溃样本，还没有 PoC → **03 + 99**（下断点、定位根因、布堆/写利用 → 先判机理与选路线）
- 我在评审一份后端源码 → **04 + 05 + 07**（写法与资源 → 权限/状态机是否成立 → 敏感字段怎么存）
- 我在测一个 Web 业务系统（黑盒）→ **08 + 05 + 06 + 10 + 13**（先判容器 → 业务规则 → 接口报文 → 主机与运行环境 → 日志）
- 我只有一串抓包和 Swagger → **06 + 05**（协议、认证、对象级校验 → 金额/库存/次数等业务不变量）
- 我在做上线前安全复核 → **08 + 11 + 12 + 07 + 13**（站点配置 → 云与容器 → 依赖与产物 → 数据存储 → 日志审计）
- 我在查「内网老断网、网站跳转异常」 → **09 + 10 + 13**（二层/解析层欺骗 → 主机是否中招 → 日志是否被清）
- 我在查一台机器中招了 → **10 + 13 + 99**（处置顺序、隐藏账号 → 日志证据 → 样本分析）
- 我在评估供应链与交付 → **12 + 11 + 99**（依赖与产物 → 镜像与工作负载 → 门禁、台账与披露）

## 多义条目的判定

| skill | 两可之处 | 最终定类理由 |
| --- | --- | --- |
| android-malware-triage | 可归 02（App）或 99（样本） | 被测物是 APK 这个平台特定安装包，判恶意要看 Manifest/DEX/模拟器，归 02；通用的样本提取与解码技巧指向 99 的 malware-sample-analysis。 |
| log-integrity-and-evidence | 可归 10（主机应急）或 13（日志数据） | 它问的是「日志是否被清理、能否作为证据」，对象是日志这份数据，归 13；主机侧的清除与处置归 10。13 因此只有 2 个。 |
| kernel-exploitation | 可归 03（二进制利用）或 10（主机/系统） | 手法是内核态任意写、改 token、覆盖表项，属于二进制利用的执行层，归 03；主机加固与补丁策略归 10。 |
| windows-access-control-attack | 可归 03 或 10 | 分析对象是服务/注册表/目录的 ACL、SID 与令牌，属于二进制与权限对象的执行层，归 03。 |
| trust-boundary-mapping | 可归 04（源码）或 99（通用方法） | 它的产出落点是「哪一行开始可以信、在哪一层校验」，紧贴代码与调用链，归 04。 |
| buffer-overflow-defense-layering | 可归 03（利用）或 10（防御加固） | 前提是「已确认的溢出」，此时讨论的是缓解与补偿控制，与 03 的利用链同一上下文，归 03。 |
| arm-mobile-overflow | 名字像 03，内容像 02 | 对象是 Windows Mobile/CE 的 ARM 程序（随设备分发），归 02。 |
| network-protocol-fuzzing | 可归 06（协议）或 99（fuzz 方法） | 它的落点是 FTP/SMTP 这类具体协议服务与 WSARecv 回溯，不是方法选型，归 06。 |
| email-trust-boundary | 可归 09（钓鱼/身份）或 10（个人主机） | 判的是「这封邮件/附件能不能在本人机器上打开」，以及邮箱分层与找回，归 10。 |
| web-minimal-exposure | 可归 08 或 07（数据暴露） | 对象是站点与服务器根目录的暴露面（目录权限、库文件位置、上传目录可执行），归 08。 |
