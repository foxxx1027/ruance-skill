# 03 桌面与二进制程序

这一层测的是没有源码、跑在本机上的可执行体：PE/ELF、内核驱动、安装包、崩溃样本与利用代码。典型被测物是一个 exe/dll/sys、一段加壳的二进制、一个能稳定崩溃的 PoC、一份补丁前后的新旧版本。核心问题是这段机器码在做什么、哪里会坏、坏了能不能被我控制。

## 这一层最常见的四类问题

- 只有二进制没有符号，入口、main 和关键函数都找不到，IDA 里全是 `sub_XXXX`。
- 一附加调试器就退出、反汇编错乱，怀疑加壳或反调试，但不知道是哪一层保护。
- 崩溃能复现，却说不清崩在哪个函数、覆盖到返回地址要多少字节。
- EIP 可控了，却卡在 GS/SEHOP/DEP/ASLR 上，或者堆布局一直占不住。

## 这一层的 skill

| skill | 作用 | 什么时候会用到 |
| --- | --- | --- |
| reverse-engineering-workflow | 在没给交付物时先定逆向的目标、深度与起点，说明挖洞/分析/利用/防护各需要什么产物。 | 「逆向从哪开始」「要还原到什么程度才算够」 |
| reverse-engineering-tooling-and-collaboration | 选逆向工具链与协作方式：IDAPython 批量标注、共享 IDB、命名规范与 YARA 沉淀。 | 「多人一起逆同一份样本怎么协作」「批量样本怎么统一标注」 |
| cpp-semantic-recovery | 把无符号 x86 反汇编还原成 C++ 的数据类型、表达式、控制语句与函数栈帧。 | 「Release 版这段除法怎么变成乘法和移位了」 |
| locate-by-known-anchor | 用字符串、符号名、崩溃消息或格式规范当锚点，直接落到目标函数，跳过逐层回溯。 | 「只记得报错文本，怎么找到处理它的函数」 |
| anti-debugging-and-unpacking | 判壳判保护 → 处理反调试 → 找 OEP → dump 修复 → 定位真实入口。 | 「一附加调试器就退出，是不是加壳了」 |
| patch-diff-and-source-analysis | 从厂商补丁与新旧版本差异反推漏洞，含解包、BinDiff 分诊与符号失效后的降级验证。 | 「只有补丁没有公告，怎么反推出漏洞」 |
| vuln-debugging-and-breakpoints | 按观察对象选断点，用条件断点、记录断点、消息断点把程序停在触发前后。 | 「断点被淹没了，怎么只看我要的那一次」 |
| reverse-driver-and-unknown-structure | 从 ring3 DeviceIoControl 反推驱动分发例程，或用读写断点逐字段还原无文档内存结构。 | 「只有一个提权 PoC 的调用片段」「这个 `[eax+0x5c]` 是什么字段」 |
| exploit-chain-construction | 用触发→信息泄露→绕过→控流四段式做缺环体检，并选定控流落点。 | 「EIP 可控但一跳就崩，缺的是哪一环」 |
| heap-exploitation | 把堆溢出/UAF/双重释放做成可控写或控流，含占坑、虚表劫持与 Safe Unlink 绕路。 | 「这个 UAF 能不能打」「对象大小怎么量才准」 |
| heap-vulnerability-locating | 用页堆/堆尾检查与分配记录反查哪个堆块被写坏、由哪段代码分配。 | 「崩在 RtlpFreeHeap，不知道谁写坏的」 |
| win-stack-overflow-exploit | 从栈帧反推偏移、选跳板、布置填充/跳板/shellcode，并用大靶子换容错。 | 「覆盖到返回地址要多少字节」「jmp esp 在哪找」 |
| linux-x86-exploit-and-format-string | 32 位 Linux 上把栈溢出/格式化串做成可用 PoC，处理 SUID、canary、ASLR 与 ret2libc。 | 「格式化字符串怎么写成任意写」「有 canary 还能不能打」 |
| shellcode-engineering | 按交互需求定 bind/reverse/staged 等载荷形态，核对注入空间与坏字符后写机器码。 | 「只有 120 字节空间，payload 怎么写」 |
| windows-exploit-and-mitigation-bypass | 在 GS/SafeSEH/SEHOP/DEP/ASLR/EMET 下找覆盖缝隙，选 cookie、虚表、SEH 链或 Ret2Libc。 | 「开了 DEP 和 ASLR，旧 exp 全失效了」 |
| metasploit-module-development | 把自用 PoC 改写成可复用、可交付的 Metasploit 模块，补齐 Targets、Space 与 BadChars。 | 「怎么把这个 PoC 做成 MSF 模块」 |
| crash-to-root-cause | 从崩溃现场走回漏洞根因、漏洞函数与精确覆盖长度，含受控崩溃与增删对照。 | 「栈回溯全是垃圾值，根因在哪」 |
| windows-access-control-attack | 从普通用户枚举服务/注册表/目录/共享内存的 ACL，用 SID/令牌/DACL 分析找配置型提权。 | 「普通用户怎么靠权限配置提权」 |
| kernel-exploitation | 把内核任意写/UAF 提权做成可控执行，决定改 token 还是覆盖 HalDispatchTable。 | 「驱动有任意写，怎么提权到 System」 |
| buffer-overflow-defense-layering | 为已确认的溢出选防御与临时缓解，判断某条加固是否真的有效。 | 「补丁打不了，这个溢出怎么临时缓解」 |

## 跨层可复用

- vulnerability-mechanism-identification（99_跨层通用方法）— 拿到崩溃先归机理，才知道该走栈、堆还是类型混淆路线。
- fuzzing-strategy（99_跨层通用方法）— 挖洞前先在盲 fuzz、智能 fuzz 与静态审计之间选路，别把预算压在错的一条上。
- symbolic-execution（99_跨层通用方法）— 卡在比较条件上、想定向生成能到达危险分支的输入时用它。
- logic-and-isolation-bugs（99_跨层通用方法）— 竞争、类型混淆、沙盒逃逸不属于内存破坏，要用它的 Check/Use 与布局错配模型。
- pentest-engagement-and-disclosure（99_跨层通用方法）— 利用代码的授权边界、scope 与披露流程。
- memory-and-resource-safety（04_源码与代码实现）— 有源码时先按编码缺陷把溢出堵掉，比事后利用便宜得多。

## 和相邻层的分界

- 与 04 源码与代码实现：04 有源码，看的是「这一行代码写错了」；03 没有源码，看的是「这段机器码在运行时出了什么事」。
- 与 99 跨层通用方法：99 负责「该用哪种方法」的选型与止损，03 负责具体执行（下断点、找 OEP、布堆、写 shellcode）。
- 与 10 主机与操作系统：Windows ACL 提权分析手法是权限对象/令牌级别的，归 03；系统默认配置该不该开归 10。
