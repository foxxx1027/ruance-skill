# 11 云与容器

这一层测的是资产跑在别人的资源池里：云主机与对象存储、安全组与 IAM、容器与 Kubernetes 控制面，以及日志审计开关。典型被测物是一份 IAM 策略、一个公开的桶、一个以 root 运行的工作负载。关注点是暴露面是配出来的，核对方式是盘资产加对基线。

## 这一层最常见的四类问题

- 安全组把 22/3389/数据库端口开到 0.0.0.0/0，公网端口数量没人统计过。
- 对象存储桶公开可列，备份、导出文件与镜像仓库凭据裸奔。
- IAM 用通配 `*`，容器以 root 运行，K8s 匿名访问与默认 ServiceAccount 权限过大。
- 没有开审计日志，出事查不到谁在什么时候改了什么。

## 跨层可复用

- network-transport-and-session（09_网络与传输）— 云上入口的 TLS、证书与域名。
- supply-chain-and-dependency-security（12_构建产物与依赖）— 镜像里的组件清单与已知 CVE。
- middleware-fingerprint-and-triage（08_中间件与Web容器）— 工作负载前面那层容器的指纹与版本。
- web-minimal-exposure（08_中间件与Web容器）— 桶公开与站点目录暴露是同一类配置问题。
- log-integrity-and-evidence（13_日志与审计数据）— 云审计日志是否开启、是否可被改动。
- data-protection-and-secrets（07_数据库与数据存储）— 桶里数据的分级、加密与留存。
- recon-funnel-and-scoping（09_网络与传输）— 先摸清公网资产再谈基线。

## 和相邻层的分界

- 与 10 主机与操作系统：11 的对象是云资源与编排层（IAM、安全组、桶、K8s），10 的对象是单台机器的系统配置。同一台云主机，系统加固归 10，安全组与 IAM 归 11。
- 与 12 构建产物与依赖：11 看运行时的镜像与工作负载，12 看构建出来的依赖与交付产物。
- 与 08 中间件：11 管「容器怎么编排、权限给多大」，08 管「容器里的 Web 服务怎么配」。
