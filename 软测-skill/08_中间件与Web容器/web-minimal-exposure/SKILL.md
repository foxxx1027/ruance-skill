# 网站最小暴露与权限矩阵

## R — 原文 (Reading)

> "只开放服务端口成为目前很多服务器的流行做法，如WWW服务器只开放80，而将其他所有端口关闭或在防火墙上做阻止策略。"
>
> — 网络安全技术联盟 主编，第11章 11.4 网站系统的安全防护（PAGE 219）

---

## I — 方法论骨架 (Interpretation)

网站风险不是一个漏洞的强弱，而是两个乘数：外部能看见并到达多少入口，以及这些入口背后的权限有多宽。
暴露面包括端口、可访问目录、遗留旧文件与备份、数据库文件位置、详细错误回显、后台入口。
权限宽度包括 Web 根目录 ACL、上传目录是否可执行、数据库文件权限、应用池/服务账号能做什么。
两者相乘：入口多但权限只读且隔离，损失有限；入口少但 Everyone 可写，一次上传或注入就能穿透。
处置顺序是先收缩暴露面，再收窄权限，最后才是 WAF、清洗、监控等边界与外层手段。
权限矩阵要逐对象写清“谁、对什么、能做什么”：Web 根只读、上传目录可写不可执行、数据库移出 Web 根、应用账号最小权限、后台按来源与角色限制。
边界过滤与冗余恢复是补强：防火墙/WAF 降低噪声，备份与还原路径保证被篡改后能恢复。
持续验证把一次性整改变成基线：定期复测端口、目录、备份与数据库可达性，发现回退就修部署模板。
核心判断：如果 WAF 拦住了请求但数据库仍可被直接下载，风险并没有被修复。

## A1 — 书中的应用 (Past Application)

### 案例 1: NBSI 注入点扫描与数据库路径暴露（c24）

- **问题**: 作者要说明网站攻击如何从一条报错推进到取数据；演示站点的输入未做边界处理，且错误信息足够详细。
- **方法论的使用**: 先让浏览器显示友好的 HTTP 错误信息，借报错判断数据库类型与语法位置；再用 NBSI 扫描注入点，观察已解表名、列名与记录。这里检查的不是“某个漏洞能不能打”，而是暴露面（详细回显、可枚举入口）与权限（数据库文件位置、账号可读范围）如何叠加。
- **结论**: 详细回显 + 可控输入 + 元数据可得，构成一条可推进的链；同章的数据库路径扫描演示又说明，数据库文件若留在 Web 根且可被 HTTP 访问，甚至不需要注入就能被直接下载（PAGE 217）。反推的防御结论是：关详细错误、收敛输入边界、把数据库移出 Web 根并禁止下载、给数据库账号最小权限。
- **结果**: 扫描出注入点并枚举出库结构（PAGE 215–216）。这条攻击演示在防御侧对应的不是“再装一个扫描器”，而是把“可被看见的入口”和“可被利用的权限”同时收窄。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 自建网站或云服务器上线前/例行检查，想知道“只开 80、443 是否就够”，需要一份暴露面清单。
2. 发现站点可列目录、备份文件或数据库文件能被 URL 直接下载，或上传目录里的脚本能被访问执行。
3. 已经上了 WAF 或云防护，但仍担心数据库位置、目录 ACL、应用账号权限等结构性暴露。
4. 页面报错暴露数据库类型、表名、物理路径，或后台登录入口直接暴露在公网且没有来源限制。
5. 需要为 Web 根、上传目录、数据库目录、应用池账号和后台入口设计一张可核对的权限矩阵。

### 语言信号 (用户的话里出现这些就应激活)

- "网站安全怎么加固" / "网站只开 80 就够吗" / "暴露面太大"
- "数据库会不会被直接下载" / "备份文件能被下载" / "上传目录能执行脚本"
- "Web 根目录权限" / "要不要给 Everyone" / "应用账号最小权限"
- "WAF 能不能替代权限配置" / "后台入口要不要限制来源"
- "web exposure", "directory permissions", "database in webroot", "upload directory executable", "least privilege", "WAF vs permissions"

### 与相邻 skill 的区分

- 与 `middleware-misconfig-audit` / `middleware-fingerprint-and-triage` 的区别：本 skill 只处理应用层暴露面与文件/数据库权限；中间件版本、配置项、反序列化与已知漏洞匹配转 middleware-* 系列。
- 与 `host-default-surface-convergence` 的区别：本 skill 面向网站目录与数据库；主机账户、默认服务、共享与登录界面等默认值收敛转该 skill。
- 与 `data-backup-recovery-discipline` 的区别：本 skill 只要求把数据库/备份移出 Web 根并限权；备份周期、异机保存与还原演练转该 skill。
- 与 `identity-deception-detection` 的区别：伪造站点、钓鱼链接与证书判据不在本 skill 范围。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **盘点暴露面**
   - 完成标准: 逐项列出端口、可访问目录、旧文件/备份、数据库文件位置、错误回显、后台入口，每项都有实际证据（端口探测结果、URL 访问结果、目录列表或配置片段），而不是凭印象。
   - 判停条件: 若没有资产处置授权或处于生产变更窗口外，只做只读盘点与风险标注，不执行关闭端口、改 ACL 等变更。

2. **建立权限矩阵**
   - 完成标准: 对 Web 根、上传目录、数据库目录/文件、应用池账号、后台入口分别写清“主体—对象—允许动作—当前状态—目标状态”，并标出缺口。
   - 判停条件: 若业务确实需要写入，先把写入收敛到独立上传目录并禁止脚本执行；若数据库暂时不能移出 Web 根，先用 Web 服务器规则阻断其 HTTP 访问并记为临时补偿。

3. **收敛暴露面与权限**
   - 完成标准: 非业务端口关闭或阻断；旧文件、备份、测试页清理；详细错误回显关闭；数据库移出 Web 根；后台入口按来源/角色限制；Web 根只读、上传目录可写不可执行、应用账号最小权限。每项有变更记录与复测结果。
   - 判停条件: 若变更导致业务中断，按变更记录回滚并保留回滚前证据，不要把“配置改了一半”当成完成。

4. **补边界过滤与冗余恢复**
   - 完成标准: 防火墙/WAF/反向代理规则有明确目的与测试记录，同时确认它们没有替代第 3 步的权限收敛；数据库与站点具备可验证的备份和还原路径。
   - 判停条件: 若问题主要是带宽/连接耗尽型 DDoS，转到 DDoS 分层防御，不在本 skill 内承诺“彻底防住”。

5. **持续验证**
   - 完成标准: 建立端口、目录、备份/数据库可达性、错误回显与后台入口的定期复测；有告警责任人与复测周期；连续两次复测没有回退。
   - 判停条件: 若同一暴露面反复出现，修部署模板/发布流程与默认配置，而不是每次手工清理。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 纯中间件指纹、配置型漏洞、反序列化、已知 CVE 匹配：转 `middleware-*` 系列，本 skill 不替代中间件加固。
- 纯 DDoS 容量清洗与可用性架构：DDoS 不是本 skill 的核心；本 skill 只负责入口收敛，不承诺抗住流量攻击。
- 只要求修代码层 SQL 注入/上传漏洞：本 skill 给出结构性约束（关回显、最小权限、数据库移出根），但不能替代参数化查询、输入校验与代码修复。
- 没有授权或没有变更窗口的线上系统：不要直接改 ACL、移数据库或关端口，只做只读评估。

### 作者在书中警告的失败模式

- **Everyone 读取是反模式（ce08）**：为省事给网站目录 Everyone 读取，会把可访问主体扩大到匿名、本地账户与多数域账户；应用池身份已足够读取站点文件。
- **数据库留在 Web 根 + Everyone 修改/写入是更严重的反模式（ce09）**：Web 进程可写数据库后，注入、上传或任意文件写都能直接改库；数据库文件还可能被 HTTP 直接下载。
- **只关端口不等于修代码**：端口收敛只减少可达服务，不修复注入、上传、越权等应用缺陷；端口少了但目录可写、数据库可下载，风险仍在。
- **WAF 不能替代权限**：WAF 是边界过滤，挡不住“数据库文件放在 Web 根且匿名可下载”这类结构性暴露，也挡不住应用账号权限过宽。
- 把详细错误回显当成“方便调试”的默认配置，会把数据库类型、表名与路径直接交给攻击者。

### 作者的盲点 / 时代局限

- 书中以 2019 年的 IIS + ASP/Access 为主要场景，具体界面、默认值与 ACL 继承关系已变化；现代 Nginx/Apache、容器、云存储与 Serverless 需要重新映射对象。
- 书中把“读取和执行”作为 Web 根权限示例，但现代应用还需要考虑配置文件、密钥、日志目录、临时目录与上传目录的分离；不能只照抄一个权限项。
- 作者较少讨论 WAF/云防护的绕过、供应链依赖、配置即代码与发布流程；这些需要用现代工程手段补强。
- 书中的“网站安全”仍以单机服务器为中心，未覆盖多租户、对象存储直链、CDN 回源与数据库托管服务等暴露面。

### 容易混淆的邻近方法论

- `middleware-misconfig-audit`：都看配置，但该 skill 看中间件自身配置与已知风险；本 skill 看目录/数据库/账号权限与外部可达性。
- `middleware-fingerprint-and-triage`：用于识别中间件与版本；本 skill 不靠指纹判断，而靠暴露面与权限矩阵。
- DDoS 分层防御：只开端口是它的入口收敛层，但本 skill 的目标不是可用性抗压，而是减少可被利用的结构性暴露。
- `data-backup-recovery-discipline`：备份与还原是冗余恢复的通用方法；本 skill 只要求网站数据库/备份不暴露在 Web 根，并具备可验证的恢复路径。
