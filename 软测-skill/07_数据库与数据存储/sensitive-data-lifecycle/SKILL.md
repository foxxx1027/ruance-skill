# 敏感数据识别、加密与密钥管理

## R — 原文 (Reading)

> "即使在服务器端，仍然要加密存储敏感数据。……规定安全的密钥强度，仅使用高于规定强度的密钥。规定密钥有效期，禁止使用已经过期的密钥。禁止使用硬编码密钥，硬编码密钥将显著增加加密数据被攻击者破解的可能性。"
>
> — GB/T 38674-2020, 5.2.1 b)、5.2.1 i)

---

## I — 方法论骨架 (Interpretation)

这是一条自上而下的漏斗，每一层都是一次减少暴露面的机会，能砍掉的层越多越安全。

第一层是划范围。标准不给敏感数据分类清单，只说"明确范围以及有权访问这些数据的用户范围"——所以这一步必须自己产出字段级清单，并写清依据（法规要求、业务后果、是否属于凭据）。凭字段名判断（"只是昵称和头像"）是最常见的失误。

第二层是减量。能不留就不留；必须留就缩短时间、减少存放地点、只留在服务端。数据一旦落到客户端就当作已泄露来设计：前端状态、localStorage、隐藏字段、缓存、日志、错误页、注释、进程信息，全都算公开面。

第三层是加密。即使在服务器端也要加密存储，因为库被拖走是常态。加密要配三件事：算法与模式不能是被攻破的（清单由自己维护，标准没给）；密钥由管理流程下发，有强度下限与有效期，禁止写进源码或配置文件字面量；随机数必须来自密码学安全源，种子不能是时间、进程号这类可预测值。

第四层是失败与清理。加密模块报错就重做，绝不能以明文继续；资源释放前清除敏感内容；临时文件与缓存副本短存快删；同时保留备份可恢复能力，否则"删得干净"会变成"丢得彻底"。

口令是这条漏斗最典型的实例：不明文存、不明文传、只存加盐的单向散列值。它同时受本 skill 的存储约束与鉴别 skill 的校验流程约束，两边都要满足。

## A1 — 书中的应用 (Past Application)

### 案例 1: 用通用伪随机数生成安全令牌（附录 A.2.2.1.2）

- **问题**: 用固定种子的通用随机类生成令牌、密钥一类安全敏感数值。
- **方法论的使用**: 走漏斗第三层——这类值属于敏感数据，其安全性完全依赖不可预测性；通用伪随机数由种子决定，线性同余序列可移植可重复，相同种子在任何实现上给出同一序列，种子又常取自系统时钟。判断依据不是"调用了随机函数"，而是"攻击者观察到少量输出后能否反推出下一个值"。
- **结论**: 凡安全相关（会话标识、重置令牌、盐、密钥）一律换密码学安全随机源；非安全场景才允许用普通随机类。
- **结果（防住什么）**: 不修时令牌可被预测或建表穷举，直接导致会话劫持与口令重置接管；换源后序列不可由外部推断。

### 案例 2: 直接用网络传来的明文口令连接数据库（附录 A.2.3.2.4）

- **问题**: 从请求参数取出明文口令，直接作为数据库连接凭据；相邻示例还有空口令与 null 口令直连。
- **方法论的使用**: 同时踩了漏斗的两层——凭据属于敏感数据却没有减量（它本不该来自用户请求，也不该以明文存在），也没有加密与配置化管理（应来自配置文件中的密文并在可信环境解密）。此外口令在链路与日志中暴露，属于"泄露面未封堵"。
- **结论**: 连接凭据只能来自受保护的配置或密钥管理，空口令与 null 口令必须直接拒绝；用户口令永远不参与建立数据库连接。
- **结果（防住什么）**: 不修时抓包或读到配置即失守，数据库凭据泄露；改造后传输与存储中均为密文，空/null 凭据无法建立连接。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 新系统定数据模型，需要回答"哪些字段要加密、加哪些、密钥怎么管"。
2. 埋点或日志里出现了用户画像、手机号、身份证、地址，团队说"只是昵称和头像，不用脱敏"。
3. 代码评审发现密钥、数据库口令、第三方 token 以字面量写在源码或配置里，或者被提交进了仓库。
4. 安全评审只问了"有没有加密"，没人看算法、模式、IV、盐与密钥派生。
5. 设计口令重置令牌、邀请链接、一次性下载链接，需要决定用什么随机源、存多久、能否落库明文。

### 语言信号 (用户的话里出现这些就应激活)

- "这个字段算敏感数据吗 / 要不要脱敏"（is this PII / do we need masking）
- "密钥放哪 / 能不能写在配置里"（where to store the key / hardcoded key）
- "我们用的 AES 够不够 / ECB 有问题吗"（is AES-ECB safe / which mode）
- "日志里能带手机号吗 / 埋点能不能上报"（can we log this field）
- "安全随机数 / SecureRandom / 加盐散列 / key rotation / data minimization"

### 与相邻 skill 的区分

- 与 `authorization-and-least-privilege` 的区别：本 skill 管"数据该不该存在、以什么形态存在"，后者管"谁能读它"；加密不能替代访问控制，反之亦然。
- 与 `authentication-and-passwords` 的区别：口令的存储形态（加盐单向散列）两边都会提到，本 skill 从数据生命周期切入，后者从鉴别流程切入。
- 与 `logging-security` 的区别：日志脱敏的字段清单来自本 skill 的敏感范围，但"记什么、防注入、保完整性"归日志 skill。

## E — 可执行步骤 (Execution)

1. **自划敏感数据清单与访问者范围**
   - 完成标准: 产出字段级清单，每项写明判定依据（法规、凭据、业务后果）与"谁有权访问"；覆盖口令、令牌、密钥、证件号、联系方式、地址、生物特征、财务与健康数据。
   - 判停条件: 若某字段判不准，一律先按敏感处理并进入步骤 2，不得因"看起来无害"而跳过。

2. **逐字段走减量漏斗**
   - 完成标准: 每个字段有"保留理由 + 保留期限 + 存放地点数"三栏；无保留理由的被删除或改为哈希/截断/派生值；能只在服务端的不下发客户端。
   - 判停条件: 若某字段必须下发到客户端才能实现业务，跳到步骤 4 先封堵客户端与日志泄露面，再回来定加密方案。

3. **确定加密方案与密钥管理**
   - 完成标准: 服务端存储也加密；算法与模式不在已知被攻破之列（禁用 ECB 与弱散列做完整性）；密钥来源是管理流程而非源码字面量，有强度下限与有效期，含轮换路径；安全相关随机值全部来自密码学安全源。
   - 判停条件: 若密钥只能硬编码进客户端产物，说明该数据不应存在于客户端，回到步骤 2 重新减量。

4. **封堵全部泄露面**
   - 完成标准: 日志、错误消息、调试信息、源码注释、进程信息、客户端存储、缓存与临时副本，逐项有"是否含敏感字段 + 脱敏规则"的结论；以"客户端与日志完全公开"为假设复核一遍仍不泄露。加密失败的分支是重新加密或终止，不是明文继续。

5. **定义清理与恢复**
   - 完成标准: 资源释放前清除敏感内容；临时文件最短存活并即删；缓存与临时拷贝有失效策略；备份可恢复且备份本身受同等保护。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 判定"这个用户能不能读这条记录"：属于授权问题，加密只保护静态存储，不解决运行时的越权读取。
- 设计 TLS 参数、证书校验、会话标识的生成与轮换：属于传输与会话范畴，加密原语只是其中一部分。
- 处理输入校验、输出编码、注入防护：与数据形态无关，走编码类 skill。
- 只是"想给字段加个 AES"却还没做减量：先做步骤 2，否则是在给不必要保留的数据加锁，暴露面并未缩小。

### 作者在书中警告的失败模式

- **ce03 硬编码密钥与凭据**：密钥进源码就等于进了每个开发者的机器、每次构建产物和每份反编译结果；轮换还得重新发版，现实中于是永不轮换，泄露窗口被无限拉长，加密退化为"有密文无秘密"。
- **ce04 用被攻破的算法或 ECB 充当加密**：MD5/SHA-1 已有实用碰撞，完整性校验可被保持摘要不变地替换内容；ECB 对相同明文块产生相同密文块，攻击者无需解密即可识别结构、重排拼接密文，且这类代码"看起来加密了"，反而不会被评审当作缺陷。
- **ce05 用非密码学随机数生成令牌**：输出由种子决定，观察少量样本即可反推内部状态并预测下一个令牌；即使不能反推，空间太小也可被枚举，直接导致会话劫持或重置接管。
- **ce13 依赖垃圾回收与退出钩子做清理**：清理时机不确定，异常终止时临时文件与敏感副本会残留，可预测文件名还会把残留变成信息泄露。

### 作者的盲点 / 时代局限

- 标准只要求"安全算法与足够长度"，不给禁用清单，也没有口令密钥派生（bcrypt/scrypt/Argon2 的成本因子）、IV 与 nonce 复用、GCM 误用、后量子迁移的约束。形式审查因此很容易放过"用了加密但仍然可破"的实现，禁用清单必须自己维护。
- 没有任何数据分级方法。"自行划定敏感范围"在缺少方法论时退化为凭经验拍字段名，跨团队口径不一致；实际落地需要引入数据分类分级制度与字段字典，而不能只依赖本条的自觉。

### 容易混淆的邻近方法论

- 授权与最小权限：一个管"数据能不能被看见"，一个管"看见后能不能用"，两者互为补充，常有团队用加密冒充访问控制。
- 鉴别与口令安全：口令既是本 skill 的敏感数据实例，也是鉴别流程的输入，需两套规则同时满足。
