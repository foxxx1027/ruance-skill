# 数据安全与隐私：从分级到密钥的工程核查

## R — 原文 (Reading)

> 传输加密：HTTPS、TLS 配置
>
> 存储加密：数据库、文件、备份
>
> 敏感信息泄露：日志、报错、前端源码、接口返回
>
> 密钥硬编码、密钥管理、脱敏与隐私合规
>
> — 用户，《漏洞筛查覆盖框架》第 5 类「数据安全与隐私」，2026-10-19

## I — 方法论骨架 (Interpretation)

1. **先看数据本身，而不是先看配置。** 任何加密与脱敏判断都依赖“这是什么数据、值多少、谁能碰”。第一步必须产出数据分类分级清单：字段/文件/备份分别属于哪一级，依据是业务定义还是监管口径。没有这张表，后面的 TLS、加密、脱敏都只是在检查技术动作，无法判断保护是否与数据价值匹配。这是设计层的起点，也是后续所有证据的坐标。

2. **再判传输面是否全程受保护。** 传输问题的判据不是“有没有 HTTPS”，而是：所有承载敏感数据的入口、跳转、回调、内部服务调用是否都走受信通道；证书是否有效、是否覆盖实际域名、是否使用过期或自签证书；是否存在 HTTP 明文入口、混合内容或 TLS 降级。TLS 版本与套件属于配置问题，证书链与域名覆盖属于部署问题，而“敏感数据经第三方明文中转”属于设计缺陷，三者要分开记录。

3. **再看存储面是否按数据级别加密。** 分别核查数据库、对象存储、文件系统、备份介质与缓存：静态加密是否启用、密钥由谁持有、快照与备份是否继承加密、临时文件与导出文件是否落在未加密路径。这里最容易把“云厂商默认加密”误当成“业务已做密钥隔离”，也容易漏掉备份、只读副本、分析库和离线导出这些边缘副本。

4. **然后系统排查泄露面。** 泄露面不是一个点，而是五条通道：日志、错误页与堆栈、前端源码与构建产物、接口返回与调试字段、监控与第三方上报。检查顺序应先看“正常请求会留下什么”，再看“异常请求会多返回什么”，最后看“构建与发布流程把什么带进了客户端”。日志与报错通常属于实现缺陷，前端打包带入配置属于构建配置问题，接口过度返回则可能是设计或实现缺陷。

5. **单独评估密钥与访问控制。** 密钥问题要同时看硬编码、配置文件、环境变量、CI/CD 变量、镜像层、Git 历史与前端产物；再看向上权限：谁可读、谁可改、是否共享、是否可轮换、轮换后旧密钥是否失效。硬编码属于实现缺陷；密钥长期不轮换、权限过宽、无审计属于设计或流程缺陷。只做一次字符串搜索不足以证明密钥管理合格。

6. **最后核对脱敏与留存。** 脱敏要看展示、导出、日志、测试数据和客服/运维后台是否一致；留存要看采集目的是否明确、保存期限、删除与归档路径、备份中的残留。隐私合规条款只作为判据来源，不能替代技术证据。常见误判是把“页面上打了星号”当成已脱敏，而接口仍返回完整值，或导出文件仍是明文。

7. **用“设计—实现—配置”三分法收敛结论。** 设计缺陷需要改数据流或权限模型；实现缺陷需要改代码；配置问题可以快速加固但仍需回归。把三者混在一张“高危清单”里，会导致修复建议无法落地。每个发现都应标注类型、影响的数据级别、证据位置与验证方式。

8. **验证要遵循最小暴露原则。** 优先只读核验：证书链、响应头、配置导出、代码检索、样例日志。需要主动验证时，只用自有测试账号与合成数据，在授权范围内做最小对照实验，例如同一接口在脱敏前后的返回差异；不得拉取真实个人信息、不得把真实密钥写入报告。无法在授权范围内验证的项，明确标为“未验证假设”，而不是直接定性。

## A1 — 书中的应用 (Past Application)

> 本 skill 为工程清单型，没有单一书籍案例；以下为公开标准条款映射，不虚构事件细节。

### 标准映射 1: OWASP A02:2021 Cryptographic Failures

- **条款**: OWASP A02:2021 Cryptographic Failures。
- **对应检查**: 敏感数据在传输或静态存储中未加密、使用弱算法或弱随机数、证书校验被关闭、密钥与数据放在同一位置，导致数据在链路或介质被读取后直接可用。
- **落到本 skill**: 用第 2 步建传输矩阵并核验证书与 TLS 配置，用第 3 步建存储加密矩阵并记录密钥归属；产出证书链与配置证据、加密启用状态与密钥持有方清单，未启用或归属不清的项列为待修。

### 标准映射 2: CWE-798 Use of Hard-coded Credentials

- **条款**: CWE-798 Use of Hard-coded Credentials。
- **对应检查**: 数据库口令、云访问密钥、API Token、加密密钥被写入源码、配置文件、镜像层或前端构建产物，且随代码仓库扩散。
- **落到本 skill**: 用第 5 步检索代码、配置、Git 历史、镜像层与前端产物，建立“密钥位置—权限—轮换状态”表；产出脱敏后的位置清单与轮换/失效建议，报告中不出现完整密钥值。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

- 上线前做数据安全评审，需要确认敏感字段在传输、数据库、备份和导出文件中是否都被保护。
- 看到日志平台里出现完整手机号、身份证号、银行卡号或会话令牌，想系统排查还有哪些通道在泄露。
- 安全扫描或人工审查发现前端打包文件、Git 历史或容器镜像里出现云密钥、数据库口令。
- 准备做等保、隐私合规或客户安全问卷，需要把数据分类、加密、脱敏、留存逐项落到证据。
- 怀疑 TLS 配置有问题：证书过期、域名不匹配、仍有 HTTP 明文入口、内部调用走明文。
- 接手一套系统，想先摸清“哪些数据是敏感的、存在哪里、谁能访问、备份是否加密”。

### 语言信号 (用户的话里出现这些就应激活)

- “日志里把用户手机号全打出来了”
- “前端源码里好像有密钥”
- “数据库是明文存的，要不要加密”
- “备份文件有没有加密”
- “证书好像过期了/域名对不上”
- “接口返回的字段太多了，身份证没脱敏”
- “密钥多久轮换一次，谁能拿到”
- “导出 Excel 里是完整信息”
- “这套系统过了等保吗，数据分级怎么做”
- “测试环境用的是生产数据”
- 英文关键词：TLS misconfiguration、hard-coded secret、sensitive data exposure、encryption at rest、data masking。

### 与相邻 skill 的区分

- 与 `supply-chain-and-dependency-security`：如果泄露来自第三方依赖、镜像层或构建产物中的依赖包，先走供应链 skill 查来源与完整性；如果密钥是本方代码/配置写入并被业务使用，走本 skill 管分类、位置与轮换。
- 与 `cloud-and-container-baseline`：对象存储公开、IAM 过宽、安全组放行属于云基线问题，走该 skill；桶里到底是什么数据、是否加密、是否该脱敏，走本 skill。
- 与 `appsec-tooling-and-threat-modeling`：需要选型、编排 secret scanning/SAST 并做误报分诊时走该 skill；已经拿到命中结果，要判断数据级别、泄露通道与修复口径时走本 skill。
- 与 `data-backup-recovery-discipline`：关心“备份能不能还原、恢复演练是否成功”走该 skill；关心“备份是否加密、谁能读、保留多久、是否含超范围数据”走本 skill。
- 与 `log-integrity-and-evidence`：关心日志是否被篡改、证据链是否完整走该 skill；关心日志内容是否写入敏感数据、是否该脱敏走本 skill。
- 与 `web-minimal-exposure`：关心 Web 根目录、备份文件、源码包是否可被直接下载走该 skill；关心被下载内容里是否含密钥与个人信息走本 skill。
- 与 `client-side-and-frontend-security`：localStorage/sessionStorage 的存取与 XSS 风险走该 skill；前端构建产物、接口返回中的敏感字段与脱敏策略走本 skill。

## E — 可执行步骤 (Execution)

1. **建数据资产与分类分级清单**
   - 动作: 按业务域列出数据库表/字段、对象存储桶、文件共享、备份、导出与日志主题；为每项标注数据级别（公开/内部/敏感/高敏感）、责任人和所在系统，依据业务定义与适用监管口径，不凭字段名猜测。
   - 完成标准: 清单覆盖主要业务链路，敏感字段有明确级别与责任人，空项标注“待确认”。
   - 判停条件: 无法获得数据字典或业务归属时，停止定级，先输出待确认清单，不以猜测继续。

2. **建传输面矩阵**
   - 动作: 收集域名、端口、回调地址、内部服务调用与第三方集成点；标注协议、证书、终止点（网关/负载均衡/应用）与是否承载敏感数据。
   - 完成标准: 每个敏感数据入口都有协议与证书状态，明文入口单独列出。
   - 判停条件: 无，继续。

3. **只读核验证书与 TLS 配置（仅在授权范围内）**
   - 动作: 对清单内入口做被动与只读检查：证书有效期、颁发者、域名覆盖、证书链、协议版本与套件、是否强制跳转、是否存在混合内容；不进行降级攻击或暴力探测。
   - 完成标准: 每个入口有“正常/异常/未验证”结论与证据截图或命令输出；异常项标注影响范围。
   - 判停条件: 目标不属于授权资产或探测可能影响生产时，停止主动检查，改为索取配置导出。

4. **建存储加密矩阵**
   - 动作: 对数据库、对象存储、文件系统、缓存、快照与备份逐项确认是否启用静态加密、算法、密钥归属（平台托管/自管/KMS）、密钥权限与轮换方式；核对临时目录与导出路径。
   - 完成标准: 每类存储有加密状态、密钥归属与证据来源；备份与只读副本不被遗漏。
   - 判停条件: 云账号无只读审计权限时，停止自行核查，改为要求提供配置截图与密钥策略文档。

5. **排查五类泄露通道**
   - 动作: 依次检查日志样例、错误页与堆栈、前端源码与 source map、接口响应字段、监控/第三方上报；用合成测试数据触发正常与异常路径，记录敏感字段出现位置与完整度。
   - 完成标准: 每条通道有“是否泄露、泄露字段、触发条件、证据位置”四列；正常路径与异常路径分别记录。
   - 判停条件: 若验证需要写入真实个人信息或访问生产日志全量，立即停止，改用脱敏样例与代码检索。

6. **检索并评估密钥与访问控制**
   - 动作: 在代码、配置、CI/CD 变量定义、镜像层、Git 历史与前端产物中检索密钥模式；对每个命中确认是否有效、用途、持有者、权限范围、轮换周期与失效机制；只记录脱敏指纹。
   - 完成标准: 产出“密钥位置—用途—权限—轮换—是否已失效”表；无法确认有效性的标注为待验证。
   - 判停条件: 发现有效高权限密钥时，停止扩散性检索，先按授权流程通知负责人并建议立即轮换。

7. **做最小对照实验（仅在授权范围内）**
   - 动作: 用自有测试账号与合成数据，对比同一数据在接口、页面、导出、日志中的呈现差异；对比脱敏配置开启前后的行为；不批量拉取、不遍历他人数据。
   - 完成标准: 每个实验有假设、输入、预期、实际与结论；能区分“仅前端遮挡”和“服务端已脱敏”。
   - 判停条件: 实验可能触达真实用户数据或影响生产稳定性时，停止并改为代码/配置审查。

8. **核对脱敏与留存策略**
   - 动作: 对展示、导出、日志、测试数据、客服与运维后台逐项确认脱敏规则是否一致；核对采集目的、保存期限、删除/归档路径及备份中的残留周期。
   - 完成标准: 每类数据有脱敏规则与留存期限，规则冲突处单独列出。
   - 判停条件: 无，继续。

9. **归并证据并分级**
   - 动作: 将发现按“设计缺陷/实现缺陷/配置问题”分类，标注影响数据级别、可利用条件、证据位置与修复成本；去重后形成风险清单。
   - 完成标准: 每条发现只有一个主类型、一个数据级别和一个可复现证据；无证据项进入“未验证假设”。
   - 判停条件: 无法区分类型时，停止定级，补充证据后再归类。

10. **给出修复建议与复测口径**
   - 动作: 针对每类问题给出最小修复动作（改数据流、改代码、改配置）、责任方与复测方法；明确复测所需证据与通过标准，密钥类问题附轮换与失效验证。
   - 完成标准: 修复建议可直接分派，复测口径可被第三方复核；报告中不含完整密钥与真实个人信息。
   - 判停条件: 无，继续。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 目标只是确认备份能否成功还原、恢复演练是否达标，应走 `data-backup-recovery-discipline`。
- 目标只是判断日志是否被删除、篡改或证据链是否完整，应走 `log-integrity-and-evidence`。
- 目标只是确认 Web 根目录、源码包、备份文件是否可被直接下载，应走 `web-minimal-exposure`。
- 目标只是前端 localStorage/sessionStorage 的存取安全与 XSS 影响，应走 `client-side-and-frontend-security`。
- 目标只是对象存储桶是否公开、IAM 是否过宽、安全组是否放行，应走 `cloud-and-container-baseline`。
- 未取得授权时，不得对生产系统做主动探测、密钥有效性验证或数据导出实验。

### 作者在书中警告的失败模式

- 本清单未覆盖“以合规勾选代替技术验证”的做法：有加密声明不等于数据实际加密，有脱敏页面不等于接口已脱敏。
- 本清单未覆盖“只查一个点就下结论”的失败：只搜代码里的密钥、只看 HTTPS 首页、只看一张日志表，都会漏掉备份、导出、内部调用与构建产物。
- 本清单未覆盖“把密钥写进工单、截图或报告”的二次泄露；证据必须脱敏并限制流转。
- 本清单未覆盖“用真实个人信息做验证”的违规风险；验证应使用合成数据与自有账号。

### 作者的盲点 / 时代局限

- 本清单基于通用 Web 与云上系统，对离线介质、嵌入式设备、大型机与行业专网的加密与密钥体系覆盖不足。
- 本清单未展开各国隐私法规的具体条款差异，合规判断需由法务或合规团队确认。
- 本清单未覆盖同态加密、机密计算、字段级加密插件等特定实现的强度评估，只做“是否启用、密钥归谁、权限如何”的工程核对。
- 本清单不提供密码学算法选型与协议形式化验证，弱算法判断应引用组织基线或标准建议。

### 容易混淆的邻近方法论

- 数据备份恢复演练（`data-backup-recovery-discipline`）：关注可还原性，不关注加密与最小化。
- 日志完整性与证据保全（`log-integrity-and-evidence`）：关注不可篡改与取证链，不关注日志内容脱敏。
- Web 暴露面收敛（`web-minimal-exposure`）：关注“能不能被拿到”，不关注“拿到后是否可用”。
- 前端安全（`client-side-and-frontend-security`）：关注浏览器侧存储与执行风险，不关注服务端数据分级与留存。
- 云基线（`cloud-and-container-baseline`）：关注平台配置是否符合基线，不关注业务数据分类与脱敏规则。
