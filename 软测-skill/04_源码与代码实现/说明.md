# 04 源码与代码实现

这一层测的是「代码本身写得对不对」：一份可读的源码、一个类的封装、一段多线程逻辑、一处资源释放。典型被测物是业务源码仓库、SDK/公共库、领域对象与金额权限字段、线程池与锁的使用点，以及解析/解压这类资源消耗点。与 03 最大的区别是这里有源码，问题能指到具体某一行、某个函数。

## 这一层最常见的四类问题

- 外部输入一路流到危险操作，中间没有任何净化或参数化，靠上游「应该校验过了」。
- 类的内部状态被 getter 直接暴露，或者校验完成后对象又被改掉（TOCTOU）。
- 金额/计数在并发下错乱、锁没包住临界区，压测时偶发超发。
- 内存、句柄、连接在某条异常分支上没有释放，或者一次解压把资源吃光。

## 这一层的 skill

| skill | 作用 | 什么时候会用到 |
| --- | --- | --- |
| source-and-binary-static-audit | 审源码找漏洞，也在剥离二进制里定位 main、恢复结构体并用 IDAPython 写审计脚本。 | 「这份源码该从哪些输入点开始审」 |
| taint-analysis | 定义污点源、传播规则、sink 与净化函数，判断不可信输入能否到达危险操作。 | 「扫描器报的这条污点流是真的吗」 |
| dataflow-analysis-and-code-modeling | 建 CFG/SSA/调用图/PDG，用数据流方程迭代到不动点，解释可达性与误报。 | 「这个变量到底能不能流到那个 sink」 |
| program-analysis-technique-selection | 在数据流、污点、符号执行、模糊测试之间决定先做什么、怎么组合、预算怎么分。 | 「静态还是动态，时间和人力该怎么分」 |
| object-design-immutability | 审类的封装与不可变性、防御性复制，防止内部状态被外部改掉或序列化时泄露。 | 「外部能不能改到这个类的内部状态」 |
| concurrency-safety | 排查偶发超发、计数错乱、死锁、线程池打满与锁的粒度问题。 | 「压测时偶发超发，是不是竞态」 |
| function-and-exception-safety | 审公共函数/SDK 的参数校验、返回值检查、格式化字符串与异常路径的信息量。 | 「这个公共函数要不要再校验一次参数」 |
| memory-and-resource-safety | 审内存、缓冲区、句柄、连接、线程的释放时机，以及解压解析导致的资源耗尽。 | 「这条异常分支会不会漏掉释放」 |
| trust-boundary-mapping | 判断一个值从哪一行开始可以信，划清入口、消息队列、第三方回调与微服务的边界。 | 「上游已经校验过了，我这里还要不要验」 |

## 跨层可复用

- input-validation-output-encoding（06_接口与协议）— 04 负责定位拼接点，具体怎么转义、怎么参数化由它给规则。
- access-control-and-idor（05_后端业务逻辑与权限）— 源码里缺失的权限判断，最终表现为越权，两边要对着看。
- business-logic-and-race-security（05_后端业务逻辑与权限）— 同一处并发，在代码层是锁的问题，在业务层是金额/库存不变量。
- appsec-tooling-and-threat-modeling（99_跨层通用方法）— 决定 SAST、人工审计与 DAST 怎么配比，避免只堆工具。
- vulnerability-mechanism-identification（99_跨层通用方法）— 把可疑代码归到正确机理，才写得清成因链。
- sensitive-data-lifecycle（07_数据库与数据存储）— 代码里出现的敏感字段该如何加密、脱敏与最小化。

## 和相邻层的分界

- 与 06 接口与协议：04 看「代码怎么写」，06 看「接口暴露出去后怎么被打」。同一个 SQL 注入，写法根因在 04，可验证的攻击面在 06。
- 与 05 后端业务：04 的并发问题落在锁、可见性与资源；05 的并发问题落在金额、库存、次数这些业务不变量。
- 与 03 二进制：04 的产出是一条代码修改或一份审计结论，03 的产出是逆向结论或一份 exploit。
