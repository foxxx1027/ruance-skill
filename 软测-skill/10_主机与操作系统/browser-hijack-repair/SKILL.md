# 浏览器劫持的症状—键位修复

## R — 原文 (Reading)

> "右键快捷菜单被添加非法网站链接。右键弹出快捷菜单功能被禁用。"（PAGE 140，第8章 8.1 常见浏览器的攻击方式）
>
> — 网络安全技术联盟 主编, 第8章 8.1

## I — 方法论骨架 (Interpretation)

这个方法论把“浏览器坏了”拆成可核对的三件事：症状、写入点、写入源。
先确认是哪一类表现——主页、标题栏、右键菜单、源菜单、首页按钮、桌面图标；不同症状对应不同注册表位置，不能用一个“重置”通吃。
再判断这些位置是被谁写的：正常插件或主题、用户自己的设置，还是恶意程序、计划任务、快捷方式参数在周期性回写。
顺序上必须先清源再修复：源还在，改回键值只会被再次覆盖；源不清就反复修，等于和写入程序赛跑。
修复时先展开子项、确认指向与用途，再删除键项和它引用的文件，避免误删正常右键功能或业务插件。
修复后做加固，但加固是“按需”而不是“拉满”：安全级别、SmartScreen、弹窗拦截要兼顾可用性。
最后处理隐私痕迹：表单、历史、Cookie、保存的密码都可能把凭据留在本机。
一句话：症状定位写入点，写入点追问写入源，先断源、再修键、后加固、清痕迹。

## A1 — 书中的应用 (Past Application)

### 案例 1: 右键菜单被添加非法网站链接

- **问题**: 浏览器右键快捷菜单中多出非法网站链接，用户并未主动安装对应功能（PAGE 140）。
- **方法论的使用**: 按“右键菜单”这一症状定位到 `HKEY_CURRENT_USER\Software\Microsoft\Internet Explorer\MenuExt`，展开可疑项，确认它指向一个 HTML 文件，判断这是外部写入而非正常插件。
- **结论**: 只删除注册表项不够，对应的 HTML 文件还在就仍可能被重新挂回；键项与引用文件要一起清除。
- **结果**: 删除 MenuExt 中的非法项及对应 HTML 文件后，右键菜单恢复正常（PAGE 140–141）。

### 案例 2: 右键快捷菜单功能被完全禁用

- **问题**: 在 IE 中单击鼠标右键无反应，右键弹出菜单功能被禁用（PAGE 140）。
- **方法论的使用**: 不把“右键失效”当成浏览器故障，而是继续检查 `Restrictions` 相关键值，寻找禁用右键的写入点。
- **结论**: “菜单多出链接”和“菜单被禁用”是两类不同症状，键位不同，不能都用删除 MenuExt 项来解决。
- **结果**: 书中对这一分支只给出继续检查 Restrictions 的定位路径，未单列恢复结果；实际处置仍需在确认键值后恢复被禁用项（PAGE 141）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 主页被改成某导航站，在浏览器设置里改回后，过一会儿又变回去。
2. 浏览器标题栏被追加推广文字或陌生网址，关闭标签页后仍然出现。
3. 右键菜单多出陌生站点链接，或单击右键完全无反应，“查看源文件”菜单消失。
4. 首页按钮被替换、点击后跳转到陌生站，桌面出现指向网页的快捷方式图标。
5. 在公用或多人共用电脑上，需要清理表单、历史、Cookie 和保存的密码后再交还。

### 语言信号 (用户的话里出现这些就应激活)

- “主页被劫持了” / “主页改不回来” / “浏览器被篡改”
- “右键菜单多了个网站” / “右键没反应” / “查看源文件不见了”
- “标题栏一直弹广告” / “首页按钮跳错地方”
- “browser hijacker” / “homepage keeps changing” / “right-click menu hijacked”
- “browser redirect” / “reset browser didn't work”

### 与相邻 skill 的区分

- 与 `malware-triage-order` 的区别: 后者从已确认的恶意样本出发做完整处置；本 skill 从“浏览器配置被改”的症状出发定位键位，查杀只是前置的清源步骤。
- 与 `identity-deception-detection` 的区别: 后者判断页面、证书、域名是否在冒充；本 skill 不判断站点真假，只修本地被改的配置点。
- 与 `host-default-surface-convergence` 的区别: 后者收敛主机级默认攻击面（账户、共享、远程入口）；本 skill 只覆盖浏览器及其快捷方式、右键菜单等可写配置。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行:

1. **认症状并记录复发行为**
   - 完成标准: 得到一份症状清单，标明属于六类中的哪几类、出现频率、是否“改回后又复发”，并记录浏览器名称与版本、是否做过重置。

2. **按症状定位可写配置点**
   - 完成标准: 每个症状都对应到一个具体键位或配置项（主页键、MenuExt、Restrictions、快捷方式目标参数、启动项、扩展列表、策略页），并区分“浏览器内置设置”与“外部写入源”。
   - 判停条件: 若发现可疑程序、计划任务或扩展正在周期性写入，先跳到步骤 3，不要只改键值。

3. **先清源**
   - 完成标准: 全盘查杀完成，可疑扩展、计划任务、启动项被禁用或删除，快捷方式参数被解除；重启后症状不再自行出现。
   - 判停条件: 若无法确认写入源（例如域策略、家长控制或企业安全软件下发），停止手工修改，转交策略管理员确认。

4. **修复键位与引用文件**
   - 完成标准: 主页、MenuExt、Restrictions 等被改项已改回或删除；删除前已展开子项确认指向与用途，并同步删除对应 HTML/脚本文件；六类症状逐项复验恢复，正常功能未被误删。
   - 判停条件: 若某项无法判断是正常插件还是劫持项，先备份该键项与文件再处置，不要直接删除。

5. **按需加固并清理隐私痕迹**
   - 完成标准: 安全区域、SmartScreen、弹窗拦截等加固项与业务可用性兼容，未盲目调到最高；表单与密码自动完成已关闭，历史、Cookie、保存的密码已按场景清理，浏览器已更新到受支持版本。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 症状由域策略、组策略、家长控制或企业安全软件统一下发：手改会被回写，应由策略管理员处理，本 skill 的键位修复不适用于受管终端。
- 已确认主机被远控、木马或挖矿程序长期驻留：先按 `malware-triage-order` 做恶意代码处置，本 skill 只负责浏览器配置修复。
- 页面本身是钓鱼站、证书异常或域名冒充：转 `identity-deception-detection`，不要用改注册表来“解决”钓鱼。
- 用户只是询问某个浏览器菜单在哪里：这是操作查询，不需要调用本 skill。

### 作者在书中警告的失败模式

- **只重建快捷方式、只把主页改回来，却不杀毒**：写入源仍在运行或由计划任务周期性回写，修复只能维持到下一次触发；必须先清源。这是 ce30 同类问题的核心——把表层开关当成安全方案。
- **把 IE 安全级别调到最高、禁用 ActiveX 当作浏览器安全方案**：只对旧 IE/旧引擎有效，对 Chrome、Edge、Firefox 无效；高等级会破坏正常业务，用户往往把业务站点加入“受信任站点”从而整体绕过；它也不阻止钓鱼页、恶意扩展或已下载的木马（PAGE 145，ce30）。
- **删除 MenuExt 项前不展开确认**：书中特别提示要先展开该项、确认它指向哪个 HTML 文件，并把文件一并删除；跳过确认会误删正常插件项，或只删键项留下残余文件（PAGE 140–141）。
- **把“重置浏览器”当成修复**：重置只恢复默认配置，不会清除外部写入源，也不处理快捷方式参数、计划任务和策略。

### 作者的盲点 / 时代局限

- 书中以 IE 和旧版 Edge 为主，注册表键位与菜单名称随浏览器版本变化；直接照搬键路径可能失效。
- 现代浏览器的主要劫持面已经转移到扩展、同步账户、默认浏览器/默认搜索设置、企业策略（如 ExtensionInstallForcelist、HomepageLocation）和安装器捆绑，书中未覆盖；遇到这些应先看扩展列表与策略页，而不是只查 IE 注册表。
- 书中未讨论修复前的证据保全与授权边界；直接删除键值可能破坏取证线索，企业环境应先导出注册表项和相关文件再处置。

### 容易混淆的邻近方法论

- “杀毒软件的浏览器修复”与“手工键位修复”：前者适合批量恢复，但可能把正常项一起改掉；后者更精确，但要求先确认写入源。
- “隐私清理”与“劫持修复”：清理 Cookie、表单只降低凭据残留，不改变主页或右键被写入的事实。
- “安全级别加固”与“补丁、扩展治理”：前者只影响旧引擎的区域策略，后者才覆盖现代浏览器的执行面。

## 相关 skills（阶段 3 定稿）

- `malware-triage-order`（depends-on）：修复键位前必须先清写入源——查杀、计划任务、可疑扩展；源还在，改回主页只会被再次覆盖。
- `host-default-surface-convergence`（contrasts-with）：前者修已被改写的浏览器与快捷方式配置点，后者收敛主机级默认账户、共享与远程入口；对象不同，可在同一台机器上先后进行。
