# 隐藏账号的跨视图发现与处置

## R — 原文 (Reading)

> “这种隐藏账号的方法并不实用，只能做到在“命令提示符”窗口中隐藏，属于入门级的系统账户隐藏技术。”
>
> “在确定了黑客的隐藏账号之后，却无法删除。这时，可以通过……运行 net user“隐藏账号”“新密码”命令来更改隐藏账号的登录密码……”
>
> — 网络安全技术联盟，第4章 绝招9、绝招10

---

## I — 方法论骨架 (Interpretation)

隐藏账号的本质不是“对象不存在”，而是“当前视图把它过滤掉了”。判断时要先问：我正在用哪个视图看账号？这个视图的枚举规则是什么？换一个枚举逻辑不同的视图，隐藏是否还成立？

把账号当成一个会在多处留下痕迹的对象，逐一对照：命令行枚举、图形化本地用户和组、SAM 注册表、管理员组成员、登录审核事件。哪个视图看不见、哪个视图看得见，本身就是线索；差异比单次枚举结果更有价值。

跨视图不是把工具挨个跑一遍，而是选择枚举逻辑确实不同的视图；同源的两个列表不构成交叉验证。

静态视图仍不足时，就看行为：谁在什么时间、从哪里、以什么登录类型使用过这个账号。行为证据能把“看不见的账号”变成“看得见的动作”。

处置顺序与直觉相反：先改密切断攻击者已有凭据，再禁用或锁定，随后排查管理员组、服务、计划任务与 SAM 权限等持久化，最后才删除。删不掉不等于无法处置；删除失败时保留禁用与改密，避免硬删导致权限被锁。

## A1 — 书中的应用 (Past Application)

### 案例 1：net user ty$ 只骗过命令行
- **问题**：作者要验证一种常见的 Windows 账号隐藏手法是否真的能让账号消失。
- **方法论的使用**：先用 net user 创建 ty$ 并加入管理员组，再分别用命令行 net user 和“计算机管理 → 本地用户和组”两个视图核对。
- **结论**：net user 不显示 ty$，但图形界面仍能看到；这种隐藏只骗过命令行，属于入门级。
- **结果**：作者判定该方法不实用，并用 net user ty$ /del 删除，同时提示检查管理员组成员。

### 案例 2：改写 SAM 项让图形界面也看不到
- **问题**：需要判断图形界面也看不到的账号，是否真的不存在。
- **方法论的使用**：回到注册表 SAM\SAM\Domains\Account\Users\Names 与对应 RID 项，核对导出、改写后重新导入的账号项。
- **结论**：图形界面可以看不到，但注册表里仍有账号项；隐藏只是绕过了某一个视图。
- **结果**：作者提示此类账号仍可在注册表查到，排查要回到注册表并结合审核策略。

### 案例 3：删不掉时先改密
- **问题**：确认存在隐藏账号后，删除操作被拒绝，处置卡住。
- **方法论的使用**：不把“删不掉”当成“无法处置”，改用管理员权限重置该账号密码，先让原凭据失效。
- **结论**：改密不依赖删除是否成功，是更低风险的先行动作。
- **结果**：攻击者无法再用原密码登录；随后仍需处理权限与持久化。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **主机排查**：拿到一台疑似被入侵的 Windows 主机，net user 列表看起来正常，但用户说有人能远程登录。
2. **账号数量对不上**：net user 与“本地用户和组”数量不一致，或出现 $ 结尾、陌生拼写、长期不用的管理员账号。
3. **应急响应**：已经确认存在隐藏账号，但删除报错或权限被改，需要决定先做什么。
4. **日志反查**：需要从登录审核事件确认某个账号是否被使用、何时使用、从哪里登录。
5. **跨平台外推**：怀疑 Linux 上有 UID 0 的异常账号或影子账号，需要把“跨视图”方法迁移过去，但不照搬 Windows 路径。

### 语言信号 (用户的话里出现这些就应激活)

- “net user 看不到，但计算机管理里有”
- “有个 $ 结尾的账号”
- “Administrators 里多了个人”
- “账号删不掉”
- “帮我查查有没有隐藏账号 / 后门账号”
- "hidden account"、"backdoor account"、"account audit"、"net user mismatch"、"SAM registry"、"4624 logon"

### 与相邻 skill 的区分

- 与 `recon-funnel-and-scoping` 的区别：那个 skill 解决“目标在不在、开放什么服务”，是外部侦察；本 skill 是在已进入主机后，对账号对象做跨视图核验。
- 与 `malware-triage-order` 的区别：那个 skill 处理恶意进程、启动项与查杀顺序；本 skill 只处理账号与凭据。若同时存在木马，先断入口与出站，再处置账号与持久化。
- 与 `buffer-overflow-defense-layering` 的区别：那个 skill 是事前加固（补丁、限制触发、限制后果）；本 skill 是事后发现与处置。
- 与 `identity-deception-detection` 的区别：那个 skill 处理网络身份映射被替换（ARP、DNS、URL）；本 skill 处理主机内账号身份被隐藏。两者都可能表现为“登录异常”，但证据面不同。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行：

1. **建立账号基线**
   - 收集“应该存在”的账号：业务与运维负责人、管理员组应有成员、近期入职离职；记录当前 net user、本地用户和组、管理员组成员、SAM Names 项。
   - 完成标准：形成一张“应有 vs 现有”的清单，所有未知项都被标记。
   - 判停条件：若没有现成基线且无法获得业务信息，先按“最小管理员集 + 近期变更”建立临时基线，不要直接判定异常。

2. **多视图交叉比对**
   - 对每个可疑账号，记录它在命令行枚举、图形化用户列表、SAM 注册表、管理员组、登录审计中分别“出现 / 不出现”；关注 $ 结尾、RID 异常、描述为空、从未登录却启用等特征。
   - 完成标准：每个差异账号都有一张跨视图矩阵，且至少两个独立视图能确认其存在。
   - 判停条件：若所有视图一致且无陌生管理员账号，但仍有入侵迹象，进入步骤 3；若既无差异也无迹象，跳到步骤 5。

3. **行为审计**
   - 查登录审核事件（如 4624 成功登录、4625 失败、4672 特权登录、4720/4726/4732 账号与组变更、1102 日志清除），核对时间、来源主机、登录类型与账号是否匹配业务。
   - 完成标准：对每个可疑账号给出“是否被使用、何时、从哪里、是否异常”的结论。
   - 判停条件：若审核策略未开启或日志被清，不能得出“没有问题”；记录证据缺口，进入步骤 4 并优先保全现场。

4. **按顺序处置**
   - 先重置可疑账号密码，切断既有凭据；再禁用或锁定；随后检查管理员组、服务、计划任务、启动项、SAM 项权限与其他账号；确认没有其他入口后再删除。
   - 完成标准：原密码无法登录（实际验证），账号被禁用或删除，持久化项已逐项排查并记录。
   - 判停条件：若删除被拒绝，不要反复硬删；保持改密与禁用，修复 SAM 或注册表权限，或转入离线处置。

5. **复核与记录**
   - 重新跑一遍多视图枚举，确认没有新增陌生账号或管理员；复查登录审计与账号变更事件；记录处置时间线与证据。
   - 完成标准：跨视图复核无差异、原凭据失效、审计中无新的异常登录。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 只是给员工建号、改密、调整权限：这是账号生命周期管理，不是入侵排查。
- 只怀疑恶意进程、挖矿或病毒：先用 `malware-triage-order`；账号可能只是其中一个持久化点。
- Linux、域控、云 IAM：可以借用“跨视图”思想，但不能照搬 Windows 的 net user、SAM、“计算机管理”路径；应改用 `/etc/passwd`、`getent`、`/etc/shadow`、sudoers、`last`/`lastlog`、审计日志或对应平台的账号与日志视图。
- 没有主机权限、只能从外部做侦察：用 `recon-funnel-and-scoping`。

### 作者在书中警告的失败模式

- **只跑一条 net user 就下结论**：$ 后缀只骗过命令行，图形界面、SAM、登录审计仍可见（ce01）。warning_signs：账号数量对不上、$ 结尾账号、管理员组陌生成员、非工作时间 4624。
- **发现即删**：攻击者可能改了 SAM ACL，删除会被拒绝，甚至让管理员失去赋权能力；应先改密再处理（ce02）。warning_signs：`/del` 拒绝访问、删除提示成功但账号仍在、SAM 权限与基线不一致。
- **日志正常 ≠ 没入侵**：审核策略可能从未开启，日志也可能被清；不能把“没看到”当成“没有”（p06）。
- **只处理账号、不看其他持久化**：改密只对密码登录有效，服务、计划任务、其他账号仍可能是入口。

### 作者的盲点 / 时代局限

- 书以 Windows 7/10 早期、本地管理员和物理接触为前提，未覆盖域环境、EDR/SIEM、云 IAM 与远程无权限场景。
- 书重操作、轻验证：没有给出“改密后如何确认攻击者已失效”“删除后如何复核”的步骤；本 skill 用“原密码实际登录失败 + 多视图复核”补上。
- 书的工具与界面会随版本变化，不要把“计算机管理”的具体菜单路径当成方法本体。
- Linux 外推时不要照搬 Windows 路径；跨视图原则成立，视图名称和命令必须替换。

### 容易混淆的邻近方法论

- “查杀病毒”不是“账号审计”：前者看进程、文件、启动项，后者看账号对象与登录行为。
- “端口封禁”不是“删除账号”：封端口只减少入口，不能使已存在的凭据失效。
- “发现异常就重装”不是本 skill：重装可能丢失证据，且未查清入口时会再次被植入。
