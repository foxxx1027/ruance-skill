# 勒索软件安全动态分析

## R — 原文 (Reading)

> “Ransomlock会锁定屏幕，但不会试图终止任何进程或拒绝网络访问该机器。因此作为分析人员，我们可在虚拟机中留下一个后门，以便在任意时间杀掉恶意进程并恢复受感染系统的控制权。”
>
> — Daniel Regalado 等，《灰帽黑客》第4版，第21章 21.3 实验21-1

> “在虚拟机中对样本进行测试时并未产生网络流量，但这不一定意味着恶意软件不在工作。”
>
> — 同上，第21章 21.4

---

## I — 方法论骨架 (Interpretation)

1. 先按破坏面分类：只锁屏（Ransomlock）还是加密文件（CryptoLocker）。判据是文件是否被改写、是否追加扩展名，而不是勒索信自称的家族名或算法。
2. 分类决定路线：锁屏型可以动态运行并夺回控制权；加密型应以样本逆向、配置/密钥线索提取和备份恢复为主，动态观察只做短时取证。
3. 动态分析的第一原则是隔离：样本只在虚拟机中运行，不接生产网络、不挂真实数据，并先打快照。
4. 对会锁屏的样本，先留远程后门（bind shell）再运行；后门不是清除手段，而是“人还能操作被锁系统”的前提。
5. 动态取证只回答“碰了什么”：Procmon 过滤目标进程，记录文件、注册表、进程与网络事件；Autoruns 查 Run 键、Winlogon\Shell 与计划任务。
6. 杀进程或重启 explorer 只恢复桌面，不等于清除感染；解锁后仍须查持久化，避免重启再被劫持。
7. 面对逐条解码的样本，不单步每条算术；搜索 CALL EAX/EDX 等“调用寄存器”指令，在调用处断点读目标地址，沿链进入新代码。
8. 当链跳到 .rsrc 等新区域，在目标地址设执行硬件断点，直达解码完成后的真实代码；进入自复制代码前清空软件断点，避免 0xCC 被复制。
9. 临时改写内存绕过反调试后立即创建 VM 快照；磁盘文件保持不动，后续从快照恢复。
10. 桌面劫持按五层 API 还原：最小化循环、WH_KEYBOARD 钩子、RegisterHotKey、HWND_TOPMOST、ClipCursor。
11. 有 GUI 的样本先打开目标窗口再附加调试器，用 View|Windows 的 ClsProc 定位按钮窗口过程，从用户事件直达关键逻辑。
12. 无流量只能记为“未观测到”，不能记为“无网络行为”；要考虑反虚拟机与时间条件，并转向静态分析。
13. 动态圈定范围，静态回答机制；最后把文件、注册表、进程链、API 序列、域名与密钥线索整理成带证据来源和置信度的 IOC。

## A1 — 书中的应用 (Past Application)

### 案例 1：用 bind shell 夺回 Ransomlock 感染机

- **问题**：locker.exe 一运行就锁住桌面，分析人员无法打开 Procmon 查看日志，也无法正常操作被感染机器。
- **方法论的使用**：先用 msfpayload 生成 windows/shell_bindtcp 投放器，把 RHOST 改为分析机 IP，投放到受害虚拟机，再用 netcat 等待 shell；启动 Procmon 并只过滤 locker.exe；运行样本等待锁屏；通过远程 shell 用 pslist 找到 PID、pskill 杀掉进程（或重启 explorer.exe）恢复桌面；最后查看 Procmon，并用 Autoruns 的 Logon 页检查持久化。
- **结论**：样本不主动终止进程、不切断网络，才有条件保留后门；杀进程只是解锁手段，不是清除结论。
- **结果**：成功解锁并取得 Procmon/Autoruns 证据，发现 Run 键的 explorer 值与 Winlogon\Shell 被改成 locker.exe；但锁屏机制与 C&C 行为仍未解释，作者据此转向静态分析。

### 案例 2：逐层跟踪 CALL EAX 穿过 Ransomlock 解码链

- **问题**：入口用 GetPrivateProfileStringA 等指令伪装正常行为，随后是大量重复解码指令，逐条单步既慢又停留在壳层。
- **方法论的使用**：改为搜索 CALL 寄存器。在 0x00401885 命中时读到 EAX=0x0041FD12（位于 .rsrc），跳入后在 0x0041FD78 再遇 CALL EAX，落到 0x002042C2；继续在基址+0x1885 找到同一模式，EAX=0x0021FD12；某次调用被跳过时样本自终止，说明接近解码结束；最后在 0x0041FB50 命中执行硬件断点，看到 PUSHAD 与 .text 被清零后填充真实指令。
- **结论**：CALL 寄存器链能高效穿过自解码层；进入自复制代码前必须清空 int3 断点；“跳过某次调用即自终止”可作为解码末期的判据。
- **结果**：成功到达真实代码，并用 CreateToolhelp32Snapshot/Process32First/Next 确认样本在枚举进程。

### 案例 3：CryptoLocker 的“无流量”与勒索加密演进

- **问题**：样本声称文件被 RSA-2048 加密，输入比特币钱包地址并提交后界面显示连接成功，但抓包没有任何流量；这能否说明样本休眠或没有 C&C？
- **方法论的使用**：先核实文件被追加 .CRYPTOLOCKER 扩展名，而可执行文件、DLL 与驱动未被加密；不把勒索信当事实，提出“检测到虚拟环境而伪装”或“只在特定时间/日期连接”两种假设；打开付款窗口附加调试器，在 View|Windows 的 ClsProc 栏找 SUBMIT 按钮窗口过程并下断点。作者同时以 AIDS 木马（对称密钥内嵌，可提取恢复）到公钥方案的演进说明：可逆性取决于真实密钥管理，而非文案。
- **结论**：无流量只说明该轮未观测到，不能判休眠；勒索信会夸大算法强度；能否恢复要看代码与配置中的真实算法、密钥位置。
- **结果**：书中未确证无流量的原因，只保留两种假设并明确转向二进制静态分析；该案例成为“无流量不判休眠”的核心判据。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 拿到疑似勒索样本，想放进虚拟机运行，但担心锁屏后无法操作或加密真实文件。
2. 样本运行后桌面被锁、任务管理器一闪就被最小化、ALT+TAB 失效，需要夺回控制权并取证。
3. 样本反复自解码，单步很久仍在壳里，需要快速定位解码完成后的真实代码。
4. 沙箱跑完没有外联流量，用户问“是不是样本没跑起来/是不是没有 C&C”。
5. 需要判断样本是锁屏型还是加密型、杀进程能否解锁，并从 Procmon/Autoruns 提炼持久化 IOC。

### 语言信号 (用户的话里出现这些就应激活)

- “这个样本一运行桌面就锁了”
- “Procmon 还没来得及看，窗口就被最小化了”
- “单步很久还在解码循环里，怎么跳到真实代码”
- “沙箱里一点流量都没有，是不是样本休眠了”
- “勒索信说 RSA-2048，文件还有没有救”
- “CALL EAX 后面跟到哪里，怎么下断点”
- “Autoruns 里该看哪个启动项，杀进程算不算清除”

### 与相邻 skill 的区分


- **composes-with** `x64-malware-cc-decoding`：本 skill 观察运行后的加密、桌面劫持与持久化行为；64 位样本的 C&C 配置与编码层解码由它完成。
- 与第 1 本 `malware-sample-analysis` 的区别：那本是一般恶意样本的行为观察与静态分析入门，覆盖进程、网络、持久化的通用流程；本 skill 只处理勒索软件这一特殊范式——先分锁屏/加密、先留后门再运行、桌面劫持 API 链、CALL 寄存器解码链、“无流量不判休眠”以及不支付赎金的处置边界。
- 与纯静态逆向 skill 的区别：本 skill 用调试器与监控工具回答“运行后碰了什么、怎么被锁住”，不替代 IDA 对加密算法和 C&C 机制的完整逆向。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **确认授权与隔离边界**
   - 完成标准: 明确样本仅用于授权分析；虚拟机使用 Host-Only/断网快照，无真实数据与生产网络；记录样本哈希与来源。
   - 判停条件: 若要求在生产机或真实数据上运行，立即停止，改到隔离环境。

2. **做静态预检并判定破坏面**
   - 完成标准: 记录文件类型、字符串、扩展名特征，确认是“仅锁屏”还是“文件被改写/加密”，给出锁屏型或加密型判断。
   - 判停条件: 若为加密型且密钥不在本机，动态分析只做短时观察，主路线转静态分析与备份恢复。

3. **为锁屏型样本设计“先留后门”方案**
   - 完成标准: 准备好 bind shell 投放器与监听端，确认样本不主动断网、不杀分析工具；记录后门连接方式。
   - 判停条件: 若样本会断网或杀分析工具，放弃后门方案，改用本地控制台、快照回滚与离线取证。

4. **布置监控并打基线快照**
   - 完成标准: Procmon 过滤器只保留目标进程；Autoruns/注册表基线已记录；VM 快照已建立并可回滚。

5. **运行样本并观察锁屏与文件行为**
   - 完成标准: 记录锁屏时间、窗口行为、文件扩展名变化、进程/注册表/网络事件。
   - 判停条件: 若桌面被锁，进入步骤 6 从后门恢复；若开始批量改写文件，立即关机或回滚快照，停止动态观察。

6. **夺回控制权并做持久化取证**
   - 完成标准: 通过 shell 杀恶意进程或重启 explorer 解锁；用 Autoruns 检查 Run 键、Winlogon\Shell、计划任务，明确区分“解锁”与“清除”。
   - 判停条件: 若解锁后再次被锁，说明持久化仍在，回到步骤 4 重新监控，不得宣布清除。

7. **跟踪内存解码链**
   - 完成标准: 搜索 CALL EAX/EDX，记录每次命中的寄存器目标地址并画出跳转链；进入自复制代码前清空软件断点；在解码目标设执行硬件断点，到达真实代码。
   - 判停条件: 若找不到下一条 CALL 寄存器，或跳过某次调用样本即自终止，视为接近解码结束，转静态确认。

8. **还原桌面劫持与关键窗口逻辑**
   - 完成标准: 将行为对应到最小化循环、WH_KEYBOARD、RegisterHotKey、HWND_TOPMOST、ClipCursor；GUI 样本用 View|Windows 的 ClsProc 在按钮过程下断点。
   - 判停条件: 若只能看到零散 API 线索而无法解释机制，停止加监控工具，转调试器与 IDA 静态分析。

9. **判定网络行为并处理“无流量”**
   - 完成标准: 用抓包与 Procmon 记录“有流量”或“未观测到流量”；无流量时标注反虚拟机、时间条件等假设。
   - 判停条件: 无网络流量→继续本地行为观察，不判休眠；转静态分析，不写“无 C&C”。

10. **提炼 IOC 与给出结论**
   - 完成标准: 输出样本哈希、落地路径、扩展名、注册表键值、进程链、API 序列、域名/密钥线索，逐条标注证据来源与置信度；写明“杀进程≠清除”“不支付赎金”。
   - 判停条件: 若解密结果乱码→先怀疑密钥/偏移/解码轮次不对，复核后再改脚本；不得据此宣称算法不可破。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **在生产环境或真实数据上运行样本**：样本可能加密真实文件、横向移动或留下持久化后门；隔离虚拟机是前提，不是可选项。
- **目标是解密被加密文件而非分析样本**：本 skill 产出的是行为取证与机制理解，不提供密钥恢复或解密服务；应转向备份恢复、厂商解密工具与专业恢复流程，且不支付赎金。
- **样本带破坏性反分析**：若检测到虚拟机/调试器就删除文件、格式化、断网、杀分析工具或主动传播，“先留后门再运行”的前提不成立，应静态优先、快照与网络隔离，必要时放弃运行。
- **已确认样本会蠕虫化或横向移动**：单机虚拟机不足以承载风险，应先做网络隔离与事件响应，而不是继续动态分析。

### 书中警告的失败模式（ce143–ce149 相关）

- **ce143 先运行再找工具看结果**：桌面被置顶窗口、键盘钩子与最小化循环夺走后，监控工具仍在后台运行，但人已无法操作；必须先布监控、留后门再运行。
- **ce144 在自复制代码上留 int3 断点**：调试器写入的 0xCC 会被复制到新地址，指令被破坏，样本崩溃或走偏；进入前用 ALT+B 清空断点。
- **ce145 逐条单步解码指令**：耗时且长期停留在壳层；应改用 CALL 寄存器追踪与执行硬件断点。
- **ce147 相信勒索信里的加密算法声明**：CryptoLocker 声称 RSA-2048 并非事实；真实算法与密钥管理只能从代码和配置确认。
- ce146、ce148、ce149 属于第 22 章 64 位样本与 C&C 解码的同类反例（沙箱报告不等于完整 C&C 清单、单层 Base64 不等于明文、乱码先查密钥），由同书 `x64-malware-cc-decoding` skill 展开，本 skill 只借用其判据。

### 作者的盲点 / 时代局限

- **2014–2015 年快照**：Windows 7/8、32 位 Ransomlock/CryptoLocker、旧版 Procmon/Autoruns 与具体地址偏移，今天不能照抄；应复用流程而非地址。
- **CryptoLocker 时代的算法叙事**：书中案例的“RSA-2048”是恐吓文本，真实算法较弱；现代勒索普遍使用混合加密、逐文件密钥与更完整的密钥封装，不能用当年的可逆性判断套今天。
- **单机、单进程视角**：现代勒索常见双重勒索（先窃取再加密）、RaaS 分工、横向移动、蠕虫式传播与 EDR 规避；单虚拟机观察不到这些，需要网络隔离、域内取证与事件响应配合。
- **检测与恢复讨论不足**：书中“感染即结束”的判断成立，但现代防线还包括离线备份、行为检测、最小权限与恢复演练；这些不在本书范围内。

### 容易混淆的邻近方法论

- **一般恶意样本动态分析**：通用流程是“跑沙箱看行为”；勒索样本会先夺走交互通道，因此必须把“留后门/先布监控”前置。
- **脱壳与静态逆向**：CALL 寄存器追踪只用于定位解码结束点，不能替代 IDA 对锁屏机制、加密算法和 C&C 的逆向。
- **事件响应与解密恢复**：本 skill 是分析范式，不是清除或恢复方案；“杀进程解锁”与“清除感染”必须分开表述。
- **64 位 C&C 解码**：本 skill 面向 32 位勒索样本的行为与内存解码；配置块定位、Base64→RC4 分层剥离属于 `x64-malware-cc-decoding` 的职责。
