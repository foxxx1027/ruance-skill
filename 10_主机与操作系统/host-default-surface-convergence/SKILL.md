# 主机默认攻击面收敛

## R — 原文 (Reading)

> "账户锁定策略是指当用户在忘记或不知道用户账户和密码的情况下，在输入X次……无效输入后，Windows会将登录置为锁定状态。"（PAGE 250，第13章 13.2 本地安全策略）
>
> "上次成功登录的用户名会显示在Windows登录界面上，这可能造成账户信息的泄露，给黑客以可乘之机。"（PAGE 247，第13章 13.2 实战6）
>
> — 网络安全技术联盟 主编，《黑客攻防与网络安全从新手到高手（实战篇）》第13章

---

## I — 方法论骨架 (Interpretation)

主机加固的起点不是补丁清单，而是厂商交付时留下的默认值。每个默认值都是厂商为便利做的取舍，同时也在替攻击者省步骤：登录界面显示上次用户名，省去账号枚举；Administrator/Guest 固定存在，省去猜名字；没有账户锁定，允许无限次在线尝试；匿名 Everyone 生效，让未认证连接直接继承共享权限；不必要的远程服务与共享默认开启，提供了现成入口。

因此收敛的动作不是"把能关的都关掉"，而是先回答三个问题：这条默认值让谁知道什么、让谁进到哪里、进来后能做什么。按"替攻击者省了多少步"排序，优先处理直接降低在线破解成本与身份可预测性的项。

落地时把主机策略收成四段：账户锁定（阈值、锁定时间、重置计数器必须同时设）、密码策略（复杂性、长度、期限、历史）、用户权限分配（去掉不必要的网络与交互登录权）、默认账户（禁用 Guest、重命名 Administrator）。前两段直接抬高在线破解成本，应先做；权限次之；默认账户最后。

收敛后仍要留检测：锁定事件、失败登录、策略是否真正生效、是否存在域策略覆盖。默认值改了不等于攻击面消失，只等于攻击者要换一条更贵的路径。

## A1 — 书中的应用 (Past Application)

### 案例 1：6 次失败锁定 30 分钟

- **问题**：主机允许对本地账户反复尝试登录，在线猜密码没有上限。
- **方法论的使用**：把"在线破解成本"落到账户锁定三元组，而不是只设一个阈值；用组策略同时配置阈值、锁定时间与计数器重置时间。
- **结论**：阈值 6 次、锁定 30 分钟、计数器重置 30 分钟，三项一起调整才形成可恢复的阻挡。
- **结果**：连续 6 次无效登录后账户进入锁定状态（PAGE 250–251）。

### 案例 2：重命名 Administrator 与 Guest

- **问题**：Windows 内置 Administrator 拥有全部权限，Guest 默认存在，攻击者可直接把这两个名字作为猜解目标。
- **方法论的使用**：把默认账户名当作"身份可预测性"这一项攻击面，在本地安全策略的安全选项中重命名系统管理员账户与 Guest 账户。
- **结论**：改名只降低直接猜默认账户的效率，不能替代强密码、锁定与权限收敛。
- **结果**：默认账户名被替换，攻击者不能再直接以 Administrator/Guest 作为目标；书中也明确其边界（PAGE 253–254）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 新装或重装 Windows、办公终端交付前，需要一份按风险排序的安全基线，而不是装完杀毒软件就算完成。
2. 审一台开了共享、保留 Administrator 默认名、登录界面显示上次用户名、没有账户锁定策略的主机。
3. 管理员问"账户锁定设几次""密码策略怎么配""Guest 要不要禁用""要不要改管理员账户名"。
4. 多人共用或半公开终端（前台、教室、值班室），需要减少账号信息泄露与误用。
5. 手上有一张"关这个、禁那个"的加固清单，需要判断哪些动作真正降低攻击者成功率、哪些只是制造安全感。

### 语言信号 (用户的话里出现这些就应激活)

- "刚装好的系统安全吗""默认配置要不要改""加固清单先做哪个"
- "账户锁定设几次""锁定时间设多少""密码策略怎么设"
- "Administrator 要不要改名""Guest 要不要禁用""登录界面显示用户名"
- "匿名访问""Everyone 权限""共享要不要关"
- "default configuration hardening""account lockout policy""anonymous access""attack surface reduction"

### 与相邻 skill 的区分

- 与 `remote-access-surface-audit` 的区别：本 skill 处理主机本地的账户、登录界面、匿名访问与策略默认值；后者处理远程入口的"服务—通道—凭据"三层。两者在默认账户与默认服务上有交叠，但分析对象不同。
- 与 `hidden-account-hunt` 的区别：本 skill 收敛已知的默认账户与默认权限；后者面向"是否存在被隐藏或克隆的账户"。前者是预防性配置，后者是排查性取证。
- 与 `malware-triage-order` 的区别：本 skill 在未失陷时降低攻击面；后者在已失陷后做处置，不应互相替代。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行：

1. **盘点默认值，而不是先改设置**
   - 列出：账户（内置管理员、Guest、空密码账户）、登录界面是否显示用户名、共享与匿名访问、远程入口、密码/锁定策略当前值、谁拥有本地管理员。
   - 完成标准：每一项都写成"默认值 → 谁知道它 → 谁能用它 → 进来能做什么"四列。
   - 判停条件：若发现未知管理员、异常登录或可疑进程，先转入失陷处置，不在已失陷主机上做"加固收尾"。

2. **按"替攻击者省了多少步"排序**
   - 优先处理：无限次在线尝试、可预测的管理员名、匿名可读共享、空密码或弱密码；其次处理显示用户名、非必要远程服务、过宽的用户权利。
   - 完成标准：得到一张有先后顺序的收敛清单，并写出每条对应的攻击者路径；不能说明对应路径的项暂时降级。

3. **先收账户与认证，再收权限与入口**
   - 账户锁定三元组同时设定（阈值、锁定时间、重置计数器）；密码策略设定复杂性、长度、期限与历史；禁用 Guest；重命名管理员账户并保留强密码。
   - 收窄"从网络访问此计算机"等用户权利，去掉不必要的远程与交互登录。
   - 完成标准：三项锁定参数均有值且相互匹配；Guest 不可用；管理员账户名已改变；每一项用户权利都有业务理由。
   - 判停条件：若关键业务依赖共享账户或服务账户，先设计例外与备用管理员，避免锁定策略直接造成业务中断。

4. **收匿名与默认暴露面**
   - 禁用"Everyone 权限应用于匿名用户"，关闭不必要的共享与匿名枚举；登录界面不显示上次用户名；停用不需要的服务与端口。
   - 完成标准：匿名连接无法继承 Everyone 权限；共享清单每项有用途与授权范围；登录界面不泄露账号名；停用服务的端口不再监听。

5. **验证生效并留下残余检测**
   - 用一次受控的失败登录验证锁定行为；核对策略是否被域策略或第三方软件覆盖；记录变更前值、变更后值与回滚方法。
   - 完成标准：有生效证据（事件记录或策略结果），有锁定与失败登录的查看责任人与周期，有回滚路径。
   - 判停条件：若无法验证策略生效（无权限、被集中管理覆盖），把该项标为"残余风险"，不要写成"已完成"。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 域或云环境已由集中策略统一管理时，逐台改本地策略可能与上级策略冲突；应先确认策略来源与优先级。
- 主机已经失陷或正在被远程操作时，先隔离与取证；在活体上改策略既可能打草惊蛇，也可能破坏证据。
- 关键业务依赖共享账户、服务账户或无人值守登录时，直接套用低阈值锁定会造成锁定型中断；需先设计例外。
- 目标不是 Windows 本地主机（网络设备、Linux、云身份）时，具体策略项不适用，只能借用"默认值→攻击者路径"的推理方式。

### 作者在书中警告的失败模式

- 把隐藏"添加或删除程序"当作阻止软件安装/卸载的完整控制：它只挡住一个界面入口，便携软件、脚本、命令行安装器都能绕过，且用户仍是本地管理员时攻击者根本不走这个入口（ce12，PAGE 262）。
- 把重命名 Administrator/Guest 称为"防御黑客入侵的最好办法"：改名不改变 SID 500/501，也不改变口令与权限；过度依赖改名会忽略 Guest 启用、共用本地管理员口令等更高风险项（ce13，PAGE 253）。
- 只按防爆破设置低阈值锁定，却不评估锁定型拒绝服务：攻击者知道用户名就能周期性续锁，共享账户与服务账户被锁会直接中断业务；应配合来源限制、告警、备用管理员与例外策略（ce27，PAGE 251）。

### 作者的盲点 / 时代局限

- 书写于 2019 年、Windows 10 早期版本语境。现代 Windows 的默认值已变化：匿名枚举、SMB1、远程注册表等默认更严，部分本地安全策略项已被移除或改由其他机制管理；照搬书中的"默认不安全"判断前要先核实当前系统版本与默认值。
- 假设读者拥有本地管理员并能自由改组策略；对受域控、MDM、云身份管理的终端覆盖不足。现代环境还需考虑 LAPS/唯一本地管理员密码、Credential Guard、集中日志与 EDR，这些书中没有涉及。
- 把"改一个策略项"当成完整防线，缺少对策略被覆盖、例外账户、业务连续性的分析；这也是本书"清单式安全感"批判的主要来源。
- 未讨论攻击者已拿到本地管理员或离线哈希后的场景：此时在线锁定与改名都不构成阻挡，需要转向凭据轮换、横向移动检测与重装/还原。

### 容易混淆的邻近方法论

- `hidden-account-hunt`：找"藏起来的账户"；本 skill 收"明面上的默认账户与默认策略"。
- `remote-access-surface-audit`：按服务—通道—凭据审计远程入口；本 skill 按账户—策略—权限收敛本地默认值。
- `account-compromise-layering`：面向账号被盗后的分层止损；本 skill 面向未失陷主机的预防性加固。

## 相关 skills（阶段 3 定稿）

- `remote-access-surface-audit`（composes-with）：同一台主机上先收默认账户与策略，再按服务—通道—凭据审计远程入口；前者回答"谁可能被猜中"，后者回答"从哪进来"。
- `log-integrity-and-evidence`（composes-with）：加固后要用登录与锁定事件证明策略真的生效，并检查是否存在域策略覆盖；日志缺失时不能宣称已收敛。
- `account-compromise-layering`（contrasts-with）：前者是未失陷前的预防性收敛，后者是账号已失守后的冻结、改密与重建；已发现异常登录时应先止损，而不是继续做加固收尾。
