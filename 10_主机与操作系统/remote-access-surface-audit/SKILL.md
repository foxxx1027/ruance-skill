# 远程访问入口—通道—凭据审计

## R — 原文 (Reading)

## I — 方法论骨架 (Interpretation)

远程控制能否成立，只取决于三个条件是否同时满足：被控端有正在监听并能接受会话的服务；主控端到被控端的网络路径可达；攻击者手里有可用凭据或已建立的会话。三者缺一，远程控制就不成立。这个模型的价值在于它不区分工具"正规"与否——系统自带的远程桌面、浏览器管理工具、第三方远控软件，只要三要素齐全，效果一样。

防御因此有一个固定的收敛顺序：先关服务，再限通道，最后强认证。关服务是抽掉入口，成本最低且最彻底；限通道是把可达范围缩到必要来源；强认证只是在入口仍然存在时提高利用门槛。顺序反过来——只加密码、不改端口、不关服务——等于默认接受入口长期存在。

还要单独检查默认值：默认端口（如 3389、2000、7314）、默认账户（Administrator）、安装后即监听的浏览器管理界面，都会让攻击者少做一步。合法的 IT 运维工具同样要按这条线审计，因为"谁装的"不改变"谁能用"。

收敛后必须验证残余：服务是否真的停止、端口是否不再监听、旧会话是否断开、失败与成功登录是否有记录。对于业务必须保留的入口，写清保留理由、可达来源、认证方式与会话审计责任人，而不是用"改了端口"冒充已关闭。

## A1 — 书中的应用 (Past Application)

### 案例 1：远程桌面用 IP + Administrator 直接接管

- **问题**：目标主机开启了远程桌面，控制端处于同一局域网并已知目标 IP。
- **方法论的使用**：按三要素逐项确认——服务已允许远程连接、通道由同一网段提供、凭据为 Administrator。
- **结论**：三要素同时成立，远程桌面就构成可直接接管的入口，与是否存在漏洞无关。
- **结果**：输入 192.168.1.103 与 Administrator 凭据后进入目标桌面，获得与本地几乎一致的操作能力（PAGE 96–98）。

### 案例 2：RemotelyAnywhere 把合法管理工具变成浏览器入口

- **问题**：需要远程管理一台主机，使用厂商提供的"正规"工具 RemotelyAnywhere。
- **方法论的使用**：不按工具品牌判断安全性，而看安装后是否产生监听服务、是否可通过网络到达、是否沿用默认 Administrator 凭据。
- **结论**：合法管理工具同样满足三要素，浏览器即可成为攻击通道；默认端口 2000 与默认账户进一步降低成本。
- **结果**：控制端用浏览器打开 http://主机:2000，输入 Administrator 后进入完整管理界面（PAGE 101–102）。

### 案例 3：QuickIP 展示三要素齐全后的能力面

- **问题**：第三方远控 QuickIP 采用服务端/客户端模式，需要评估其影响半径。
- **方法论的使用**：先确认服务端监听端口与密码，再从客户端验证通道与凭据；三要素成立后继续盘点"能做什么"。
- **结论**：一旦三要素齐全，能力面包括磁盘浏览、屏幕控制、进程与服务查看、远程关机，影响半径远超"看一眼桌面"。
- **结果**：客户端添加 192.168.109.1:7314 并输入密码后，成功执行上述操作（PAGE 110–111）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 办公网里有一台机器为 IT 支持开了远程桌面或装了第三方远控，需要判断是否保留、如何收敛。
2. 主机或服务器把 3389 或默认管理端口暴露到公网、经厂商中继，管理员认为"密码很强"所以没问题。
3. 做暴露面盘点时，需要同时检查系统自带入口（远程桌面、远程注册表、远程协助）和第三方远控、浏览器管理界面。
4. 发现陌生监听端口（如 2000、7314）或不熟悉的浏览器管理页，需要判断它是不是一条远程通道。
5. 事后复盘"有人远程进过这台机器"，需要分清入口是哪个服务、从哪条通道进来、用了哪组凭据。

### 与相邻 skill 的区分

- 与 `host-default-surface-convergence` 的区别：本 skill 审计远程入口的服务—通道—凭据三层；后者收敛本地账户、登录界面与策略默认值。主机开着远程桌面时两者会同时适用，但一个看"入口怎么成立"，一个看"默认值替攻击者省了什么"。
- 与 `malware-triage-order` 的区别：本 skill 是未失陷前的入口审计；后者是已失陷后的恶意代码处置。
- 与 `recon-funnel-and-scoping` 的区别：后者从外部发现暴露面；本 skill 对已知或授权入口做三层核查与收敛。
- 与 `identity-deception-detection` 的区别：证书与身份欺骗的判据归后者；本 skill 只把证书告警当作通道可信度信号。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行：

1. **列出所有远程入口，而不是只查远程桌面**
   - 系统自带：远程桌面、远程注册表、远程协助、远程管理服务；第三方：IT 支持工具、浏览器管理界面、客户端—服务端远控；同时记录监听端口、进程、启动方式、使用人。
   - 完成标准：每个入口都有"服务/进程—端口—使用人—业务理由"四项；未知监听项单独标记。
   - 判停条件：出现无法解释的监听服务或异常会话，先按失陷处理并隔离，不继续做常规收敛。

2. **验证通道：谁能到达这个端口**
   - 从外网、其他网段、VPN 内分别测试可达性；记录 NAT、端口映射、厂商中继、反向连接等路径。
   - 完成标准：形成"来源群体 × 端口 × 是否可达"的矩阵；每条可达路径都有对应控制（防火墙、ACL、VPN、分段）。
   - 判停条件：若入口直接暴露在公网且无额外控制，先限制通道，再讨论认证。

3. **核查凭据与会话层**
   - 检查是否沿用默认账户或默认口令、是否多机共用本地管理员口令、是否启用网络级认证与锁定、会话是否可共享或无人看守。
   - 完成标准：每个入口都能说出"用哪些账户、什么认证方式、失败如何处理、会话谁能看到"；默认凭据清零。
   - 判停条件：若业务必须共用账户且无法改，记录为例外并加会话审计与来源限制，不要宣称"已强认证"。

4. **按固定顺序收敛：关服务 → 限通道 → 强认证**
   - 不用就关服务或卸载；必须保留则限制来源与网络路径；最后才加网络级认证、强密码、锁定与多因素。
   - 完成标准：每个入口要么被移除，要么三层都有明确配置；移除项需确认服务停止、端口不再监听、旧会话已断开。
   - 判停条件：若只完成了"改端口"或"加密码"，不得标记为已收敛；那只是通道或凭据的一小部分。

5. **留会话审计与复审**
   - 记录成功与失败登录、会话起止、来源地址与操作；对必须保留的入口设定复审周期与责任人。
   - 完成标准：有可查询的登录/会话记录，有异常告警或人工复核安排，有变更前后证据与回滚方式。
   - 判停条件：若日志缺失或被清理，先恢复日志可见性，否则无法证明入口已被控制。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 设备完全离线或物理隔离、没有远程管理需求时，直接关闭入口即可，不需要完整的三层审计。
- 提供远程支持本身就是业务（托管运维、远程桌面服务商）时，不能用"关服务"作为默认答案，应转向身份隔离、会话录制、最小权限与租户分隔。
- 主机已经失陷、攻击者已建立会话时，先隔离与取证；常规收敛可能惊动攻击者或破坏证据。
- 目标是利用某个 RDP 或远控协议漏洞时，属于漏洞分析与补丁管理，不是本 skill 的入口审计。

### 作者在书中警告的失败模式

- 只改密码不关服务：只要服务开着、通道可达，攻击者仍可反复尝试凭据或利用协议问题；关闭不用的入口比加固认证更便宜、更彻底（p08，PAGE 111–112）。
- 把"开启防火墙"当成全部答案：防火墙只处理通道层，服务仍在运行、凭据仍可复用，且出站反向连接可以绕过入站限制（f06 失效条件）。
- 忽略 RDP 证书告警并勾选"不再询问"：自签名或不受信证书可能意味着中间人，继续连接会把凭据交给代理，且后续同类替换不再告警（ce29，PAGE 99）。

### 作者的盲点 / 时代局限

- 书写于 2019 年、Windows 10 早期版本语境。现代 Windows 客户端默认关闭远程桌面，远程注册表服务默认不运行，网络级认证与证书处理也更严格；书中的"默认开启"判断需按当前系统版本重新核实。
- 只覆盖入站远控与局域网可达性，没有展开出站反向连接、厂商云中继、零信任代理、临时授权、会话录制与多因素认证；这些在现代远程运维中是主战场，需要重新评估原有的"关服务"结论是否仍成立。
- 默认读者拥有本地管理员并能自由关服务；对托管终端、域集中策略、SaaS 管理面覆盖不足。
- 书中演示的 RemotelyAnywhere、QuickIP 等工具已停更或难以获取，具体端口与界面会失效；可迁移的是三要素与收敛顺序，不是工具步骤。
- 书中没有区分"改端口"与"关服务"：端口变更属于通道层伪装，服务仍在监听、凭据仍可复用，不能当作入口已关闭。

### 容易混淆的邻近方法论

- `host-default-surface-convergence`：收本地账户与策略默认值；本 skill 收远程入口的服务—通道—凭据。
- `malware-triage-order`：已失陷后的恶意代码处置；本 skill 是未失陷前的入口审计。
- `recon-funnel-and-scoping`：从外部发现暴露面；本 skill 对已知或授权入口做三层核查与收敛。
- `identity-deception-detection`：证书与身份欺骗的判据；本 skill 只把证书告警当作通道可信度信号。
