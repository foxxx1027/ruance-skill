# 可移动介质入口封堵（USB Autorun Hardening）

## R — 原文 (Reading)

> “主要措施有关闭系统默认打开的‘自动播放’功能……在U盘的根目录下建立Autorun.inf目录，并设其属性为‘隐藏’和‘只读’，可以截断利用移动磁盘自运行进行传播的病毒。”
>
> — 网络安全技术联盟，第10章 10.2（绝招1–4）

---

## I — 方法论骨架 (Interpretation)

U 盘病毒的第一入口不是“病毒文件本身”，而是介质插入后系统读取并执行 `autorun.inf` 所指向程序的那条链。要封的是这条执行链，不是媒体播放器的开关。

在 Windows 上，这条链至少有三个独立控制点：组策略中的“关闭自动播放”、注册表 `NoDriveTypeAutoRun`（及对应策略键）、`Shell Hardware Detection` 服务。它们分属策略层、注册表层和服务层，关掉一个不代表另外两个已经失效。

因此正确做法不是“找个地方关一下”，而是三条路径全部关闭，再逐条确认状态，最后用一次真实插入来验收：不弹自动播放选项、不执行任何程序。

除了“关”，还要“挡写入”：在磁盘或 U 盘根目录放一个名为 `Autorun.inf` 的目录，设为隐藏、只读，让病毒无法再创建同名文件。它只能阻断依赖 autorun.inf 的传播，不等于杀毒。

“查”的判据是根目录基线：正常 U 盘根目录不应凭空出现隐藏的 `autorun.inf`、`*.exe` 或异常目录；出现即按可疑介质处理，先查杀、后打开，绝不双击试探。

“用”的顺序是先检查、后双击。对离线或工控环境，不能把希望寄托在病毒库更新上，应叠加只读介质、专用摆渡机、应用白名单和固定操作规程。

若还要防数据泄露，加密与密钥备份必须同时设计：恢复密钥要离开加密介质单独保存，否则加密盘丢失时数据仍可能永久不可读。

## A1 — 书中的应用 (Past Application)

### 案例 1: 三条关闭路径的对照应用（第10章 绝招1–3）
- **问题**: U 盘插入后可能自动执行 `autorun.inf`，作者把“关闭自动播放”列为 U 盘安全防护的首要措施。
- **方法论的使用**: 书中没有只给一个开关，而是分别给出组策略、注册表、服务三条关闭路径。
- **结论**: 三条路径都能独立影响这条执行链，任一条未关都可能保留触发面；因此应全部关闭，而不是“关一个就算完成”。
- **结果**: 书中的演示停在三条路径各自的设置，未给出“三条全关后插入测试”的组合验收；本 skill 把插入验收补成完成标准。

### 案例 2: 根目录隐藏文件与同名目录免疫（第10章 绝招4）
- **问题**: U 盘病毒以隐藏的 `autorun.inf` 和可执行文件传播，正常文件窗口里不容易看到。
- **方法论的使用**: 作者用 WinRAR 直接查看 U 盘根目录，发现 `autorun.inf` 后查看其内容（如出现 `open=***.exe`），据此判定感染并删除；同时建议在根目录建立隐藏、只读的同名 `Autorun.inf` 目录。
- **结论**: 根目录出现本不该有的隐藏文件就是中招信号；同名目录可以让病毒无法再写入同名文件，从而截断一条传播路径。
- **结果**: 书中演示了查看与删除 `autorun.inf`，并把同名目录免疫列为建议；未验证“目录是否真的阻止了写入”，本 skill 要求补一次写入测试。

### 案例 3: BitLocker 恢复密钥先备份（第10章 绝招8–9）
- **问题**: U 盘携带重要数据，丢失或被盗会造成数据泄露，需要对介质加密。
- **方法论的使用**: 作者在启用 BitLocker 时先选择恢复密钥的备份方式（Microsoft 账户、文件或打印），再设置密码、选择加密范围并开始加密，并提示加密完成前不要移除驱动器。
- **结论**: 加密前必须先把恢复密钥存到加密介质之外；密码或智能卡丢失后，恢复密钥是唯一的解锁路径。
- **结果**: 书中演示了“保存到文件”的备份流程，并提示加密过程中不要拔出 U 盘；本 skill 进一步把“密钥不与加密盘同放”作为验收项。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 新买或经常交换文件的 U 盘/移动硬盘，用户希望“插上不中毒”，问怎么关闭自动播放或自动运行。
2. 用户已经在系统设置里关了自动播放，但插盘仍出现 `Auto` 选项、仍自动打开程序，怀疑还有遗漏路径。
3. 离线机、工控机、实验室机只能用 U 盘交换数据，用户需要一套不依赖病毒库实时更新的介质使用规程。
4. 用户准备打开一个来源不明的 U 盘，想先判断根目录是否有隐藏的 `autorun.inf`、`*.exe` 或异常目录。
5. 用户要给 U 盘做 BitLocker 加密，或担心恢复密钥丢失后盘打不开。

### 语言信号 (用户的话里出现这些就应激活)

- “U 盘一插就中毒”“插上 U 盘就自动运行”
- “怎么关闭自动播放”“自动播放关不掉”“右键还有 Auto”
- “autorun.inf 删不掉”“U 盘根目录有隐藏文件”
- “工控机/离线机怎么用 U 盘”“不能联网怎么防 U 盘病毒”
- “BitLocker 恢复密钥放哪”“加密盘打不开”
- “USB virus”“disable autorun”“USB hardening”“NoDriveTypeAutoRun”“Shell Hardware Detection”

### 与相邻 skill 的区分

- 与 `recon-funnel-and-scoping` 的区别: 后者解决“目标是否存在、开放什么端口/服务”，本 skill 解决“介质插入本机后执行什么”，不主动扫描网络。
- 与 `buffer-overflow-defense-layering` 的区别: 后者沿漏洞触发链做补丁/缓解/后果限制；本 skill 封的是恶意文件的介质入口，不分析溢出。
- 与 `hidden-account-hunt` 的区别: 后者查账号持久化；本 skill 查介质根目录与自动执行链，不处理账号。
- 与 `identity-deception-detection` 的区别: 后者识别 ARP/DNS/URL 等身份映射替换；本 skill 不涉及网络身份欺骗。
- 与 `data-backup-recovery-discipline` 的区别: 后者管备份的故障域与恢复写入纪律；本 skill 只在 BitLocker 密钥备份上借用“异地保存”，不处理数据恢复。
- 与 `wireless-security-grading` 的区别: 后者管 Wi-Fi 认证与旁路；本 skill 管可移动介质，二者入口不同。
- 与 `malware-triage-order` 的区别: 本 skill 是“插入前/使用中”的预防与检查；一旦确认主机已感染或介质已带毒，转后者做隔离、定位、清除与复核。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行:

1. **建立介质与主机基线**
   - 记录主机系统版本、是否有本地管理员权限、组策略是否可用、`Shell Hardware Detection` 是否被业务依赖。
   - 按介质类型记录“根目录正常应有哪些隐藏项”：普通 U 盘通常不应有隐藏的 `autorun.inf`/`*.exe`；厂商工具盘、系统盘、加密盘可能例外，必须单独标注。
   - 完成标准: 形成一张基线表；没有基线的高风险介质，默认按“根目录隐藏文件=可疑”处理。

2. **三条路径全关并逐条验证**
   - 组策略侧: 找到并启用“关闭自动播放”，作用范围覆盖可移动介质（按当前系统版本确认策略位置，不照搬旧版菜单）。
   - 注册表侧: 设置 `NoDriveTypeAutoRun` 及相关策略键；若沿用书中的 `MountPoints2` 权限做法，把它视为注册表层补充，而不是唯一开关。
   - 服务侧: 将 `Shell Hardware Detection` 设为禁用并停止；先记录它对硬件事件通知等业务的影响，有依赖时改用补偿控制。
   - 完成标准: 三条路径逐条检查均为“已关闭/已禁用”，并用已知干净的测试 U 盘插入验证——不弹自动播放选项、不执行程序、右键不出现异常的 `Auto` 入口。
   - 判停条件: 任一条未通过，不得宣称已加固；回到失败的那条路径。若组策略不可用（家庭版/无域/无管理员），改用注册表+服务+用户操作规程，但仍要完成插入验证。

3. **介质免疫与只读/加密策略**
   - 在所有相关磁盘和 U 盘根目录建立名为 `Autorun.inf` 的目录，属性设为隐藏、只读；确认它是目录而不是文件，并尝试创建同名文件验证写入被阻断。
   - 需要防篡改时启用只读/写保护（硬件写保护、介质只读、权限控制）；需要防泄露时启用 BitLocker，并在加密前把恢复密钥保存到加密介质之外，实际做一次取回/解锁验证。
   - 完成标准: 免疫目录存在且不可被同名文件覆盖；只读策略有写入测试；恢复密钥有异地副本且可读取。
   - 判停条件: 介质必须可写时，不要宣称“只读已保护”，改为“免疫目录+插入检查+受控摆渡”。

4. **插入时的检查流程**
   - 打开“显示隐藏文件”和“显示已知文件扩展名”，先看根目录：是否多出 `autorun.inf`、`*.exe`、`*.lnk` 或异常目录；若存在 `autorun.inf`，先读内容（例如 `open=*.exe`），不要双击任何文件。
   - 先查杀、后打开：在线环境先更新引擎做多引擎/专杀扫描；离线环境按第 5 步的摆渡流程处理。扫描结果只有“可疑”而没有具体文件与处置动作时，视为未处理。
   - 完成标准: 每次插入都有检查记录（干净/可疑/已处置）；确认“检查在双击之前”。
   - 判停条件: 发现根目录异常隐藏文件、`open=` 指向可执行文件、或扫描命中——立即停止打开，隔离介质，转 `malware-triage-order`。

5. **离线/工控场景的替代方案**
   - 不依赖病毒库实时更新：设置一台专用的、可更新病毒库的摆渡/扫描机；未知介质先在摆渡机扫描，再以只读或一次性写入介质转入生产机。
   - 叠加物理写保护/只读介质、应用白名单、禁用不需要的自动运行与可移动介质写入权限，并保留介质交接记录。
   - 完成标准: 形成可执行的书面流程，并用已知干净介质做一次全流程演练；生产机从未直接打开未经检查的介质。
   - 判停条件: 无法提供扫描/摆渡条件时，禁止未知介质接入受保护主机；不要用“装了一个不更新的杀毒软件”替代流程。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 主机已经出现感染迹象（陌生进程、异常外联、文件被加密、反复弹窗）：本 skill 只能降低入口风险，不能清除已有恶意代码，应转 `malware-triage-order`。
- 目标是数据恢复、磁盘取证或备份设计：应转 `data-backup-recovery-discipline`；本 skill 的 BitLocker 部分只处理密钥备份，不处理恢复。
- 目标是非 Windows 平台或现代系统，且 `autorun` 语义不同：不要照搬 Windows 的三条路径；应使用该平台的挂载选项、`noexec`、端点策略与介质控制。
- 用户只是问“U 盘为什么打不开/怎么恢复文件”：先判断是硬件、文件系统还是数据丢失，不要用加固流程代替故障诊断。

### 作者在书中警告的失败模式

- **把“自动播放”当成媒体播放器设置**：只关 Windows Media Player 或默认程序，插盘仍出现 `Auto` 选项或仍执行程序。警告信号：设置里关了媒体自动播放，但右键菜单仍有 `Auto`；插入后仍弹出程序。
- **只关一条路径**：组策略关了但服务仍在运行，或注册表改了但策略覆盖，或服务禁用后用户仍手动双击。警告信号：只检查了一个开关；没有做插入验收；换一台机器就失效。
- **把广谱侦测当查杀**：广谱/启发式只提示“可能有未知病毒”，不能完整查杀。警告信号：结果只有“可疑”没有文件路径与处置动作；清除后 `autorun.inf` 仍在；没有第二引擎复核。
- **恢复密钥与加密盘同放**：把 BitLocker 恢复密钥文件留在加密盘根目录，或只存一份。警告信号：密钥文件在待加密介质上；从未试过用密钥解锁；密钥没有异地副本。
- **同名 `Autorun.inf` 目录被误判**：目录本身可能被病毒伪装、删除或替换。警告信号：名为 `Autorun.inf` 的其实是文件；属性不是隐藏/只读；目录内出现可执行文件；免疫后从未验证写入是否真的被阻断。
- **在工作机上双击可疑介质里的文件“看看是什么”**：一旦执行，可能向外群发或感染本机。警告信号：测试机仍连公司/校园网；邮件客户端已登录；没有隔离环境。

### 作者的盲点 / 时代局限

- 书中以 Windows 7/10 早期版本为主，组策略、注册表路径和服务行为在 Windows 11 上已有差异；现代 Windows 对 U 盘默认不再执行 `autorun`，但旧系统、嵌入式系统和用户手动双击仍使入口存在，不能因此认为问题消失。
- USBKiller、USBCleaner、Autorun 病毒防御者等工具多已停更或改版，菜单路径与病毒库不可依赖；应使用当前可维护的引擎与端点控制。
- 作者偏重单机、管理员、物理接触场景，缺少企业侧的资产台账、集中策略、日志留存、EDR、写阻断器和介质交接审计。
- 书中很少给出“加固后如何验证”的步骤；关闭服务/策略的可用性副作用也没有系统评估。本 skill 的插入验收和写入测试是对这一空白的补充。
- “广谱侦测”只能提示未知病毒，作者也明确说不能完全查杀；不能把它当成离线环境的兜底。

### 容易混淆的邻近方法论

- “关闭自动播放”≠“关闭媒体播放器的自动播放”：前者针对 `autorun.inf` 执行链，后者只是媒体功能。
- “`Autorun.inf` 目录免疫”≠“已经清除病毒”：它只阻断一条依赖同名文件的传播路径。
- “U 盘加密”≠“U 盘杀毒”：加密保护机密性，不阻止带毒文件被执行。
- “广谱侦测/启发式提示”≠“查杀”：前者只给线索，后者需要具体清除与复核。
- “介质只读/写保护”≠“主机安全”：主机仍需补丁、最小权限、应用白名单与日志。
