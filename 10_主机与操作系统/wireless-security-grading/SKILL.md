# 无线安全的分级加固与旁路优先

## R — 原文 (Reading)

> “Reaver 工具会对 WiFi 保护设置（WPS）的注册 PIN 码进行暴力破解攻击，并尝试恢复出 WPA/WPA2 密码。”
>
> “WEP 方式……已经被爆出存在严重安全隐患，除测试外不建议使用。”
>
> “MAC 地址过滤……这个只是相对的。”
>
> — 第12–13章 无线网络与无线路由器安全

---

## I — 方法论骨架 (Interpretation)

1. 无线安全不是“选了哪种加密”这一个选项，而是一组能到达同一凭据的路径。
2. 先枚举路径：WEP 的 IV 统计、WPA/WPA2-PSK 的四次握手加字典、WPS PIN 旁路、MAC 白名单克隆、路由器默认管理口令与远程管理。
3. 再给每条路径估攻击成本：是否需要邻近目标、是否需要抓到握手、是否需要 PIN 枚举、是否可离线跑字典、是否需要先拿到管理面。
4. 实际强度取成本最低的那条路径，而不是最强的那一项；WPA2 再强，WPS 开着就等于留了旁路。
5. 加固顺序是“先关旁路，再升主路径，最后加门槛”：先关 WPS、改默认管理口令、按需关闭远程管理，再升级到 WPA2/WPA3 与强口令，最后才用 MAC 过滤降低随意接入。
6. MAC 过滤只是准入门槛，链路层地址可伪造，不能当作加密。
7. 隐藏 SSID 只降低被发现概率，不构成安全边界；不用无线时应同时关闭无线功能与 SSID 广播。
8. 每次改动都要用攻击者视角复测：扫描工具是否还识别 WPS、错误口令是否被拒、旧客户端是否仍能连接、管理页是否还接受默认口令。

## A1 — 书中的应用 (Past Application)

### 案例 1: WEP 的破解前提是统计收集，不是口令强度
- **问题**: 老设备或测试环境仍在使用 WEP，使用者以为“把密码设复杂一点就安全了”。
- **方法论的使用**: 作者按认证路径而不是口令长度判断强度：WEP 的弱点在 IV 复用与统计破解，抓包并配合重放收集足够多的 IV 后即可恢复密钥；换更复杂的口令不会改变这条路径的攻击成本。
- **结论**: WEP 属于协议设计缺陷，正确动作是更换加密方式，而不是继续加长密码。
- **结果**: 书中把 WEP 列为“除测试外不建议使用”，加固建议指向 WPA/WPA2，而非“换个复杂密码”。

### 案例 2: WPA-PSK 与 WPS 是两条路径，后者可以绕过前者
- **问题**: 主网络已经启用 WPA/WPA2-PSK，但路由器仍默认开启 WPS，管理员认为“主密码够强就没事”。
- **方法论的使用**: 作者把两条路径分开估成本：WPA-PSK 需要抓到四次握手，再靠字典命中，强度取决于口令熵；WPS 只需对 PIN 做分段枚举，成功后可直接恢复出 PSK，绕过主口令强度。
- **结论**: 主路径再强也会被旁路拉低；应先关闭 WPS，再讨论 WPA2 强口令。
- **结果**: 书中用 Reaver 演示由 WPS PIN 得到 WPA PSK，说明“开了 WPA2”不等于安全，WPS 必须单独关闭。

### 案例 3: MAC 过滤只是门槛，克隆即可绕过
- **问题**: 管理员开启 MAC 白名单，认为名单之外的设备无法接入，网络就安全了。
- **方法论的使用**: 作者把 MAC 过滤归为“准入控制”而非加密：它只检查可伪造的链路层地址，既不保护空口数据，也不验证用户身份；攻击者克隆一个已授权 MAC 就能通信。
- **结论**: MAC 过滤可以保留为降低随意接入的低成本措施，但必须与强加密、关闭 WPS、强管理口令一起使用。
- **结果**: 作者自述“这个只是相对的”，并紧接着讲解 MAC 克隆；因此它不能被视为安全边界。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 家里、小店或办公室的 Wi-Fi 被蹭、网速异常，用户想通过“改密码”或“加白名单”解决。
2. 新装或重置路由器，需要做初始安全配置，问 WPS、访客网络、管理口令、远程管理该怎么设。
3. 用户直接问“WPA2 够不够安全”“WPS 要不要开”“隐藏 SSID 有没有用”“MAC 白名单能不能防蹭网”。
4. 咖啡馆、诊所等场所要同时提供顾客 Wi-Fi 和保护内网收银/办公系统，需要做网络分级与隔离。
5. 旧设备兼容性导致不能直接启用 WPA3，需要在兼容与强度之间做取舍。

### 语言信号 (用户的话里出现这些就应激活)

- “Wi-Fi 被蹭了”“密码改了好几次还是有人连”“怎么防止别人蹭网”
- “WPS 能开吗”“WPS 关了会不会影响连接”“PIN 码是什么”
- “MAC 白名单够不够”“隐藏 SSID 是不是就搜不到了”
- “WPA2 和 WPA3 选哪个”“路由器管理密码还是 admin”
- “wireless security”“Wi-Fi hardening”“WPS PIN”“PSK”“rogue AP”“evil twin”“SSID broadcast”

### 与相邻 skill 的区分

- 与 `identity-deception-detection` 的区别: 后者识别 ARP、DNS、URL 等“身份映射被替换”的欺骗；本 skill 处理同一凭据的多条认证路径与配置加固。遇到伪造 SSID/邪恶双胞胎时，可先用前者的映射思路识别，再回到本 skill 关闭旁路、强化认证。
- 与 `recon-funnel-and-scoping` 的区别: 后者是在未知目标上做发现、端口与服务收敛；本 skill 是对已掌握的路由器或无线网络做分级加固，不负责扫描整个网段。
- 与 `usb-autorun-hardening` 的区别: 两者都属于“入口收敛”，但对象不同；后者管可移动介质与自动播放，本 skill 管无线接入路径与管理面。
- 与 `buffer-overflow-defense-layering` 的区别: 后者按“消除漏洞→限制触发→限制后果”处理内存破坏；本 skill 按“攻击成本最低的认证路径”排序，不处理溢出。
- 与 `data-backup-recovery-discipline` 的区别: 后者管数据副本与恢复写入纪律；本 skill 管无线接入强度。路由器配置备份可以归入后者的故障域检查。

## E — 可执行步骤 (Execution)

1. **盘点认证路径与攻击成本**
   - 完成标准: 至少列出主加密方式（WEP/WPA-PSK/WPA2/WPA3）、WPS、MAC 过滤、管理面（默认口令/远程管理）、访客网络五类路径；每条标注“需邻近/可离线/需握手/需 PIN/可克隆”和相对成本高低。
   - 判停条件: 若发现 WEP 或 WPS 开启，直接记为最高优先级旁路，先进入步骤 2，不要先调口令复杂度。

2. **先关闭或移除旁路**
   - 完成标准: WPS 的 PIN/PBC 已关闭；管理员默认账号与口令已修改；WAN 侧远程管理按需关闭；UPnP 按需关闭；访客网络与内网已隔离。
   - 判停条件: 若固件不支持关闭 WPS，或该型号存在已知 WPS 漏洞且无更新，升级固件或更换设备；只改 Wi-Fi 密码不算完成。

3. **升级主加密与口令**
   - 完成标准: 主网络使用 WPA2-AES 或 WPA3；口令长度至少 12 位且不是字典词或个人信息；不使用 WEP/TKIP；WPA3 兼容问题用过渡模式并记录残余风险。
   - 判停条件: 若旧客户端无法连接 WPA3，退回 WPA2-AES 并优先更换客户端；不得为兼容而退回 WEP 或 TKIP。

4. **加固管理面**
   - 完成标准: 管理口令与 Wi-Fi 口令不同；管理界面不从 WAN 可达；固件处于厂商支持版本；关闭不需要的远程管理与调试接口；配置备份存到与路由器不同的故障域。
   - 判停条件: 若管理页仍接受默认口令，或固件已停止更新且无法替换，视为未完成，建议更换设备而不是继续叠加无线侧措施。

5. **用攻击者视角复测**
   - 完成标准: 扫描工具不再把该 AP 识别为可 WPS 攻击；错误口令与未授权 MAC 被拒绝；旧客户端仍能正常连接；从外网确认管理页不可达。
   - 判停条件: 若复测仍显示 WPS 可枚举或 PIN 可猜，回到步骤 2；若兼容性失败，回到步骤 3 调整加密组合，而不是关闭加密。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 企业、校园或园区需要 802.1X/RADIUS、证书、动态 VLAN 与逐用户审计：本 skill 的 PSK 分级不足，应按企业无线架构设计。
- 需要无线入侵检测、邪恶双胞胎定位或攻击取证：本 skill 只做配置加固，取证还需要抓包、信号定位与日志。
- 纯信号覆盖、信道干扰、漫游体验优化：这不是认证强度问题，按本 skill 处理会答非所问。

### 作者在书中警告的失败模式 (warning_signs)

- **把 WEP 当成“弱密码”**: 以为换个更复杂的口令就能保住 WEP；实际是协议设计缺陷，必须更换加密方式。
- **把 WPA-PSK 当成企业级认证**: 全网共享一个预共享密钥，没有逐用户身份；口令一旦泄露，所有设备同时失守。
- **把 MAC 过滤当成加密**: 认为设了白名单就安全；MAC 可克隆，过滤只能提高门槛。
- **把隐藏 SSID 当成安全边界**: 认为“搜不到”就连不上；隐藏只降低被发现概率，已知 SSID 的客户端仍可连接。
- **只改密码不关 WPS**: 主口令设得很长，却保留 WPS PIN 旁路；扫描工具仍可枚举 PIN 并恢复 PSK。
- **管理面仍是默认口令**: 路由器管理密码为 admin/123456，或管理页暴露在 WAN 侧；无线侧再强也会被从管理面改掉。

### 作者的盲点 / 时代局限

- 书中设备与工具基于 2018–2019 年前后的环境；WEP 在现代路由器上多已移除，WPS PIN 漏洞也多被厂商修补或默认关闭，但“先找旁路、按最低成本定强度”的判据仍然成立。
- 只讨论 WPA-Personal/PSK，没有覆盖 WPA-Enterprise、802.1X、WPA3-SAE 的降级攻击、802.11w 管理帧保护与 PMF。
- 重操作、轻验证：书中演示了破解，却没有形成“关闭 WPS 后用扫描工具复测”的闭环；本 skill 把复测补成独立步骤。
- 默认单路由器管理员视角，未覆盖 Mesh 组网、访客网络隔离、物联网设备分段与路由器固件供应链风险。

### 容易混淆的邻近方法论

- **加密 vs 认证 vs 准入**: WPA2/WPA3 同时提供加密与认证，WPS 是配对旁路，MAC 过滤只是准入；三者不能互相替代。
- **隐藏 vs 加密**: 隐藏 SSID 是降低可见性，不是保护数据；不构成边界。
- **`identity-deception-detection` 的 evil twin 识别 vs 本 skill 的配置加固**: 前者判断“这个 AP 是不是假的”，后者保证“真 AP 的认证路径没有旁路”；两者应串联使用。
