# 06 接口与协议

这一层测的是请求与响应这一层：REST/GraphQL/WebSocket/RPC 的接口面、登录后的会话与令牌、参数进入解释器后的注入，以及 FTP/SMTP 这类多步协议。典型被测物是 Swagger 文档、抓包得到的请求、JWT/Cookie、XML/模板/URL 参数、Java 反序列化入口。

## 这一层最常见的四类问题

- 接口能枚举、GraphQL introspection 开放、响应里带了别人的字段或不该下发的字段。
- JWT 可改 alg、OAuth 回调可改 redirect_uri、注销后会话仍有效。
- 参数进了 SQL/模板/XML/URL，靠回显或带外信道就能确认，编码差异还能绕开 WAF。
- 反序列化入口在 T3/wls-wsat，旧 payload 在补丁后失效，不知道还有哪些入口。

## 这一层的 skill

| skill | 作用 | 什么时候会用到 |
| --- | --- | --- |
| api-and-interface-security | 枚举 REST/GraphQL/WebSocket/RPC 接口，逐接口查认证、授权、对象级校验、批量赋值与限流。 | 「Swagger 暴露了，接口怎么系统性过一遍」 |
| auth-session-and-federation-security | 查认证强度、会话与 Cookie 生命周期，以及 JWT/OAuth/SAML 的签名、受众、回调与 scope。 | 「JWT 能不能改 alg 绕过」「登出后 token 还能用」 |
| input-validation-output-encoding | 按上下文做输入校验与输出转义，覆盖注入、XSS、命令注入与开放重定向。 | 「这个值存库前要不要编码」「这样过滤能防注入吗」 |
| ssrf-xxe-and-template-injection | 判输入进入哪种解释器，为 NoSQL/SSTI/XXE/SSRF 选最小对照，并用回显或带外确认。 | 「模板里能不能注进表达式」「XML 接受 DOCTYPE 吗」 |
| non-memory-vulnerability-analysis | 做 SQL 注入（含盲注）、XSS、格式化串、路径回溯与编码绕过（GBK/NFKC）的验证。 | 「上了 WAF，还能不能用宽字节绕」 |
| java-deserialization-entry-enumeration | 枚举 JBoss/WebLogic/WebSphere 的反序列化入口，读补丁黑名单预测绕过并做回显验证。 | 「补丁之后旧 payload 全失效了」 |
| network-protocol-fuzzing | 对 FTP/SMTP/POP3/IMAP4 等服务做协议级 Fuzz，并从 WSARecv 回溯处理函数。 | 「登录前的协议字段怎么 fuzz」 |

## 跨层可复用

- access-control-and-idor（05_后端业务逻辑与权限）— 接口的「对象级校验」本质是授权矩阵，要借它的主体—对象—动作模型。
- authentication-and-passwords（05_后端业务逻辑与权限）— 登录接口本身的强度、锁定与账号枚举。
- middleware-fingerprint-and-triage（08_中间件与Web容器）— 先判清容器，才知道该枚举哪些反序列化与管理员入口。
- file-and-upload-safety（05_后端业务逻辑与权限）— multipart 上传接口的落盘、命名与路径问题。
- network-transport-and-session（09_网络与传输）— TLS、证书、会话标识与重放属于传输层，别在接口层硬解。
- logging-security（13_日志与审计数据）— 接口是否记录可审计事件、日志会不会被输入注入。
- fuzzing-strategy（99_跨层通用方法）— 协议 fuzz 之前先选 Blind 还是 Smart。

## 和相邻层的分界

- 与 05 后端业务：06 看「协议对不对、认证与对象级校验有没有」，05 看「业务状态机与金额/库存不变量」。「接口返回了他人字段」归 06，「合法接口下重复退款成功」归 05。
- 与 09 网络与传输：09 看链路与传输（TLS、ARP/DNS、可达性、抓不到包），06 看应用层报文内容。
- 与 08 中间件：同一个反序列化点，判断「容器是哪个、入口怎么配的」归 08，「用哪个 gadget、怎么回显」归 06。
