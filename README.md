# Ruance-Skill

> **一套面向软件测试全领域的可执行技能库：115 个方法论技能 × 14 类被测对象导航 × 触发式调用机制。**

把软件测试领域的成熟作业方法论固化为一个个可独立调用的「技能卡片」——每张卡片回答一个问题：**遇到这类测试场景，该怎么一步步做、依据是什么、什么时候不该这么做。** 适用于人工测试作业参考，也可直接装载到 AI Agent（Claude Code / Cursor / Trae 等）作为可自动触发的领域技能。

---

## 一、这套技能库是什么

一个技能 = 一份结构化的测试作业方法论，包含**方法论出处、方法论骨架、应用案例、触发场景、可执行步骤、使用边界**六个固定部分。115 个技能按**被测对象**组织成 14 个类目——从前端页面、移动 App、桌面二进制，到源码实现、业务逻辑、接口协议、数据存储、中间件、网络传输、主机系统、云与容器、构建产物、日志审计，外加不针对具体对象的跨层通用方法——回答测试者最实际的问题：**我在测什么对象，就该看哪个类目、走哪条方法路线。**

**规模一览**：

| 维度 | 数量 |
|---|---|
| 技能总数 | 115 |
| 被测对象类目 | 14 |
| 技能间引用关系（frontmatter 显式声明） | 364 |
| 触发测试用例 | 1004 |
| 随库盲测结果文档 | 64 |

```
├── 05_后端业务逻辑与权限/           （6 个技能）
├── 06_接口与协议/                  （7 个技能）
├── 07_数据库与数据存储/             （3 个技能）
├── 08_中间件与Web容器/              （4 个技能）

├── 10_主机与操作系统/               （9 个技能）
├── 11_云与容器/                    （1 个技能）
├── 12_构建产物与依赖/               （2 个技能）
├── 13_日志与审计数据/               （2 个技能）
└── 99_跨层通用方法/                 （40 个技能：方法选型与分析 + 思维与组织方法）
```

- **导航层（14 个类目目录）**：每类一份 `说明.md`——这一层测什么、最常见的问题形态、技能清单（每项带「什么时候会用到」的触发语）、与其他类目的「跨层可复用」互相指路；`总览.md` 是按**被测对象**找技能的入口；
- **技能层（115 个技能目录）**：每个技能一份 `SKILL.md`，是技能的**本体**；
- **质量层（随技能目录携带）**：每个技能的 `test-prompts.json` 触发测试用例与 `test-results.md` 盲测结果，构成可验证、可回归的质量证据。

## 三、技能卡片解剖

每个技能是一份固定结构的 `SKILL.md`，由 **frontmatter 元数据 + 六段正文**构成：

### frontmatter（机器读取部分——决定技能何时被自动激活）

```yaml
---
name: file-and-upload-safety          # 技能唯一标识（=目录名）
description: |                        # 何时调用 + 何时不调用 + 中英双语触发词
  当你要处理文件路径拼接、下载或导出接口、上传落盘、临时文件、
  目录遍历、符号链接与文件句柄竞争时使用。不适用于只讨论对象存储桶
  策略或数据库读写权限的问题。触发信号：路径穿越 / 上传绕过 /
  webshell / path traversal / file upload / symlink。
source_chapter: ……                   # 方法论出处定位（可溯源）
tags: [file-security, path-traversal, file-upload, temp-file]
related_skills:                       # 技能间引用关系（依赖/对比/组合）
  - slug: input-validation-output-encoding
    relation: composes-with
---
```

### 六段正文（人与 Agent 共读部分）

| 段 | 名称 | 作用 |
|---|---|---|
| **R** | 原文依据 | 方法论的一手出处引用（章节可溯），保证「有据可查」 |
| **I** | 方法论骨架 | 用结构化语言重写的核心逻辑与关键判据，不读原文也能懂 |
| **A1** | 应用案例 | 1–3 个该方法论被实际使用的案例：遇到什么问题 → 怎么用 → 得出什么 → 结果如何 |
| **A2** | 触发场景 ★ | 用户会在什么情境下需要它、语言信号（中英双语）、与近缘技能的区分——这是技能被精准调用的关键 |
| **E** | 可执行步骤 | 3–7 步操作流程，每步带**完成标准**与**判停条件**，拿来即用而非空泛原则 |
| **B** | 边界 ★ | 什么时候**不要**用、已知的失败模式、时代局限、易混淆的邻近方法论——防止滥用 |

卡片末尾附「相关 skills」（`depends-on` / `contrasts-with` / `composes-with` 三类关系的自然语言说明）与「审计信息」（准入验证判定记录）。

### 4.2 两个分类维度

- **目录按「被测对象」分类**（01–13 + 99）：每个技能只出现在一个类目，回答「我在测什么」；
- **`两层类目.png` 按「作用」分类**：安全编码、Web 与接口安全、客户端、逆向工程、漏洞利用、模糊测试、恶意代码与应急、基础设施、工程治理、思维方法十个方向，回答「这个技能用来干什么」；
- 两个维度**正交**：同一个技能在两个视图中的归属可能不同——例如 `file-and-upload-safety` 在作用维度属于「安全编码」，在对象维度属于 05（因为它测的是上传点的业务行为）。

### 4.3 技能网络

364 条显式引用关系把 115 个技能连成网：**依赖**（用 A 前先理解 B）、**对比**（A/B 二选一的情境判据）、**组合**（A/B 常配合使用）。每个技能的 SKILL.md 末尾有自然语言版关系说明，各类目 `说明.md` 提供分组视图。

## 五、质量保障体系

这套技能库的每个技能都经过两道质量闸门，证据随仓库携带：

### 5.1 准入验证（内容质量）

每个技能入选前通过三重验证，判定记录保留在卡片「审计信息」段：

- **V1 跨域验证**：该方法论在至少 2 个独立语境下成立（不同章节、不同对象、不同结论），排除一时兴起的表达；
- **V2 预测力验证**：用它能推导出一个原始材料未直接讨论的新场景结论，排除「只能复述例子」的描述性内容；
- **V3 独特性验证**：抹掉出处后仍非「任何聪明人都会说的常识」，只保留真正差异化、反直觉的方法论资产。

### 5.2 触发盲测（调用质量）

1004 条测试用例（每技能 6–12 条），分三类：`should_trigger`（应激活本技能，426 条）、`should_not_trigger`（不应激活，326 条，其中大量是「应触发近缘兄弟技能」的抢调诱饵）、`edge_case`（边界场景，252 条）。由未参与建设的独立 Agent 做单选「选择题」盲测——只给全集合的 name + description，隐藏预期答案，要求对每条用户话语选中一个技能或 none：

- **判卷标准**：`should_trigger` 必须命中本技能；`should_not_trigger` 诱饵**零容忍**（跨技能诱饵必须正确分流到兄弟技能）；`edge_case` 需符合边界理由；
- **回炉机制**：未达标技能回炉修正触发描述（description / A2 段）后定向复测，失败案例与修正过程逐条保留在 `test-results.md`；
- 每技能目录下的 `test-prompts.json`（darwin 兼容格式）完整保留测试基准。

## 六、使用方式

### 6.1 人工使用（按被测对象浏览）

```
1. 打开 总览.md → 按「被测对象 → 类目」对照表定位，或按典型处境选类路线走
2. 进入类目目录读 说明.md → 按「什么时候会用到」触发语定位技能
3. 打开技能的 SKILL.md → 按 E 段步骤执行，B 段确认边界
4. 需要跨对象配合时，按 说明.md 的「跨层可复用」跳转相邻类目
5. 按卡片末尾「相关 skills」跳转依赖 / 对比 / 组合技能
```

### 6.2 Agent 装载（自动触发）

将技能目录复制到宿主技能目录（如 `~/.claude/skills/`、`~/.trae-cn/skills/` 或项目级 `.claude/skills/`）。注意：**宿主目录名必须等于 SKILL.md 的 `name` 字段**，改名会让技能失效：

```bash
git clone https://github.com/foxxx1027/ruance-skill.git
cd ruance-skill

# 装载全部技能（目录名取自 name 字段）
find . -maxdepth 2 -type f -name SKILL.md | while read -r f; do
  src=$(dirname "$f")
  name=$(sed -n 's/^name:[[:space:]]*//p' "$f" | head -1)
  cp -r "$src" ~/.claude/skills/"$name"
done
```

装载后，当对话中出现匹配场景（如「这个崩溃样本怎么定位根因」「这个上传接口能不能绕过」「扫描报告几万条没人处理」），对应技能按其 `description` 自动激活，Agent 按 E 段步骤给出带完成标准的操作指导。

### 6.3 按处境选类（典型路线）

| 你的处境 | 建议路线 |
|---|---|
| 测一个 H5 页面 / 前端应用 | 01 → 06 → 13（DOM 与端侧存储 → 它调的接口 → 是否留下可审计记录） |
| 测一个 App，怀疑关键逻辑在 native 层 | 02 → 03 → 99（分层调试与签名 → 逆向手法 → 机理判定与方法选型） |
| 拿到一个崩溃样本，还没有 PoC | 03 + 99（下断点、定位根因、布堆/写利用 → 先判机理与选路线） |
| 评审一份后端源码 | 04 → 05 → 07（写法与资源 → 权限/状态机是否成立 → 敏感字段怎么存） |
| 测一个 Web 业务系统（黑盒） | 08 → 05 → 06 → 10 → 13（先判容器 → 业务规则 → 接口报文 → 主机环境 → 日志） |
| 只有一串抓包和 Swagger | 06 + 05（协议、认证、对象级校验 → 金额/库存/次数等业务不变量） |
| 上线前安全复核 | 08 → 11 → 12 → 07 → 13（站点配置 → 云与容器 → 依赖与产物 → 数据存储 → 日志审计） |
| 查「内网老断网、网站跳转异常」 | 09 → 10 → 13（二层/解析层欺骗 → 主机是否中招 → 日志是否被清） |
| 查一台机器中招了 | 10 → 13 → 99（处置顺序、隐藏账号 → 日志证据 → 样本分析） |
| 评估供应链与交付 | 12 → 11 → 99（依赖与产物 → 镜像与工作负载 → 门禁、台账与披露） |

## 八、约定与说明

- **分类是导航不是边界**：技能的适用范围以其 SKILL.md 的 A2 / B 段为准；每个技能只归一个类目，跨层能力在各类目 `说明.md` 的「跨层可复用」中互相指路，不重复建目录；
- **多义条目有判定记录**：跨类目两可的技能（如 App 样本分析归 02 还是 99、内核利用归 03 还是 10）在 `总览.md` 中逐条给出最终定类理由，保证归类可复核；
- **两个维度配合用**：找「测什么」走目录的对象维度；要「一个作用的全景」（如所有安全编码类技能）看 `两层类目.png` 的作用维度；
- **授权纪律**：渗透、模糊测试与样本分析类技能默认面向自有系统与已获授权的目标；`pentest-engagement-and-disclosure` 技能专门界定授权边界、交战规则与披露流程，先过它再动手。
