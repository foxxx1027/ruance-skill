# 云与容器基线：从暴露面到检测闭环

## R — 原文 (Reading)

> 端口扫描、服务识别、补丁管理
>
> 操作系统、容器、Kubernetes 基线
>
> WAF、防火墙、日志审计、入侵检测
>
> 云配置：对象存储、IAM、安全组
>
> — 用户，《漏洞筛查覆盖框架》第 10 类「基础设施与主机安全」，2026-10-19

## I — 方法论骨架 (Interpretation)

1. **先盘资产与网络暴露，再谈基线。** 基线的对象是资产，不是配置文件模板。第一步要回答：有哪些云账号、区域、VPC、主机、容器、集群、域名与公网入口，哪些是生产、哪些是临时。随后做端口与服务识别，确认哪些入口对公网开放、经过哪层网关、是否有安全组或防火墙限制。资产不清时，扫描结果会混入影子资产和已下线系统，导致修复资源浪费。资产归属与网络分区属于设计层，端口与规则属于配置层。

2. **主机基线按“补丁—账号—服务—加固”四条线核查。** 先看补丁级别与内核版本是否在支持范围内，再看账号与密钥（多余账号、共享账号、过期密钥）、服务与启动项、远程管理入口、日志代理与磁盘加密。补丁缺失是配置/运维问题；共享账号与过度 sudo 往往是设计问题；日志代理未部署属于实现或部署缺口。常见误判是把“扫描器显示补丁数”当成“已修复”，不核对重启与生效状态。

3. **容器基线分镜像、运行时与编排三层。** 镜像层看基础镜像来源、是否含密钥与构建工具、是否固定 digest；运行时看是否以 root 运行、是否只读根文件系统、能力集、挂载与网络模式；编排层看命名空间、资源限制、健康检查与重启策略。容器内漏洞属于供应链 skill，容器配置与运行时隔离属于本 skill。最容易漏的是特权容器、hostPath 挂载、host 网络与挂载 Docker socket，它们能直接把容器逃逸变成主机控制。

4. **Kubernetes 要先看控制面暴露，再看工作负载。** 控制面检查 API Server 是否对公网开放、是否启用匿名认证、RBAC 是否过宽、etcd 是否受保护、审计日志是否开启；工作负载检查 ServiceAccount 权限、Secret 管理、NetworkPolicy、PodSecurity 级别与镜像拉取策略。匿名访问与 RBAC 通配属于配置问题，但“所有工作负载共用一个高权限 ServiceAccount”通常是设计缺陷。误判点是把“集群能跑”当成“基线合格”，漏掉默认命名空间与 CI/CD 用的高权限账号。

5. **云 IAM 按“人、机、临时、根”四类主体核查。** 人：是否有 MFA、是否长期密钥、权限是否最小；机：实例角色/服务账号是否过宽、是否可跨账号信任；临时：STS 与会话时长；根/管理员：是否启用、是否有硬性保护与告警。重点看通配动作、通配资源、跨账号信任与权限提升路径。IAM 过宽是配置问题，但账号体系没有分区隔离是设计问题。最容易漏的是 CI/CD 角色、运维跳板角色与第三方集成角色。

6. **对象存储与数据面分开看。** 存储基线检查公共访问、桶策略、加密、版本控制、日志与跨域配置；数据分类、脱敏与留存属于 `data-protection-and-secrets`。常见误判是“桶列表不可见就认为不公开”，实际对象仍可被直链访问；也容易漏掉静态网站托管、CDN 回源与备份桶。把访问策略与数据级别对应起来，才能判断公开是否合理。

7. **检测与日志是基线的一部分，不是附加项。** 检查 WAF 是否覆盖主要入口、规则是否处于阻断而非仅观察、防火墙默认拒绝是否生效、云审计与主机日志是否集中收集、IDS/EDR 是否在线、告警是否有接收人与处置流程。日志“有没有”属于配置问题，“是否被篡改、证据链是否完整”属于 `log-integrity-and-evidence`。最常见失败是日志开了但无人看、告警阈值过高、WAF 只记录不阻断。

8. **最后做基线复核与差异收敛。** 把发现映射到明确基线项（如 CIS 类控制项或组织内部基线），记录“当前值—期望值—证据—责任方”，按暴露面、影响范围与修复成本排序；对例外项建立书面豁免与到期复核。基线不是一次性扫描，要能回答“上次差异是否已修、是否引入新差异”。只输出一屏红色项而不做差异对比，无法证明修复有效。

## A1 — 书中的应用 (Past Application)

> 本 skill 为工程清单型，没有单一书籍案例；以下为公开标准条款映射，不虚构事件细节。

### 标准映射 1: OWASP A05:2021 Security Misconfiguration

- **条款**: OWASP A05:2021 Security Misconfiguration。
- **对应检查**: 云资源、主机、容器或集群保留默认配置、开放不必要的端口与服务、启用调试接口、权限过宽或缺少安全加固，形成可直接访问的入口。
- **落到本 skill**: 用第 3 至 8 步逐层核对网络、主机、容器、K8s、IAM 与存储配置；产出“当前值—期望值—证据—责任方”的基线差异表。

### 标准映射 2: CWE-732 Incorrect Permission Assignment for Critical Resource

- **条款**: CWE-732 Incorrect Permission Assignment for Critical Resource。
- **对应检查**: 对象存储桶、共享目录、Kubernetes Secret、云 IAM 策略或主机文件权限被赋予过宽主体，导致未授权读取或修改关键资源。
- **落到本 skill**: 用第 6 步核对象存储访问策略、第 5 步核 IAM 通配与跨账号信任、第 4 步核工作负载权限；产出主体—资源—动作矩阵，标注可匿名或跨边界访问的项。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

- 新系统上云或新集群上线前，需要确认网络暴露、主机加固、容器与 K8s 配置是否符合基线。
- 收到 cloud security posture 告警，或客户要求提供云配置与容器基线证据。
- 发现公网端口过多、安全组放行过宽、对象存储可公开访问，需要系统排查而不是逐条救火。
- 容器被扫描出以 root 运行、特权模式或挂载主机目录，想确认影响与修复顺序。
- K8s 集群担心 API Server 暴露、RBAC 过宽、ServiceAccount 权限过大。
- 要确认 WAF、防火墙、审计日志、IDS/EDR 是否真的在阻断与告警，而不是只开通了服务。

### 语言信号 (用户的话里出现这些就应激活)

- “云上到底开了哪些公网端口”
- “安全组是不是放太宽了”
- “容器怎么是以 root 跑的”
- “这个 Pod 挂了主机目录，危险吗”
- “K8s 的 API Server 能不能从公网访问”
- “RBAC 是不是给太大了”
- “对象存储好像谁都能读”
- “IAM 里有好几个星号权限”
- “WAF 开了但好像只记录不拦”
- “云审计日志有没有开”
- 英文关键词：cloud misconfiguration、container escape、Kubernetes RBAC、public bucket、cloud audit log。

### 与相邻 skill 的区分

- 与 `host-default-surface-convergence`：关注 Windows 主机默认共享、默认服务与系统组件暴露时走该 skill；关注云主机补丁、账号、服务与容器/K8s 基线时走本 skill。
- 与 `recon-funnel-and-scoping`：需要从外部做资产发现、端口扫描与范围收敛时走该 skill；已确定资产范围，要核查云资源、容器与 K8s 配置基线时走本 skill。
- 与 `remote-access-surface-audit`：关注 VPN、堡垒机、RDP/SSH 等远程入口的认证与暴露时走该 skill；关注这些入口背后的主机与云资源配置基线时走本 skill。
- 与 `log-integrity-and-evidence`：关注日志是否被篡改、证据链是否可采信时走该 skill；关注日志审计是否开启、是否集中收集、告警是否有人处置时走本 skill。
- 与 `supply-chain-and-dependency-security`：镜像内语言依赖、基础镜像来源与镜像仓库完整性走该 skill；容器运行时权限、K8s 配置与云资源基线走本 skill。
- 与 `data-protection-and-secrets`：桶内数据分级、加密密钥归属、脱敏与留存走该 skill；桶是否公开、IAM 是否过宽、安全组是否放行走本 skill。
- 与 `appsec-tooling-and-threat-modeling`：要选型、编排 CSPM/容器扫描并做结果去重与误报分诊时走该 skill；要按基线逐项核查并给出配置修复时走本 skill。

## E — 可执行步骤 (Execution)

1. **确认授权与核查范围**
   - 动作: 明确云账号、订阅、区域、集群、主机与域名范围，确认只读权限与变更审批边界；记录本次不覆盖的资产与原因。
   - 完成标准: 范围清单可追溯到账号与资产 ID，授权方式与联系人明确。
   - 判停条件: 未取得云账号只读权限或资产归属不明时，停止主动扫描，先做资产确认。

2. **建资产清单**
   - 动作: 汇总云主机、容器、集群、负载均衡、对象存储、数据库、公网 IP 与域名；标注生产/非生产、责任团队、生命周期状态，识别影子资产。
   - 完成标准: 资产清单与云账号实际资源能对上，生产资产无遗漏，临时资产有到期标记。
   - 判停条件: 无法区分生产与非生产时，停止基线定级，先补标签与归属。

3. **核查网络暴露与防火墙**
   - 动作: 在授权范围内做端口与服务识别，核对安全组、网络 ACL、防火墙与 WAF 覆盖；确认公网入口、管理端口、数据库端口与内网横向放行规则。
   - 完成标准: 每个公网入口有端口、服务、暴露原因与限制措施；高危管理端口单独列出。
   - 判停条件: 扫描可能触发生产防护或影响业务时，停止主动探测，改用配置导出与流量记录。

4. **核查主机基线**
   - 动作: 检查补丁与内核支持状态、账号与密钥、sudo 权限、服务与启动项、远程管理配置、日志代理、磁盘加密与时间同步；核对补丁是否重启生效。
   - 完成标准: 每台抽样主机有“当前值—期望值—证据”记录，补丁状态区分已安装与已生效。
   - 判停条件: 无，继续。

5. **核查容器运行时基线**
   - 动作: 检查容器是否以 root 运行、是否特权、能力集、只读根文件系统、hostPath/host 网络、Docker socket 挂载、资源限制与镜像 digest；区分应用容器与系统组件容器。
   - 完成标准: 高风险运行时配置逐项有证据，特权与主机挂载单独标注影响。
   - 判停条件: 需要进入生产容器执行命令时，停止，改用编排配置与镜像检查。

6. **核查 Kubernetes 控制面与工作负载**
   - 动作: 检查 API Server 暴露与匿名认证、etcd 保护、审计日志、RBAC 通配与默认 ServiceAccount、Secret 管理、NetworkPolicy、PodSecurity 与命名空间隔离；核对 CI/CD 使用的高权限身份。
   - 完成标准: 控制面暴露、RBAC 高风险绑定、工作负载特权与隔离缺口各有清单与证据。
   - 判停条件: 无，继续。

7. **核查云 IAM**
   - 动作: 按人、机、临时、根/管理员四类主体列出权限，检查 MFA、长期密钥、通配动作与资源、跨账号信任、权限提升路径与未使用身份；核对 CI/CD 与第三方集成角色。
   - 完成标准: 产出主体—资源—动作矩阵，标注可跨边界或可提权的组合。
   - 判停条件: 发现可立即提权的高危身份时，停止扩散性枚举，按授权流程通知并建议先限制。

8. **核查对象存储与数据面配置**
   - 动作: 检查桶与对象的公共访问、桶策略、加密、版本控制、日志、跨域与静态托管；抽样验证直链与 CDN 回源是否绕过预期限制；不下载业务数据。
   - 完成标准: 每个桶有访问状态、加密状态与证据；公开或可直链的桶标注数据级别待确认。
   - 判停条件: 验证需要读取真实对象内容时，停止，改用策略与元数据判断。

9. **核查检测与日志能力**
   - 动作: 确认 WAF 规则模式（阻断/观察）、防火墙默认策略、云审计与主机日志是否集中、IDS/EDR 在线率、告警接收人与处置记录；抽查一条告警的闭环。
   - 完成标准: 每类检测能力有覆盖范围、模式与责任人；抽查告警能追到处置结果。
   - 判停条件: 无，继续。

10. **做基线差异复核与修复排序**
   - 动作: 将发现映射到基线项，记录当前值、期望值、证据、责任方与例外；按暴露面、影响范围、利用条件与修复成本排序，输出修复与复测计划。
   - 完成标准: 差异表可对比上一轮结果，例外有到期复核；修复项可直接分派。
   - 判停条件: 基线版本不统一时，停止合并统计，先确定适用基线再排序。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 只关注 Windows 默认共享、默认服务与系统组件暴露，应走 `host-default-surface-convergence`。
- 只关注内网资产发现、横向可见性与隔离，应走 `lan-visibility-and-containment`。
- 只关注 VPN、堡垒机、RDP/SSH 等远程入口的认证与暴露，应走 `remote-access-surface-audit`。
- 只关注日志是否被篡改、证据链是否完整，应走 `log-integrity-and-evidence`。
- 只关注镜像内语言依赖漏洞与包来源，应走 `supply-chain-and-dependency-security`。
- 只关注数据分级、加密密钥归属与脱敏，应走 `data-protection-and-secrets`。
- 未获授权时，不得做端口扫描、配置变更、权限枚举或对象内容读取。

### 作者在书中警告的失败模式

- 本清单未覆盖“资产不清就扫基线”的失败：影子资产与已下线系统会污染结果，修复也可能打错对象。
- 本清单未覆盖“把扫描通过当成基线合格”的失败：容器扫描不覆盖运行时特权，配置扫描不覆盖检测与告警闭环。
- 本清单未覆盖“只修单条告警”的失败：同一安全组、同一 IAM 角色往往被多个资产复用，逐条修会反复出现。
- 本清单未覆盖“开了日志就等于有检测”的失败：无接收人、无阈值、无处置记录的告警不构成检测能力。
- 本清单未覆盖“用生产账号做验证”的风险：权限枚举与对象读取必须使用只读角色并限定范围。

### 作者的盲点 / 时代局限

- 本清单以通用云平台与 Kubernetes 为主，对专有云、混合云与行业托管环境的控制项覆盖不足。
- 本清单未展开各云厂商的具体策略语法与托管服务差异，需按平台文档补充。
- 本清单未覆盖服务网格、Serverless 与边缘节点的完整基线，只做通用容器与主机层核查。
- 本清单不提供合规认证结论，CIS 类基线项需按组织适用版本映射。
- 本清单未覆盖大规模多账号组织的云治理平台设计，偏单账号或单集群核查。

### 容易混淆的邻近方法论

- 主机默认面收敛（`host-default-surface-convergence`）：聚焦 Windows 默认组件，不是云资源全量基线。
- 内网可见性与隔离（`lan-visibility-and-containment`）：回答“内网能看到什么、如何隔离”，不回答云配置是否符合基线。
- 远程入口审计（`remote-access-surface-audit`）：回答“入口是否该开放、认证是否足够”，不覆盖入口后的主机与集群配置。
- 日志证据保全（`log-integrity-and-evidence`）：回答“日志能否作为证据”，不回答“是否开启与告警”。
- 供应链安全（`supply-chain-and-dependency-security`）：回答“组件来源与版本”，不回答“运行时权限与网络基线”。
